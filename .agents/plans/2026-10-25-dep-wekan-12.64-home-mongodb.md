# Plan: Update WeKan to chart 12.64.0, home-owned MongoDB, idle FerretDB target

## Goal
Update the two home-cluster WeKan instances (`wekan` + `boards`) from chart
9.99.0 / `ghcr.io/wekan/wekan:v9.99` to chart 12.64.0 / `v12.64`, keeping the
existing MongoDB and all data, and deploy the new chart's FerretDB **idle**
beside it as the ready-made migration target.

WeKan chart >= 10.86 no longer bundles the groundhog2k MongoDB chart (it
ships FerretDB instead). Therefore:
- the home umbrella **adopts the MongoDB chart as its own dependency**,
  pinned so it renders the live `home-mongodb` StatefulSet byte-identical —
  without this, the bump removes the mongodb manifests and ArgoCD would
  prune the running database;
- `ferretdb.enabled: true` on one instance deploys `home-ferretdb` idle,
  while `externalDatabase.url` (mirrored by the kept `secretEnv` MONGO_URL)
  keeps WeKan on MongoDB until the data is migrated.

This is also why Renovate's `renovate/wekan-12.x` branch (version-only bump)
and the earlier v11 attempt (merged + reverted same day, 2026-09-07) cannot
land as-is.

## Verified context (2026-10-25)
Live state on home cluster (default namespace):
- Deployments `home-wekan` + `home-boards`, both `ghcr.io/wekan/wekan:v9.99`,
  served at `wekan.spencerslab.com` / `boards.spencerslab.com`. Both share
  one database.
- StatefulSet `home-mongodb` (`docker.io/mongo:7.0.34`, groundhog2k chart
  `mongodb-0.7.6`), Services `home-mongodb` + `home-mongodb-internal`, PVC
  `mongodb-volume-home-mongodb-0` (2Gi). Rendered today by BOTH wekan
  subcharts of the `home` umbrella (byte-identical duplicates — the live
  `home` Application carries `RepeatedResourceWarning` conditions for it).
- Both instances share it via `secretEnv` `MONGO_URL=mongodb://home-mongodb:27017`
  (manual fix for the old chart's broken computed URL, wekan/charts#54).
  **No `/dbname` in the URL** — the live data sits in the database Meteor
  picks when no path is given; the chart's `/wekan` example would point at
  an empty database.
- The `home` Application's live syncPolicy currently has no `automated`
  block (no prune, no selfHeal), but adoption makes the change safe under
  any sync mode — the mongodb resources stay in the manifests either way.

Chart research (wekan.github.io/charts, tgz extracted to /tmp/opencode):
- 9.99.0: bundles groundhog2k `mongodb-0.7.6` (condition `mongodb.enabled`);
  computes MONGO_URL from Bitnami-style per-pod DNS (never resolved — #54);
  a `secretEnv`/`env` MONGO_URL suppresses the computed one (#6289 gate).
- 12.64.0: no mongodb dependency; `ferretdb:` templates in the chart itself
  (Service name `<release>-ferretdb` = `home-ferretdb` here, fixing #54);
  computed-URL precedence: `externalDatabase.url` > legacy `mongodb.url` >
  ferretdb (only when enabled and no external URL) — so with
  `externalDatabase.url` set, `ferretdb.enabled: true` deploys FerretDB but
  WeKan still dials the external URL; `directConnection=true` is appended
  when missing (harmless for single-node MongoDB, required for FerretDB —
  wekan/wekan#6582).
  - FerretDB templates use the parent chart's name helpers: the aliased
    `boards` instance derives `app: boards` labels/selectors while `wekan`
    derives `app: wekan`. Two instances rendering `home-ferretdb` would
    emit the same-named StatefulSet with DIFFERENT immutable pod selectors
    — so FerretDB is enabled on exactly one instance.
  - FerretDB image: `ghcr.io/wekan/ferretdb:latest`, pullPolicy Always (the
    chart's deliberate choice — tracks wekan/FerretDB releases).
  - Old `mongodb.architecture`/`replicaSet`/`service.nameOverride` values
    keys are unknown to the new chart and ignored (left in place, inert).
- All other templates (service, data-pvc, secret, hpa, ingress,
  serviceaccount) are byte-identical between the versions.
- The umbrella-level `mongodb 0.7.6` dependency with `image.tag: 7.0.34` +
  `storage.requestedSize: 2Gi` renders all four live mongodb resources
  byte-identical (verified with helm template diff).

   wekan digest matches renovate's `wekan-12.x` branch.
3. `services/home/prod/values.yaml`
   - New top-level `mongodb:` block (`image.tag: 7.0.34` — WeKan needs 7;
     `storage.requestedSize: 2Gi` — must match the live PVC, the StatefulSet

   - `wekan:` block: `ferretdb.enabled: true` (deploys `home-ferretdb`
     idle: Service + StatefulSet + 8Gi PVC `ferretdb-data-home-ferretdb-0`),
     `externalDatabase.url: "mongodb://home-mongodb:27017"` (mirrors the
     kept `secretEnv` MONGO_URL — the two move together; comment records
     the invariant, the #6289 precedence, the single-instance FerretDB
     render, and why there is no `/dbname`).
   - `boards:` block: `ferretdb.enabled: false` (rendered once by `wekan`,
     shared by both like the MongoDB it replaces), same
     `externalDatabase.url`, `WITH_API=true` env added (user choice: REST
     API on both instances; `wekan` already had it for the wekan-mcp
     server).
   - Kept as-is: the `secretEnv` MONGO_URL entries, the existing env lists
     (`METEOR_REACTIVITY_ORDER: oplog,polling` etc. — the running
     behavior), resources, SSO wiring, and the now-inert per-instance
     `mongodb:` values blocks.
4. `renovate.json` — packageRule disabling auto-updates for the umbrella
   `mongodb` dependency (services/home/**): 0.7.6 is a data-infrastructure
   pin, not a routine dependency; any other chart version re-renders the
   live database. (wekan itself stays renovate-managed — version-only bumps
   are safe now that values are new-chart-shaped and mongodb is
   umbrella-owned.)

## Migration path (later, when ready)
1. Dump + restore (both speak the MongoDB wire protocol, per the chart's own
   note): `mongodump` from `home-mongodb` → `mongorestore` into
   `home-ferretdb:27017` (via port-forward or exec — user-run).
2. Point both instances at FerretDB: set `externalDatabase.url` (and the
   `secretEnv` MONGO_URL, or remove the secretEnv so the chart computes it)
   to `mongodb://home-ferretdb:27017/<db>?directConnection=true` in both
   `wekan:` and `boards:`.
3. Verify boards load, then retire MongoDB: remove the umbrella `mongodb`
   dependency + values block (and the renovate pin rule) once nothing dials
   it anymore.

## Risks / notes
- **One-way data migration:** once WeKan 12.x runs its DB migrations,
  reverting the chart to 9.99 against the migrated data will not work.
  User accepted proceeding without a mongodump backup.
- FerretDB tracks `ghcr.io/wekan/ferretdb:latest` (chart default, pullPolicy
  Always) — expected for this chart.
- After this lands, Renovate version-only wekan bumps are safe. Note the
  existing "Non-critical services" packageRule automerges wekan minor/patch
  on schedule — 12.x point releases will flow automatically.
- Syncs on this app are manual; the first sync after merge rolls wekan +
  boards to v12.64 (WeKan runs DB migrations on boot — brief downtime per
  instance), starts the idle `home-ferretdb`, and leaves `home-mongodb`
  untouched (now rendered by the umbrella itself).
- Merge to `main` / PR creation is user-owned.
