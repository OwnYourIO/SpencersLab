## Marker contract (writer authority = the boards skill; reader = question-notify)
- Key/shape (OQ2 confirmed): top-level `metadata.pipelineNoop = { at: <epoch-ms>, reason: "no-cards" | "no-claimable-cards" }`. Never nested under `openchamber.*` (app-owned zod namespace — the writer READS `openchamber.kind` but never writes anything under `openchamber`; never touch `suggestDoneAt`/`reviewOffer`).
- Writer predicate (conjunctive, observable by the coord from its own tool calls this session): ZERO successful `pipeline_claim` (attempts returning `locked`/`ok:false` do not count; a held lock ⇒ not a no-op — alert stays) AND zero board writes (`move_card`/`add_comment`/custom-field/checklist mutations). The predicate lives ONLY on the write side — the reader never re-derives it (it cannot see the board calls without the rejected Option-A surface).
- **The writer marks every no-op end regardless of launcher** (scheduled or manual). Marker presence ALONE must never suppress: scope is the reader's conjunction (OQ4 ruling). Manual probes stay observable-by-phone by design; the writer's marker on a manual run is forensic evidence, not a mute button.
- Reader suppression predicate (all four, else push — fail-loud): (1) event is FINISHED (`session.execution.succeeded`) — crash/question/approval never consult it; (2) top-level session (existing filter first); (3) the read `metadata.pipelineNoop` is an object with a non-empty string `reason`; (4) the read `metadata.openchamber.kind === "scheduled"` (tolerant deep read; any other shape/value ⇒ not scheduled ⇒ push). Verified fact: the kind discriminator rides OpenChamber scheduled launches ([CF52-1], and the user confirmed it present on a live session record 2026-10-29).
- Exits that mark: boards-skill Card pickup step 4 "Nothing anywhere" (`reason: no-cards`) and the Parallel-pipeline-loops "at most 3 claim attempts … report no eligible work" stop (`reason: no-claimable-cards` — covers lock-availability-skipped-everything and contention alike). Gate `SKIP`/`LIVE` replies do NOT mark (OQ5 confirmed — their fail-closed minimalism forbids API/rename there; they keep alerting even when kind=scheduled, because no marker ⇒ push).
- Self-identification (OQ3 confirmed): the run uses the sessionID from its own `session_rename` if it already renamed; otherwise it calls `tools.opencode.session_rename({title: "no-op <yyyy-mm-ddThh:mm>"})` — the current-session form returns the id deterministically, the grant already exists on all six coord variants, no new permission rows, and the title is the human breadcrumb.
- Write recipe (mirrors the cf-52/kickoff in-work-mark mandate): `opencode api get /api/session/<id>` → unwrap the `{"data": …}` envelope → merge `pipelineNoop` into the CURRENT FULL metadata object (PATCH replaces `metadata` whole — a partial write deletes siblings; this is what preserves `openchamber.kind` the reader depends on) → `opencode api patch /api/session/<id> -d '{"metadata": <merged>}'`, epoch computed inline via `$(date +%s%3N)` (covered by the family's `date *` allow). Any leg failing ⇒ proceed to the clean end anyway: no marker ⇒ alert (fail-loud), never a retry loop, never a stall.
