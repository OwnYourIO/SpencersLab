## Facts this chunk builds on (RESEARCH.md §3 — do not re-derive)
- `peers:` is in the v266 schema (predates the deployed pin by ≥26 releases) and is **NOT a blanket URL proxy**: required keys `proxy` + `models` (explicit list of the inner's model IDs). Request path is appended VERBATIM to `proxy` → **no `/v1` suffix** (that would double-prefix).
- Routing/naming (O1 resolved): peer models are always addressable as `strata/<inner-id>`; the **bare inner ID also routes** while exactly one peer serves it and no outer local model/alias shadows it; outer rewrites the request-body `model` FQ→bare before forwarding, so the inner resolves its own IDs. `/v1/models` lists the qualified names.
- Anthropic `/v1/messages` routing + SSE pass through natively (peer hop rewrites Host, strips Origin, sets `X-Accel-Buffering: no`) — Claude Code via `ANTHROPIC_BASE_URL=https://llama.<domain>` works through the existing ingress/ServersTransport (responseHeaderTimeout 0, idleConn 3600s — already stamped on every gpu-ai subdomain).
- `apiKey` omitted (inner `apiKeys: []` = the quarantine posture); `timeouts.responseHeader` is THE knob for a peer that cold-starts → 1800 (O2 resolved).
- Peers are not outer `models:` entries → invisible to the outer matrix (RAM law stays operator-discipline + C04; "peers models are not reachable via /upstream passthrough" — probes stay on llama-swap's own /health, already decided).
