# C01: kickoff-mint-branch.sh — the validated branch-mint script
size: S   wave: 1   depends_on: []

## Goal

Land `scripts/kickoff-mint-branch.sh <worktree-dir> <branch>`: the single deterministic entry point that attaches the run's branch to a freshly created (detached) opencode worktree, idempotently, with in-script validation standing in for what a wildcard shell grant cannot constrain.

## Tasks

- [ ] Write `scripts/kickoff-mint-branch.sh` (bash, `set -euo pipefail`, comment header in gate.sh's voice: why the validation envelope exists — the calling coordinators hold only a `bash scripts/kickoff-mint-branch.sh *`-shaped grant, so every safety property lives here):
  - Args: exactly two — absolute worktree directory, branch name. Wrong arity → usage line + exit 2.
  - Resolve the repo: `git -C "$dir" rev-parse --show-toplevel` must succeed; the dir must appear in that repo's `git worktree list --porcelain` output and must NOT equal the toplevel (the main checkout is never a mint target — this is the rule that keeps the wildcard grant safe).
  - Branch name validation: matches `^[A-Za-z0-9._-][A-Za-z0-9._/-]*$` (no leading `-` — never an option string; reject anything else); equals `basename "$dir"` (Q2 invariant: branch == worktree name, per every observed run).
  - Mint: if `git -C "$dir" rev-parse --verify "refs/heads/$branch"` succeeds → print `EXISTS <branch> <sha>` (sha of the branch tip), exit 0, and do NOT check anything out (the worktree may sit elsewhere on purpose; resume runs get a no-op). Else `git -C "$dir" checkout -b "$branch"` from the worktree's current HEAD → print `MINTED <branch> <sha>`; on checkout failure print `REJECT <reason>` and exit 1.
  - Never evals, never word-splits args unquoted, no network, no credentials (mirror gate.sh's posture notes).

## Tests (agent-test writes, review runs)

- t1: `bash -n` static pass; shellcheck skip-with-warning where absent (t1 convention, cf-50).
- t2 happy path: scratch repo, `git worktree add --detach`, run script → `MINTED <name> <sha>`, `git -C <dir> branch --show-current` == name, HEAD sha unchanged (the base commit is preserved — the invariant cf-50/cf-52 improvisations honored).
- t3 idempotence: second invocation → `EXISTS <name> <sha>`, exit 0, checkout state untouched.
- t4 branch≠basename → `REJECT`, exit 1, scratch repo unharmed.
- t5 non-registered dir and the scratch repo's main checkout (toplevel) → `REJECT`, exit 1.
- t6 arity/bad-name negatives: 0/1/3 args → usage + exit 2; name starting `-` or containing `;`/space → `REJECT`.
- t7 branch at detached commits: commit once detached, then mint → branch includes the commit (proves the cf-52 recovery ordering is never required again).

## Notes for dev

- The script must work when invoked from ANY cwd (gate.sh precedent: nothing resolves against `$0` except the usage line).
- `checkout -b` is the only mutation; git refuses it when the branch exists — the EXISTS pre-check exists to give coord a clean idempotent verdict, not to paper a race.
