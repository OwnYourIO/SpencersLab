# C08: Locks — co-tenant cards on one pipeline, and "don't start unless the pipeline is empty" (with a human override)
size: L   wave: 2   depends_on: []

## Goal
Make one pipeline lock able to hold **more than one card** when the owner decides that's intended, while keeping the default conservative: a run does not start a claim on a pipeline that already has live foreign holders unless the human explicitly overrides. Stamp races between co-tenants are accepted by the owner ("they'll overwrite each other's timestamps, that's fine") — but one run must never release, kill, or reap another run's hold.

Single implementation: `.opencode/plugin/pipeline-locks/index.ts` (hand-managed; the plugin owns `.pipeline/` — agents never touch those files).

## Tasks
- [ ] Lock record v2: a pipeline lock file carries `version: 2` and a `holders: [{cardId, sessionID, setId, claimedAt, heartbeatAt, cardTitle?}]` list plus the file-level `claimedAt`/`heartbeatAt` stamps (last-writer-wins, kept so the existing staleness formula and the reaper's `max(heartbeatAt, mtime)` keep working unchanged). `newLockRecord` gains the holder shape; stamps stay `localIso` offset-ISO.
- [ ] `claimLockSet`: keep reap-before-claim and the one-claim-per-session-root rule. New decision tree per pipeline key: **free** → add our holder (atomic tmp+rename + `utimes`, as today); **live foreign holders and no override** → refuse with `{ok:false, reason:"occupied", pipeline, holders:[{cardId, sessionID, age}]}` (the "should not start unless the pipeline is empty" rule, now answered by the engine rather than by a `pipeline_status` guess); **live foreign holders and `shared: true` in the claim input** → append our holder and answer `ok:true` with the co-tenant list. `sanitizePipelineKey` and the sorted-set-with-rollback walk are unchanged.
- [ ] Heartbeats: a beat updates the calling session's holder stamps and the file stamp (last-writer-wins accepted); throttle/audit semantics unchanged.
- [ ] **Holder-level staleness**: `reapStale` prunes individual holders whose own `heartbeatAt` (and the file mtime floor) exceeds `staleMs`, while the file survives as long as one holder is fresh; the file is reaped (moved to `locks/.reaped/`) only when the last holder goes stale. Reap meta, `timeouts.jsonl` degrade and the Timeout-list leg gain the cardId-of-the-pruned-holder granularity.
- [ ] Release: `releaseLockSet` owner-checks per holder, removes only the caller's entries, and deletes the file only when the list empties; the "release the whole set or nothing" all-or-nothing property is preserved per holder.
- [ ] Lock-lost: `checkMember`/`handleLockLost` compare **our holder entry**, not the whole file — a stolen/absent our-holder is `PIPELINE LOCK LOST` for us; another holder's presence or a co-tenant's reap is not. Cache invalidation stays per-set.
- [ ] `pipeline_status`: report per-pipeline `holders[]` (cardId, sessionID, age, state) plus the `shared` fact, so a run can still read emptiness before claiming (the guard the boards skill keeps as a cheap plugin-aliveness check).
- [ ] boards skill, `Parallel pipeline loops`: the pick rule reworded — "SKIP a candidate whose pipeline set has live foreign holders" stays the default; a new clause defines the sanctioned override (the human told this run to share → claim with `shared: true`, and the claim comment records that the set was shared and with whom). The Exit/release bullets gain the per-holder wording; the timestamp-overwrite acceptance is stated once, with the "never release a co-tenant" boundary next to it.
- [ ] `.rulesync/rules/overview.md` (→ `AGENTS.md`): the pipeline-worker bullets state the co-tenancy posture and that emptiness is the engine's answer, not a guess.

## Acceptance criteria
1. Claiming a free pipeline behaves exactly as today (same file shape plus `holders`), and a second card claiming the **same** pipeline without `shared: true` gets `reason:"occupied"` with the holder list and writes nothing.
2. With `shared: true` both cards hold the same pipeline key; `pipeline_status` shows two holders; each run's beats keep its own holder fresh.
3. `releaseLockSet` by one card removes only its holder and leaves the file (and the other holder) intact; the file disappears only after the last holder releases.
4. A co-tenant that is reaped or lost does **not** invalidate another holder: the survivor's next guarded call still passes, and only the dead holder's session sees `PIPELINE LOCK LOST`.
5. Reaper: one stale holder among fresh ones is pruned from the file (audit + `timeouts.jsonl`/Timeout comment name the pruned cardId); the file is only moved to `locks/.reaped/` when its last holder goes stale.
6. `pipeline_claim`'s registered tool schema gains the override input; the A15 arm stays green (tool rows ↔ permission rows ↔ boards skill constants).
7. The boards skill and generated `AGENTS.md` describe the same posture the engine answers; `node --test 'tests/opencode/*.test.ts'` and `bash tests/agent-perms/surface.sh` exit 0.

## Notes for dev
- Do **not** weaken the exclusive-create primitive for the no-override path: the `wx` acquisition is what makes the empty-pipeline rule enforceable. The shared path appends via the existing atomic tmp+rename; a torn read has to fail closed (refuse the claim), never silently merge.
- Never delete or rewrite another session's holder on an error path — the failure mode the ACs exist to prevent. When an existing arm's verdict changes, that is a design signal: stop and report, don't re-pin to match the code.
- Stamps: instants (epoch-ms, mtime) are values; only displayed stamps go through `localIso`.
- This chunk does not touch the question/continue-anyway path (C09) and must not add a config flag for sharing — the override is a per-claim input the human supplies, not a site-wide setting.
