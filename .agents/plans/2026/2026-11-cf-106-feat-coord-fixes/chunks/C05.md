# C05: Friction follow-up — five modes in both coordinator families, Inbox preferred on board runs
size: S   wave: 1   depends_on: []

## Goal
When a run ends with `open` friction, the coordinator asks **how** to handle it, not just whether. Today `pipeline-role-coord` step 11 offers one multi-select and then always launches a fresh `agent-plan` per checked item, while the boards override always mints Inbox cards — neither family can say "do it here", "plan only", or "record it for the owner". The owner's ruling: the offer carries **five** options in **both** families, and on `agent-board-coord` family runs the Inbox card is the preferred (recommended) one.

## Tasks
- [ ] `pipeline-role-coord` step 11 rewritten: keep the ONE multi-select over open `FRICTION.md` items, then ask ONE mode question with exactly five options —
  1. `new session` — a fresh `agent-plan` session planning the fix as its own ticket (the shipped behavior; **recommended first** for the plain `agent-coord` family);
  2. `current session` — the fix is worked here: launch `agent-plan` (or implement inline when the item is mechanical and this role's contract permits the delegation shape it does permit — the coordinator still never writes files itself);
  3. `plan only` — write the plan file for the item and launch nothing;
  4. `Inbox card` — create a card in the board's **Inbox** (Backlog swimlane) recording the friction for the owner, per the boards follow-up-card mechanics;
  5. `none` — check nothing → stop, exactly as today's "user checks none".
- [ ] Modes are per-item overridable with a single global default; a mixed answer is allowed ("item A new session, item B Inbox"). Two questions max in the follow-up phase, never a per-item interrogation.
- [ ] Family preference stated in both places: plain `agent-coord` family recommends `new session`; `agent-board-coord` family recommends `Inbox card` and **never** treats an Inbox card as an auto-pickup item (the Backlog-swimlane location rule stays).
- [ ] Folder rules per mode: `new session`, `plan only` and `Inbox card` all create work **outside** the current ticket (its own folder / its own card); `current session` is bounded — it never re-opens a `done` chunk of the current plan, and any new work lands as a recorded new chunk in `STATE.json` plus a `DECISIONS.md` line, never as an untracked edit.
- [ ] boards `Friction follow-up (board override)` reconciled with the same five options: keep the Inbox destination, the re-resolved list id via `list_lists`, the never-`add_checklist` rule, the checklist-answers toggling line (its model reference follows C02's vocabulary if C02 landed first; otherwise leave the current literal and let C02's sweep cover it — do not half-rename), and the "this is not a run: claims nothing, moves nothing off Inbox" posture.
- [ ] `question` stays allowed in every role (unchanged) — modes are asked, never inferred.
