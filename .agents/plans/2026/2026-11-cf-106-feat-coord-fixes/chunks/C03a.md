# C03a: No-op audit instrument — prove which runs end unmarked-and-unarchived before any wording changes
size: S   wave: 1   depends_on: []

## Goal
Turn the archive/alert question from a guess into a measurement. The planning pass already read the OpenCode session store and produced the first evidence table (`2026-11-03-cf-106-feat-coord-fixes-noop-evidence.md`): **the marker+archive contract works when a run reaches a marked exit (13/13 scheduled marked runs are also archived), and the failures are runs that never reached one** — three died mid-turn on malformed `<tool_call>` output, one found its own session missing the `dev-boards` MCP tools. C03a ships the instrument that regenerates that classification on demand, so C03b's fix (and every later regression) is judged by a readback instead of a memory.

## Tasks
- [ ] New repo diagnostic `scripts/session-noop-audit.sh` (hand-managed repo machinery, the `agent-board-coord-gate.sh` precedent): read-only over `~/.local/share/opencode/opencode.db` through `python3`'s stdlib `sqlite3` (`file:…?mode=ro`; there is **no** `sqlite3` binary in the workspace), joining `session_v2` (`id,title,slug,agent,model,directory,metadata,time_created,time_archived,idle_outcome`) with the `session_message` tail, and emitting one row per board-coord session in a window: verdict class, marker presence/shape, archive presence, kind, model, title, and a one-line last-text excerpt.
  - Verdict classes (fixed vocabulary, machine-derived): `marked-archived`, `marked-unarchived`, `unmarked-archived`, `gate-stop` (first prompt line starts `GATE: SKIP` / `GATE: LIVE` / the board-check stop wording), `abnormal-end` (last assistant text carries a raw `<tool_call>`/`<function=` block or the run ends with <3 turns), `mcp-surface-absent` (the transcript reports the board MCP tools missing), `did-work`.
  - Flags: `--since <ISO>`, `--until <ISO>`, `--repo <directory>` (default: this repo's canonical root), `--limit N`, `--json`, and **`--db <path>`** (default the host store path) so the suite can point it at a fixture and the owner can point it at a copied snapshot.
  - `--abnormal-signal` needs no knob: the abnormal-end heuristic is fixed (raw `<tool_call>`/`<function=` in the last assistant text, or a turn count below the floor), and the class names are the vocabulary the readback uses.
  - **Read-only by construction**: the script opens the DB in `ro` mode and contains no `opencode api` POST/PATCH, no board call. The suite proves it by scanning its own text.
- [ ] Invocation posture (constraint-driven, spelled out in the script header and the plan runbook): a **human or an interactive session** runs it — an unattended scheduled run cannot, because its `bash scripts/…` call resolves to `ask` and `ask` denies in that posture (the owner's answer 11 keeps the toggle posture, ledger L1). No new shell grant is added anywhere for it.
- [ ] Runbook: `tests/cf106-noop/readback.md` — how to run the audit after C03b lands, and what "fixed" looks like: zero `unmarked-*` scheduled rows for runs whose last verdict was a stop path, and the alert-silence claim checked against the marker column, not against memory.
- [ ] Fold the planning-pass table into the evidence artifact as the baseline (it is already written; C03a only has to reproduce it, proving the script's classification matches reality).

## Acceptance criteria
1. **Baseline parity, non-flaky by construction.** `bash scripts/session-noop-audit.sh --since 2026-11-02 --until 2026-11-04` must reproduce the evidence artifact **row by row for the session ids the artifact names** (as of its 2026-11-03T22:45Z read: 32 `marked-archived` scheduled rows, 6 unmarked scheduled rows — 2 `abnormal-end` on raw tool-call XML, 3 mid-turn deaths after the lock check, 1 `mcp-surface-absent` — and the 1 manual `probeSentinel` control row). Sessions created after the artifact's timestamp must **not** change any of those verdicts; the comparison is per-id, never a total-count equality, because the store is live.
2. The verdict vocabulary is exhaustive and mutually exclusive as implemented: every row gets exactly one class; an unparseable session falls into `did-work` rather than crashing.
3. The script is read-only: no `mode=ro`-less connect, no `opencode api post|patch`, no `dev-boards` call, no write to `.pipeline/` or any session record (machine-checked).
4. No permission change anywhere in this chunk: no new `bash scripts/session-noop-audit.sh` shell row is added to any agent (the A12/A15 arms stay green and prove it).
5. `bash tests/cf106-noop/surface.sh`, `bash tests/noop-marker/surface.sh` (unchanged, HOLD), `bash tests/agent-perms/surface.sh`, `bash tests/agent-board-coord/gate.sh` exit 0.
