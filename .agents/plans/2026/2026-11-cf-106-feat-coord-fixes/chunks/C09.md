# C09: After a reap — one sanctioned "continue anyway" question, then a takeover lock keyed by the card id
size: M   wave: 3   depends_on: [C08]

## Goal
A run whose lock set was reaped (the owner paused too long at a human stop, or a stale-clock reap fired mid-run) currently has exactly one contract: stop forever, "only a fresh run re-claims". The owner wants an escape hatch with a human in it: stop, **ask once** whether to continue anyway, and if yes, resume this card under a lock named by the **card id** — a key no other run is contending — instead of re-fighting the pipeline label that got reaped.

## Tasks
- [ ] Signal, not question (plugins have no question channel): on `handleLockLost` and on the reap-of-our-own-set path, write the takeover hint into the session pin next to the existing `LOCK_LOST_STOP` pin — the reaped `cardId`, the pipeline set, and the reap stamp from the `locks/.reaped/` record — and extend the `PIPELINE LOCK LOST` text with the takeover instruction ("stop the current step; ask the user ONCE whether to continue anyway; on yes, re-claim with `pipelines:[<cardId>]`; on no or silence, take the blocked/abandoned exit"). Keep the phrase `PIPELINE LOCK LOST` and its do-not-commit/do-not-move meaning intact — suites and agents depend on that literal.
- [ ] Takeover claim support in `claimLockSet`: when the claimed set is exactly `[<cardId>]` for this run's card **and** a reap record for that card exists, mark the claim `takeover: "after_reap"` in the lock record and the events audit — an evidence trail, not a new permission. No auto-reclaim: the engine never claims on the run's behalf, and a takeover without a reap record is an ordinary claim under a card-id key (legal, unpinned by policy but not audited as a takeover).
- [ ] Reaper's human-facing outputs gain one line each: `reapCommentBody` and the Timeout-list comment carry "a fresh run may continue this card if the owner approves; it will hold the card-id lock" — the Timeout triage stays human-owned, and until the **Timeout** list exists live, the `.pipeline/timeouts.jsonl` degrade row keeps the same fields plus the takeover hint.
- [ ] boards skill: `Parallel pipeline loops` → Human stops (D20/D21) and Exit bullets: the `PIPELINE LOCK LOST` posture becomes "stop the step, then exactly ONE sanctioned question in this run; answer gates the resume". Define the resume shape: re-claim with `pipelines:[<cardId>]`, keep the card where it is (it is already **Executing** or **Timeout** — moving it back out of **Timeout** is the owner's call, so the run asks before any move), append a comment naming the takeover and the lock key, and record the takeover in STATE.json `kickoff.claim` (the lock set it now runs under). A run that gets no answer within its own session takes the abandoned exit — never a silent resume, never a second question.
- [ ] `pipeline_release` unchanged in meaning; the Exit "blocked → abandon-release or keep-and-stale" choice keeps its wording, with the takeover option named ahead of it as the human-gated branch.

## Acceptance criteria
1. A reap of the calling session's own set (or a lost our-holder) produces a stop signal whose text names the takeover path, and the session pin carries `{cardId, pipelines, reapedAt}` evidence.
2. The engine never re-claims by itself: after the reap, any further guarded write still refuses until a new `pipeline_claim` succeeds in this session.
3. A claim with `pipelines:[<this run's cardId>]` after a recorded reap lands a lock whose record and audit line say `takeover: "after_reap"`; the same claim with no reap record lands as an ordinary card-id-keyed claim (no takeover tag).
4. A takeover claim under a card-id key does not touch, invalidate or read the original pipeline's lock file (the reaped pipeline may already belong to another run).
5. The boards skill's stop/exit bullets state the one-question rule, the resume lock key, the no-answer exit, and the "Timeout→out is the owner's move" boundary — in source **and** mirror, and the `TICK_PROMPT` parity pin matches the rewritten section.
6. `node --test 'tests/opencode/*.test.ts'` (esp. `-reap`) and `bash tests/agent-perms/surface.sh` exit 0.
