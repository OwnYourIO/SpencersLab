## Decisions

- 2026-10-29 plan D1: **Design A — explicit `-C` READ rows** (nine verbs) + `git worktree list*`, inserted after `git ls-files *` before `git add *`, block grows 14→24 (-local/alias) / 19→29 (-pr). Alternative B (one `git *` allow before the push/force denies) rejected: the deny rows are prefix-literal, so `git push*`/`git push*main*` cannot match `git -C <repo> push …` — B silently opens cross-worktree push (incl. main, the repo's most forbidden action), checkout/reset/worktree-remove anywhere; plugging it needs unbounded mid-command globs (`*main*`, `*push*`) that also kill legitimate reads (`git -C x log main..HEAD`). Safety rationale for A: every granted verb is read-only or ref-shared (bare `git branch *` already mutates shared refs from any dir — `-C` adds no new power class); all HEAD-moving verbs stay at the deny baseline including their `-C` forms. Evidence: agent-coord.md:78-119/118-134, agent-perms A10 matcher model :809-830, D27 entry permissions.md:90.
- 2026-10-29 plan D2: new rows use the **no-space `verb*` shape** — matches zero-arg AND arg forms in one row. Precedents: `git push*` (shipped), `bash scripts/session-origin.sh*` (documented zero-arg rationale), fuser's bare+space pair `git worktree list`/`git worktree list *` (agent-fuser.md:75-79) subsumed. `list*` prefix collides with no other worktree verb; `show*`/`log*`/`branch*` suffix forms touch no mutation verb.

- 2026-10-29 plan D13: **D27 directory-blindness residual ACCEPTED.** `git -C <other> commit/rebase/cherry-pick` write verbs act on the TARGET worktree's current branch and no glob can restrict the directory.
