# C04: Restore HA pushes — resolve the ha-mcp URL from the plugin ctx's MCP CONFIG view

size: M   wave: 4   depends_on: [C03]

## Goal
Fix the live incident: since the 2026-10-25 fleet split (commit 5dcc99dab moved
`admin-global-homeassistant` from the project config to the machine-global
`~/.config/opencode/opencode.json`), EVERY push of every trigger (question,
lifecycle, approval) dies in `haMcpUrl()` — 94× "no URL found for
admin-global-homeassistant" in the coder pod's stdout. Both discovery legs
broke: `ctx.mcp.list()` on v2.1.4 returns the status view `Mcp.Server
{name,status,integrationID}` (additionalProperties:false — no `url`, so the
`typeof cfg?.url === "string"` check never matches), and the project-jsonc
fallback now parses a file with 0 HA hits. User-chosen fix (intake decision):
make `haMcpUrl` resolve the URL through the plugin ctx's MCP **config view** —
`ctx.mcp.transform((editor) => editor.get(MCP_SERVER_KEY))`, whose entries
carry the full server config including `url`, and which includes servers
declared in the machine-global config because `ConfigMCPPlugin` feeds every
config document into that state (plan Grounding #18–#25). One fix in one
function restores all three push paths at once, because they all funnel
through the single `sendHANotify` → `haMcpUrl` chain.

## Notes for dev
- The exact ctx shape (v2.1.4, binary-verified — do not "optimize" against the
  docs, which still describe the V1 ctx): `ctx.mcp.transform(callback)` returns
  `Promise<{ dispose: () => Promise<void> }>`; `callback(editor)` receives
  `{list(): [name, config][], get(name): config | undefined, set, update,
  remove}`; config entries for remote servers carry `{type:"remote", url,
  headers?, oauth?, disabled?, codemode?, timeout?, protocol?}`. Leg 1 must
  await the Registration promise, capture in the callback, dispose in a
  finally, and tolerate the callback firing 0..N times (idempotent capture).
- Why never-throw-in-callback is not just style: the v2.1.4 state machinery
  wraps registered callbacks in a group — a throw marks the group failed and
  removes ALL its registrations (and a failed group makes FUTURE transform
  calls no-op, callback never firing). The plugin survives by catching inside
  the callback (H6 pins it).
- Keep the `list()` scan's existing tolerant entry-form handling verbatim as
  leg 2; only its POSITION (after a leg-1 miss) changes. Do not merge the two
  legs into one loop.
- Remove the dynamic `node:fs`/`node:path` import with the parse (AC 5 greps
  `node:fs` too — the string appears in the import line you are deleting).
- `sendHANotify`'s URL handling, handshake, `tools/call`, error logging, and
  the 240 cap stay byte-identical — the fix is strictly inside discovery. All
  three triggers (question hook, lifecycle `deps.notify`, fired approval
  callback) already share the single `sendHANotify(ctx, …)` path, so restoring
  `haMcpUrl` restores every trigger at once — do NOT add per-trigger URL logic.
- Erasable-only TS, no deps, nothing new under `.opencode/` besides the plugin
  file edit; zero edits under `tests/` (agent-test owns the new file).
