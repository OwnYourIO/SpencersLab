# C03: Pending-only approval push — 15 s timer per request, `permission.replied` cancels
size: M   wave: 3   depends_on: [C02]

## Goal
Stop pushing "needs approval" the moment `permission.asked` arrives. The user's
OpenChamber client has **Permissions: accept everything** checked: it answers the
ask milliseconds after the server publishes it, and C02 pushed anyway (live bug
report, 2026-10-27). New contract: a push happens **only if the ask is still
pending 15 s after arrival** — on `permission.asked` start a per-request-id
timer; if a `permission.replied` for that request id arrives first (auto-approve,
a human clicking once/always, OR a human rejecting — every reply value cancels,
plan Grounding #14), cancel the pending push; if the timer fires, push with the
existing title/excerpt contract. 15 s is the user's explicit choice ("Actually,
make that 15s"). Lifecycle and question behavior stay exactly as shipped; the
legacy 35 tests stay byte-identical.

Design consequences (DECISIONS 2026-10-27): the cooldown gate is consulted at
PUSH time (inside the timer callback), not at arrival — a cancelled ask must not
consume a cooldown stamp. The subscribe loop itself does not change: it already
dispatches every event to `handlePermission`, which now self-filters on BOTH
`permission.asked` and `permission.replied`.
