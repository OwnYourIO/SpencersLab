# C01: Lifecycle events — finished & crash-out HA notifications
size: M   wave: 1   depends_on: []

## Goal
The question-notify plugin subscribes to the OpenCode V2 event stream and
pushes one Home Assistant notification when a TOP-LEVEL session completes an
assistant turn (`session.execution.succeeded`) and exactly one when a
top-level session stops on a terminal execution failure
(`session.execution.failed`), while child (subagent) sessions, retries,
interrupts and all other event types produce nothing. Existing question
notify behavior is untouched.

## Tasks
- [ ] Export the test seam from `.opencode/plugin/question-notify/index.ts`:
  `isTopLevel`, `truncate` (identical semantics to today's
  `s.slice(0, MAX_MESSAGE)`), `questionTitle`/`finishedTitle`/`crashTitle`,
  `lastAssistantExcerpt`, `crashExcerpt`, `handleLifecycle(deps, event)`.
- [ ] Implement `handleLifecycle` dispatching on `event.type`: only
  `session.execution.succeeded` → finished push and `session.execution.failed`
  → crash push; every other type (including V1-compat `session.idle` /
  `session.error`) ignored. Look up topology via injected session getter;
  child sessions (`parentID` present) and failed lookups suppress the push.
- [ ] Finished push: title `OpenCode: <agent> finished`, message = last
  assistant `text` part excerpt (fallback `"no text output"`), capped at 240.
- [ ] Crash push: title `OpenCode: <agent> stopped`, message =
  `error.message` (fallback `error.type`, then `"unknown error"`), capped
  at 240.
- [ ] Wire the live loop in `setup`: `for await (const event of
  ctx.event.subscribe({ signal }))` → dispatch each event as a fire-and-forget
  promise (`void handleLifecycle(realDeps, event).catch(log)`), never breaking
  the loop or the agent; return a cleanup that aborts the controller.
- [ ] One-shot stderr debug log for the first lifecycle-type event received
  (keys of the event + of `event.data`), following the existing
  `debugLogged` convention, so the user-owned live smoke can confirm the
  envelope shape.
- [ ] Create `tests/opencode/question-notify.test.ts` covering the Tests
  list below; import plugin helpers from
  `../../.opencode/plugin/question-notify/index.ts`.
- [ ] Keep the existing question tool-hook path byte-equivalent in behavior
  (its filter, cooldown, and title are regression-checked by the tests).

## Notes for dev
- Do NOT convert the default export to `Plugin.define` — the current
  plain-object `{ id, setup }` shape is user-verified against the installed
  v2.0.32; changing it risks the working question path.
- `setup` currently returns nothing; returning
  `() => controller.abort()` is per the V2 guide and safe.
- Real deps: `getSession = (id) => ctx.session.get({ sessionID: id })`,
  `getMessages = (id) => ctx.session.context({ sessionID: id })`,
  `notify = (title, message) => sendHANotify(ctx, title, message)`. Extend
  `sendHANotify` to take the full title string (question path builds its
  title via `questionTitle` so the produced notification is unchanged).
- The subscribe loop must guard every branch: a throw inside the loop body
  must not stop consumption (wrap each event in `void ... .catch(err =>
  console.error(...))` like the existing fire-and-forget).
- No npm deps, no package.json, nothing added under `.opencode/` beyond the
  plugin file edit. Tests import the `.ts` directly — Node v26 type-stripping
  runs it; keep syntax erasable-only (no enums/namespaces/parameter
  properties).
- Live-server verification (service restart + phone pings) is USER-OWNED:
  record it in the change manifest; never run `opencode service restart`
  yourself.
