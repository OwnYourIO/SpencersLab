# C10: Question-flow wiring — breach + resume procedures, B1 decision-order guarantee
size: M   wave: 2   depends_on: [C07, C08, C09]

## Goal

Complete the card's question flow: when a question sits unanswered >15 minutes the reconciler
RECORDS it, moves the card to **Awaiting Answers**, settles the pending Form so the run cannot
suspend forever (P6: cancel-with-message), alerts on the O2-RULED channel (admin-HA,
`haNotify`-gated, transport live from C15 — interim comment+row), and STARTS THE NEXT
AVAILABLE TASK; when the user answers (a human change on the Awaiting-Answers card) the card
returns to Executing and the run wakes on a bounded one-line forward. The B1 order guarantee
becomes a pinned, end-to-end doctrine.

  would resume pending steers the Esc-footgun class, X10/R4). If in doubt, omit: the Form
  cancel alone settles the run.

  only), so the push leg is plugin-side, and its transport home is card-runner from C15
  (pipeline-locks' copy stays live until then — do NOT duplicate it early). Sequencing,
  recorded in the subsection: before C15 the breach alert = card comment + jsonl row

  the doctrine that a wave-2-tip branch has no phone push for breaches — the channel is
  ruled, the transport lands at C15. question-notify stays disabled and byte-untouched
  regardless (no re-enable, no cross-plugin dedupe).
- The resume leg's "human change" detector interim (comment-id-set from the preload snapshot)
  is exactly one of the C12 hash fields — the doctrine wording should cite the field, so C12
  industrializes without a doctrine edit.
