# C12: Card-change detection + bounded forwarding (`.pipeline/cards/` store, M6 bounds)
size: L   wave: 3   depends_on: [C05, C07, C10]

## Goal

Industrialize the reconciler's "user changed the card" leg as ONE detection design (RESEARCH
§4.1/§6.10 — snapshot-diff floor + scoped-activity classifier + timestamp hint, one apply
function): card-runner keeps the per-card store `.pipeline/cards/<cardId>.json` (the R4 §4.1
record), hashes a canonical projection per tick, classifies human-vs-agent, and forwards
changes as a CARD.yaml REWRITE + ONE bounded line (`synthetic` + `queue`, idempotent inbox
id) — never a payload paste, never the new context injector (M6).

## Acceptance criteria

1. `node --test tests/opencode/*.test.ts` GREEN; detection battery added (count grows).
2. Projection law pinned: `sort` EXCLUDED, no `updatedAt` anywhere in the module (negative
   grep), comment id-set (not timestamps), labelIds sorted-set, custom fields name-keyed,
   checklist pairs in stored order, timestamps hashed-but-classified-separately (arms quote
   the field list against the R4 law).
3. Cross-process durability: store row written by one instance reads back from a fresh
   instance (the two-process simulation arm); torn-write protection (injected failure
   preserves the prior row).
4. Self-change filter: an agent-published hash matching the new state ⇒ clean pass writes
   NOTHING (the controller discipline arm); a hook-blind-field delta with no agent attribution
   ⇒ classified human; ambiguous ⇒ fail-open human + exactly one forward (dedupe arm).
5. M6 bounds: forward line <300 chars pinned; `delivery:"queue"` + idempotent inbox id pinned
   (a replayed tick with the same id forwards nothing — first admission wins); coalesce arm
   (two deltas, one tick → one forward); cap arm (6th human delta → no forward + comment-once
   + `card_forward_capped` row).
6. Degrade arms: `list_card_activities` absent → snapshot-only classification, RESULT-style
   audit note, never a failure; `whoami` absent → free-pass filter; MCP failure → one retry,
   then skip the tick's detection, never throw (never-throw law battery extends).
7. CARD.yaml rewrite arm: the forward leg rewrites the file with the new snapshot stamp
   (fixture folder), and the one-line forward NAMES the file, never pastes card content
   (negative grep on the forward template).
8. Zero `ctx.storage` in the new legs (M1 grep arm holds); bounded-life retirement arm (card
   leaves tracked set → record retired on a later tick).
9. boards-skill matrix row 5 cites the contract; `bash tests/dispatcher/surface.sh` GREEN
   (C07 arms + a new row-5 arm); `generate --check` GREEN + idempotence.

## Notes for dev

- The inbox-item id shape: caller-supplied, stable across replays — derive from
  `(cardId, hash)` (NOT a timestamp — a replayed tick must reuse the id; "first admission
  wins, retried payload/metadata/delivery ignored" is the upstream contract R4 verified).
- `ctx.session.synthetic` exists on the plugin ctx (R3/R4 parity table) — but inbox
  list/update/cancel do NOT (HTTP-only); the forward leg needs only synthetic+queue. Verify
  the plugin-ctx parity on the shipping build (R-2 fan-out guard applies to any event-driven
  enrichment here).
- The plan-folder resolution interim (lock-file join) must carry the same TODO-to-C14 comment
  discipline as C08 — one join module both legs share, so C14 re-points ONE function.
- The forward template's actor class wording: "by the owner" vs "by a run" — keep it coarse
  (the filter's output is a class, not an identity claim).
- aislop: this is card-runner's biggest leg — keep functions small; the file-too-large debt
  class is accepted but complexity errors are not.
- O6 discipline (ruled 2026-11-23): the classifier's factual floor — REST writes bypassing
  the activity hooks, `modifiedAt`/`dateLastActivity` bumping on UI writes only, the scoped
  export answering per-card, the admin export flags — is TAG-PINNED SOURCE evidence
  (`[v12.99]`), NOT pod-proved until the owner's C19 probes. Every leg that leans on those
  facts stays capability-gated with a degrade that is correct even if a fact flips on the
  deployed pod (snapshot-diff is the floor precisely because it needs none of them); code
  comments label the mechanism with its evidence class, never as "verified live".
