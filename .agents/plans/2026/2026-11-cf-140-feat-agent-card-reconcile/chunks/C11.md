## Notes for dev

- The scoped export answers activities for the card PLUS whatever the scope pull includes —
  filter client-side on `cardId` before slimming (the exporter's flat-array shape, EXPLORE-
  wekan-mcp §4 Option C).
- Activity documents have no schema (server-only collection) — pass through field names as
  the v12.99 source shows them (`userId`, `activityType`, `value`, `oldValue`, `timeKey`,
  `timeValue`, `timeOldValue`, …); do not invent camel/snake normalizations beyond the slim.
- The four both-path activity rows (move, archive, delete, comment — R4 §1.3) are the ones the
  C12 self-change filter must weigh; the tool stays dumb (return the rows), the classifier
  lives in card-runner.
- Server-side startup already computes the user identity for its own guard — reuse that
  value/path for `whoami`, never a second login.
