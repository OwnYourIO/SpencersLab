# C08: card-runner question hook — durable pending-question record
size: M   wave: 2   depends_on: [C03]

## Goal

card-runner owns the question-detection leg itself, independent of question-notify's disabled
state (the O2 research law; RV §4.4 requirement): an `execute.before` hook on the `question`
tool records `{sessionID, cardId, askedAt, questionText, callId}` durable + cross-process at
hook time, with consume-once claims against the multi-instance fan-out (#56290/R-2) and
dedup keys that tolerate BOTH Code-Mode call-id shapes (#65742/R-3). The durable Form read
(C07/C10, reconciler-side) stays the truth; this record is the cardId join + `askedAt`
accelerator the Form itself lacks (R3 §1: the Form record carries no ask-time).

      this leg only RECORDS (alerting is the reconciler's breach procedure, C10; the O2

## Acceptance criteria

1. `node --test tests/opencode/*.test.ts` GREEN; new question-hook battery added (count grows).
2. The record is durable + cross-process: a fresh plugin instance (empty in-memory state)
   reads the file and sees the ask (two-process simulation arm — the class that killed the
   board-context guard).
3. Fan-out dedupe: the same event delivered to two injected instances writes ONE record
   (consume-once arm); both call-id shapes (outer-execute id, nested per-call id) dedupe to
   one ask (R-3 arm).
4. cardId join: with a fixture lock file the row carries the cardId; without one it carries
   `cardId: null` + never throws (interim-join arms; the C14 registry re-point is a named
   TODO comment in code citing the chunk, not a guess).
5. Never-throw law: hostile ctx, missing hook surface, fs failures → degrade line + no record
   + no throw (battery extends C03's).
6. `grep -c "ctx.storage" .opencode/plugin/card-runner/index.ts` still 0 (M1 holds with the
   new legs).
7. No push/notification in this leg (negative-grep arm: no HA/MCP notify calls in the question
   path — alerting is C10's reconciler-side procedure; the O2 separation).
8. R-8 shipping-build duty recorded in the chunk's review notes: `form.metadata.kind===
   "question"` + `q0,q1,…` keys + `ctx.session.form.*` presence were live-probed on v2.3.2 by
   R3 but must be re-proved on the deploy build before the breach leg (C10) flips on — the
   hook record itself has no such dependency (execute.before is proven since 2.1.x).
