# C05: CARD.yaml contract — schema home, coord writer step, plan-file map, three-home rule
size: M   wave: 1   depends_on: [C04]

## Goal

Land the card-as-YAML dump the card asks for: the coordinator writes the card it holds as
`CARD.yaml` into the run's plan folder (the plan-file maps explain what it holds and that
agents read it), the reconciler refreshes it on detected human changes (C12 wires the
machinery; the CONTRACT lands here), and the three undefined homes (Worktree-unchecked,
grouped sibling, Rework re-pick) get ONE explicit rule (RV M5). No new MCP tool: the dump is a
YAML rendering of `get_card_details` (RESEARCH §4.2/§6.2 — the `format: yaml` arg stays cut).

## Notes for dev

- The dump is written by an AGENT (coord), not the plugin — no plugin code here. Keep it that
  way (P2): the plugin cannot know the folder at claim time (the folder does not exist yet —
  agent-plan creates it after kickoff).
- YAML by hand-rolled string construction is the house pattern (formatBlock precedent); the
  coord may also simply render the JSON payload as YAML-ish key: value lines — the schema
  section pins what must be present, not the emitter.
- CARD.yaml is a plan-folder file: coord-writable (its permission rows already allow plan-file
  edits — verify `CARD.yaml` is admitted by the coord edit allows; if the allows are
  path-literal (STATE.json/DECISIONS.md/FRICTION.md), add CARD*.yaml rows in this chunk —
  agents-sync permission-drift lesson: drift is silent).
- Staleness stamp is mandatory in the header: an old CARD.yaml in a long-running session must
  be visible as one (the block-footer posture).
