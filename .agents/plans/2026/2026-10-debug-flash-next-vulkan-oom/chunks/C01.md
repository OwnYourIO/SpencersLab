## Acceptance criteria
1. `EVIDENCE.md` exists in the feature folder and contains the full crash-window upstream log with the radv line and the abort stack.
2. It states, with journal excerpts or an explicit "absent" note, whether the same-window `amdgpu_vm_validate`/command-submission kernel errors occurred on gpu-ai (distinguishes kernel-GTT exhaustion from a purely userspace allocation failure).
3. It contains llama.cpp's own view of Vulkan0 memory (from `--list-devices` or load-time `Vulkan0 ... [memory]` lines) plus the `mem_info_*`/gttsize values from the host — i.e. the real device-local budget, replacing the unverified 512 MiB number.
4. A successful-load comparison (q8 MoE) is captured on the same axis, so "what changed" between working and crashing regimes is quantified (resident GiB, device allocations, free RAM).
5. A one-paragraph "what the crash is NOT yet ruled out of" list feeds the research/reintegration pass (double-count vs aperture vs build-support vs KV size).
