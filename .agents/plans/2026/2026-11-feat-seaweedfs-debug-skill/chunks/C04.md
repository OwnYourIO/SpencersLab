- [ ] `skills/seaweedfs-debug/references/loki-recipes.md` — LogQL recipes for debugging
      SeaweedFS FROM its log store (the lab ships weed logs to the Loki that itself stores on
      weed — the self-reference is the point):
  - Label reality: stream label is `app_kubernetes_io_name="seaweedfs"` (there is NO `app`
    label); `pod` rides STRUCTURED METADATA, not a stream label — aggregate/match with
    `by (pod)` / `| pod=~"seaweedfs-volume-.*"` after a pipeline stage, never inside the stream
    selector.
  - The self-query-noise rule: a verification query served by this Loki GETs the very index
    objects stored on SeaweedFS — querying a corrupt window regenerates the error lines it is
    measuring (and re-triggers the s3 retry loop while the bad object lives). Recipes therefore
    measure RATES over fresh windows (or s3-side `retry reading` counts), never historical
    totals, and post-repair verification uses a window that starts after the fix.
  - Paste-ready queries (each with what-it-proves): per-pod churn rate
    (`sum(count_over_time({app_kubernetes_io_name="seaweedfs"} |= "error writing JSON status"
    [1h])) by (pod)`); s3 retry-loop driver (`… |= "retry reading"` rate + fid extraction);
    Loki-side NoSuchKey sweep (`{cluster="monitoring", app_kubernetes_io_name="loki"} |~
    "NoSuchKey"`); filer deletion-queue retries (`|= "max retry attempts (10) reached"`);
    read-only marks (`|= "is read only"`); EC churn trio on admin (`|= "relaxed placement"`,
    `|= "EC Detection: stopping early"`, `|= "invalid task ID"`); vacuum skips
    (`|= "skip vacuuming: not enough copies"`); idx>dat load-time marks (`|= "idx references
    end="`); post-restart verification windows.
  - Agent access note: these run via `readonly-global-grafana` (Loki datasource) — read-only
    and agent-safe; the Grafana tool names/datasource id belong to the fleet config, not here.
