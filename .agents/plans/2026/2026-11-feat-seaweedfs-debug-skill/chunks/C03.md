- [ ] `skills/seaweedfs-debug/references/weed-shell.md` — operating discipline:
  - The pasteable exec pattern (lab-grounded): `kubectl -n default exec -i seaweedfs-master-0
    -c seaweedfs -- weed shell -master=localhost:9333
    -filer=seaweedfs-filer-client.default:8888 2>&1 <<'EOF' | tee <log>` + the binding rule:
    a heredoc feeds the pipeline segment it is attached to — `A | tee f <<'EOF'` feeds TEE and
    the shell gets nothing (verified by experiment 2026-11-11); tee goes LAST.
  - Lock-first law: mutation verbs need `lock` in the SAME piped session
    (`lock\n<cmd>\nunlock`); the lock is cluster-wide exclusive and BLOCKS while another holder
    (admin maintenance worker, human shell) has it; broken pipe mid-run leaves the cluster
    locked → recover with `echo "unlock" | weed shell …`; read-only verbs never lock.
  - Piped-mode exit-code law (4.50, PR #11117): exit 1 if ANY piped command failed (`lastErr`
    sticky — later successes never clear it); interactive sessions exit 0 after errors; usage
    errors exit 2; stderr carries `error: <detail>` per failed command. Build scripts on
    piped mode + exit status.
  - `-collection` matcher discipline table: `""`/`*` = every collection (verb-dependent),
    `_default` = the unnamed pool exactly, a literal name (`logs`, `media`, `default`) matches
    only that name — the admin UI RENDERS the unnamed pool as "default" but the shell does NOT
    alias it (`-collection=default` on this cluster is a silent no-op). Per-verb notes:
    `ec.decode` accepts `""` ≡ `_default`; `volume.mark` help names `_default`;
    `-volumeId` scoping is collection-free.
  - Simulate-first discipline: `volume.check.disk` / `volume.fsck` without `-apply` are read-only
    diagnostics — run them first, read the verdict, branch (the verdict texts and branches live
    in the runbook Phase 3; link, don't restate).
  - Long-run realities: check.disk/fsck take hours on 10k+ entry indexes (tmux/screen); fsck
    reverse-mode progress is `-v`-gated and the first finding prints only after the full filer
    walk (a silent fsck is WORKING, not hung); probe lines (`volume.list -readonly`,
    `volume.list` stats fields `file_count`/`deleted_file`).
- [ ] `skills/seaweedfs-debug/references/collections-and-ec.md` — mechanism facts:
  - Why this cluster's big pool is UNNAMED: the four dynamic-CSI StorageClasses
    (`seaweedfs-{extra,important,backups,backup-important}`,
    `services/infra/prod/templates/pvc-storage-classes.yaml`) carry no `collection` parameter;
    named pools (`logs`, `media`, …) come from explicit bucket/collection config.
  - The display-alias trap (admin UI "default" == `""`) with the §R1.4 evidence chain in one
    paragraph + pointer.
  - EC arithmetic: RS(10,4) = 14 shards; decode requires ALL 10 DATA shards present (parity
    optional — decode does not RS-recover); `ec.rebuild` reconstructs from ANY ≥10 of 14 and is
    the prerequisite when a data shard is missing; ≤9/14 = mathematically unrecoverable. Batch
    decode aborts on the first failing group → always per-`-volumeId`. Empty-index groups purge
    cleanly on decode (no volume created).
  - Shard inventory surfaces: admin `/storage/ec-shards` (HTML, `data-volume-id` rows, health
    labels like "Minor Issues"/"Degraded"), `/storage/ec-volumes/{id}`, shell `volume.list` EC
    lines, `/api/admin` `total_ec_volumes`/`total_ec_shards` totals.
  - Read-only mechanics condensation (§R1.2): the five trigger sites (load-time idx>dat,
    disk-space-low, IO quarantine, unavailable-marker, operator mark), which persist (`.vif`;
    operator + unavailable) vs runtime-only (idx>dat re-detects every load; disk-space-low
    self-clears on probe), what `volume.mark -writable` actually does (reopen idx, clear flags,
    rewrite `.vif`, notify master), NO self-heal mechanism exists, `-fixReadOnly` experimental +
    uni-directional.
  - Vacuum mechanics condensation (§R1.3): master auto-sweep every ~14 min (840 s + jitter,
    leader-only, `garbageThreshold` 0.3, skips read-only except disk-space-low); explicit
    `volume.vacuum` (`-volumeId` vacuums a read-only volume anyway); `volume.vacuum.disable/enable`
    around long repair windows; `volume.deleteEmpty` candidate rules; the diverged-pair hazard —
    vacuum hardens divergence (per-replica tombstone loss, revision bump closes the resurrection
    gate, deleted-data resurrection on the wrong replica) → heal BEFORE vacuum;
    `vacuum.submit.all`/`delete.emptyVault` DO NOT EXIST in 4.50 (guide-era phantoms).
  - "Never EC again" posture: Phase-0 env var state + why `WEED_MAINTENANCE_ENABLED` stays unset
    (auto-vacuum must keep running); EC needs ≥15 distinct-fault-domain servers for 10+4 with
    tolerance — single-node infra never qualifies; the prevention idea (collection params on the
    StorageClasses / `fs.configure`) with a pointer to runbook Phase 5.
