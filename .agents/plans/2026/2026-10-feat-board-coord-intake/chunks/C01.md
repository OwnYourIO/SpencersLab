## Pinned tool interface (consumers in C02–C03 quote these names)
- `list_custom_fields(board_id)` → `GET /api/boards/{b}/custom-fields` →
  `[{id, name, type}]` (v9.99 returns exactly these three per row).
- `get_custom_field(board_id, custom_field_id)` →
  `GET /api/boards/{b}/custom-fields/{cf}` → slimmed full doc: `{id, name,
  type, settings, show_on_card, automatically_on_card, always_on_card}`.
- `create_custom_field(board_id, name, type, settings=None,
  show_on_card=True, automatically_on_card=False,
  show_label_on_minicard=False, show_sum_at_top_of_list=False)` →
  `POST /api/boards/{b}/custom-fields` with JSON body
  `{name, type, settings: {}-defaulted, showOnCard, automaticallyOnCard,
  showLabelOnMiniCard, showSumAtTopOfList}` → `{id}`. Docstring MUST warn:
  v9.99's REST create IGNORES `alwaysOnCard` and does not backfill existing
  cards (research §1).
- `set_card_custom_field(board_id, card_id, custom_field_id, value)` —
  upsert with attach-if-missing: `GET /api/cards/{c}` → take `listId` +
  `customFields`; entry exists →
  `POST /api/boards/{b}/lists/{l}/cards/{c}/customFields/{cf}` body
  `{value}`; not attached → `PUT /api/boards/{b}/lists/{l}/cards/{c}` body
  `{customFields: [existing..., {_id: cf, value}]}` (the dedicated POST
  route silently no-ops on unattached fields — research §2). Returns
  `{card_id, custom_field_id, value, attached}`. Docstring notes the
  whole-array read-modify-write races concurrent UI edits; single-agent
  board accepted.
- `delete_checklist_item(board_id, card_id, checklist_id, item_id)` →
  `DELETE /api/boards/{b}/cards/{c}/checklists/{cl}/items/{i}` (exists in
  v9.99: `server/models/checklistItems.js` ~L217). Returns
  `{deleted: true, item_id}`.
- `_slim_card` additions: `card_number` (None for the by-list projection —
  documented in `list_cards_in_list`'s docstring: use `get_card` for
  labels/custom fields/card number).
