size: M   wave: 2   depends_on: [C02]

## Goal

Render the canonical-instance credentials into dev workspaces: a
`forgejo-token-canonical` ExternalSecret + `bitwardenIds` sentinel + UUID slot,
and the matching `FORGEJO_TOKEN_CANONICAL` / `FORGEJO_HOST_CANONICAL` container
env in the kubernetes-hardened template — exactly the names C02's startup
script consumes (dependency: the env-name contract; dev-git-auth's c6-style
cross-check compares both sides).

## Notes for dev

- Mirror `secret-forgejo-token.yaml` closely — its comment header carries the
  PASSWORD-field convention note; the new item is `forgejo-token-canonical`
  (its own item; never point two concerns at one Bitwarden item).
- `optional = true` on the secret_key_ref is load-bearing: until User action 1
  lands the UUID, the Secret doesn't exist on-cluster and workspaces must
  still start (the script then simply skips the canonical pair — C02's guard).
- Do NOT touch the legacy `kubernetes/` template or `terraform.tfvars`
  (out of scope; DECISIONS 2026-10-24).
- Landing order on-cluster is coord's concern: repo merge → ArgoCD syncs the
  ExternalSecret (refresh fails until the item exists — `optional` keeps
  workspaces alive) → user fills UUID + creates the PAT.
