# C04: dev coder server-side — Forgejo external-auth provider + token encryption (GitOps)
size: M   wave: 3   depends_on: []

## Goal

Register a `gitea`-type Coder External Auth Provider on the DEV coder server
(coder.dev.scifi.farm) pointing at the dev Forgejo (git.scifi.farm), and enable
at-rest encryption of Coder's external token storage — both as
`CODER_*`-env entries in the existing `coder-secrets` ExternalSecret, so the
whole SSO-issuer config lands via ArgoCD. Add the reloader pod annotation so a
coderd restart happens automatically when the secret first syncs.

Verified contract basis (replan research §B + docs fetched at tag v2.35.2,
2026-10-24): env provisioning `CODER_EXTERNAL_AUTH_0_ID/TYPE/CLIENT_ID/
CLIENT_SECRET/AUTH_URL/DISPLAY_NAME`; the provider ID is part of the callback
path the forge-side OAuth app must whitelist (`/external-auth/<ID>/callback`);
`giteaDefaults()` auto-derives REGEX/TokenURL/ValidateURL from the AUTH_URL
host, so NO explicit `_REGEX` is set; encryption flag has an env form
`CODER_EXTERNAL_TOKEN_ENCRYPTION_KEYS` (comma-separated base64 32-byte keys,
first key encrypts, rest decrypt-only).

## Notes for dev

- Until the user creates the two Bitwarden items and fills the UUIDs, the
  ExternalSecret's new entries cannot resolve: external-secrets then skips
  updating the target Secret — coderd keeps running on its last-synced
  content and simply has no provider yet. That inert window is the designed
  bootstrap order (items first, then ArgoCD sync, then reloader restart).
  Do NOT "fix" this by making the data entries optional.
- The `ea_*`/`token_encryption_keys` secretKey names are template-internal;
  the load-bearing strings are the seven env keys and their values.
- Follow the file's existing quoting for the `{{ \`{{ ... }}\` }}` v2-template
  escapes exactly — copy the CODER_OIDC_CLIENT_ID line's shape.
- Do not touch the forgejo-token / forgejo-token-canonical service templates,
  the coder-templates/** HCL (C06's file), or `services/gpu/prod/**` (C05).
- AUTH_URL carries the full authorize path (docs example shape); the
  derivation lives in coderd source (`giteaDefaults`) — trust it, do not add
  TOKEN_URL/VALIDATE_URL/REGEX keys.
