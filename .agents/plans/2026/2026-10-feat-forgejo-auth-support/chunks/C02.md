# C02: workspace-startup.sh — dual-host Forgejo auth + forgejo SSH known_hosts at 22222
size: M   wave: 1   depends_on: []

## Goal

One workspace authenticates to BOTH lab Forgejo instances over https git + the
`fj` CLI, driven by two independent optional env pairs, and pre-trusts the
forge's real SSH endpoint (`[host]:22222`) on both instances so `ssh://` clone
URLs stay non-interactive.

## Tasks

- [ ] In `containers/coder-workspace/workspace-startup.sh`, factor the existing
  Forgejo block into a function `wire_forgejo` taking three arguments: the
  token value, the **name** of the env var holding it (the credential helper
  must keep echoing `$<NAME>` for at-use-time expansion — nothing written to
  disk), and the host-or-URL. Body = today's behavior: strip scheme/path to a
  bare host, `git config --global credential.https://<host>.helper`, then
  `fj auth add-token --host "https://<host>" "<token>"` with the same
  log-not-fatal error handling.
- [ ] Call it twice, each behind its own `[ -n ... ] && [ -n ... ]` guard:
  `(FORGEJO_TOKEN, FORGEJO_TOKEN, FORGEJO_HOST)` — names and behavior exactly
  as today — and `(FORGEJO_TOKEN_CANONICAL, FORGEJO_TOKEN_CANONICAL,
  FORGEJO_HOST_CANONICAL)` — new. No env for a pair ⇒ no action (preserve the
  documented optional contract).
- [ ] known_hosts loop: scan the lab forges at their forgejo SSH port —
  `ssh-keyscan -p 22222 git.scifi.farm` and `ssh-keyscan -p 22222
  git.spencerslab.com`, entries landing as `[git.scifi.farm]:22222` /
  `[git.spencerslab.com]:22222` (ssh-keyscan's native form for non-default
  ports; matches the permanent `ssh://git@<host>:22222/...` URL shape from the
  forgejo-ssh sibling). Keep `github.com` at the default port. Keep the
  existing properties: skip-if-present, empty-output-is-warn, unreachable-is-
  warn-not-fatal. Drop the old port-22 `git.scifi.farm` scan (it pins the
  NODE's sshd key, not forgejo's).
- [ ] SSH-key registration banner: list the Forgejo hosts first — canonical
  (`git.spencerslab.com`) and dev (`git.scifi.farm`) → Settings → SSH/GPG Keys
  — then GitHub, as today.
- [ ] Keep the script POSIX `sh`: `set -eu` style, no bashisms, works under
  dash. Update the top-of-file comment only where the behavior claims change
  ("Token git auth … FORGEJO_TOKEN + FORGEJO_HOST" now covers the second pair).

2. `bash tests/coder-workspace/startup-script.sh` => exit 0 (extended env

## Notes for dev

- Order inside `wire_forgejo`: git config first, then `fj` (a Forgejo API
  outage must not cost the user their working https push path — today's
  failure semantics, keep them).
- `fj` stores tokens per host in its own store; seeding two hosts is additive
  (v0.7.0 `auth add-token --host`).
- The dev instance may be unreachable from a dev workspace pod's keyscan at
  first boot — that is exactly why scan failures stay warn-only.
- Do not rename `FORGEJO_TOKEN`/`FORGEJO_HOST`: they are the established
  contract dev-git-auth.sh c6 checks; the new names are additive only.
- C03 emits these env names from the template; keep the spelling verbatim.
