# C02: Quiet-by-default / DEBUG-gated output (evidence-driven; errexit untouched)
size: M   wave: 4   depends_on: [C03, C04]

## Goal
Quiet the normal runs per the LOGSPAM.md ranking (OQ1's evidence-driven
redirect) and make `DEBUG=true` the single verbose switch, without touching
errexit semantics: `set -euo pipefail` stays at all 43 run blocks + 3 scripts
(D2's law — the redirect does not endorse gating `set -e`). The gate set, by
evidence rank: (a) the build-charts git-fetch ref enumeration + progress block
(~976 ln/fan-push — the biggest "ours" source), (b) the `helm dependency
update` / `repo add` chatter (~700 ln across the legs — output capture with
one-line summaries), (c) the `cr` package/upload/index echo (~250 ln — output
capture with one-line summaries), (d) the heavy diag dumps in build-containers +
builder-bootstrap (the 72-ln release legs — the smallest target), (e) the
renovate `LOG_LEVEL` (default STAYS `info` per OQ7 — the scout's `warn`
recommendation is overruled; `DEBUG=true` raises it to `debug`). The cheap
single-line diag echoes (`ROLE` / `event` / `run`, `renovate --version`) stay
ungated (OQ8). The detection endpoint lines stay as designed. The act-runner
platform noise (~21% of the biggest job + the checkout/cleanup blocks) is NOT
gateable from workflow YAML — out of scope, recorded in the review notes.

## Notes for dev
- The guard spelling is the inline var reference: `if [ "${{ vars.DEBUG }}" =
  "true" ]; then … fi` — an unset repo variable renders empty, so unset → false
  holds with no extra shell default.
- Mechanism findings (source-verified + empirically verified, record in the
  review notes): `actions/checkout@v7`'s fetch args are `--no-tags --prune
  --no-recurse-submodules` + `--progress` only when `show-progress` (the input
  default is true) — there is no `--quiet` / refspec input; in a non-tty
  context a `git fetch` WITHOUT `--progress` still emits the per-ref summary
  (only the `remote:` progress lines drop), and `git fetch -q` is fully silent.
  Hence: `show-progress: false` removes the progress block; the checkouts'
  per-ref summary lines are a documented residual; the two explicit
  `git fetch --tags` calls gate fully.
- The (b) capture wraps C04's extracted `bash scripts/forgejo-helm-repo-add.sh`
  invocation (one per leg) — the script file is untouched by this chunk; the
  (c) capture wraps C03's scoped package step — that step shape is untouched,
  only its output is redirected. This is why C02 runs wave 4 (DECISIONS D6).
- Do not gate the detection endpoint lines (the designed "green nothing-built
  reads differently" doctrine) nor the one-line context echoes (OQ8).
- `renovate.yaml` env is a job-level block on a container job: the expression
  lives in the value, no new env key.
- The act-runner platform noise (the `##[]` / `[command]` / `##[endgroup]`
  markers, the Complete-job cleanup blocks, the checkout-action internals beyond
  the progress lines, registry-login warnings) is not gateable from workflow
  YAML — out of scope; name it in the review notes.
