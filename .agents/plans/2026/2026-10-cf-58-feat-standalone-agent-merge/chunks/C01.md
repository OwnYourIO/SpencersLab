- [ ] Content sections (wording is dev's, the contracts are fixed):
  - **Applies to**: the `-pr` variants only (`agent-coord-pr`, `agent-board-coord-pr`, `agent-dev-pr`, standalone `dev-pr`); a `-local` or plain-alias agent that loads it has drifted — it must stop, not push.
  - **Push rules**: feature/ticket branch only, and only when the run's mandate is remote build/test (the `-pr` invocation is the standing user request for the branch push — cite AGENTS.md Hard rules: never `main`, never a refspec that updates `main`, never force-push, never self-remediate an accidental push, merge-to-main stays human-owned).
  - **What a push triggers here**: `.github/workflows/aislop.yaml` runs `aislop ci --changes` on the PR (score floor + no error findings on touched files); `docker-build.yaml`/`release.yaml` fire on merge to main — so a push is build+test, not deploy; ArgoCD syncs only after the user merges.
  - **PR creation**: `gh pr create` when `gh` is authenticated, else hand the user the compare URL (`https://github.com/ownyourio/SpencersLab/compare/main...<branch>`) — never claim a PR exists that was not created.
  - **Verify after push**: confirm the remote branch exists (`git ls-remote origin <branch>`) and report commit range + CI expectation in the RESULT/card comment; a failed push is reported, never retried with force.
  - **Deploy stage hook**: when a Lifecycle `Deploy` check drives the push (C05), the push/PR is the Deploy action; `-local` variants answer Deploy with "ready — commits local" and stop.
