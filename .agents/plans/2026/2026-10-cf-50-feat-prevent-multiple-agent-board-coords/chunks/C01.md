# C01: Session-side gate — scripts/agent-board-coord-gate.sh
size: S   wave: 1   depends_on: []

## Goal
A deterministic, fixture-testable script that evaluates ONLY the session operand of the D11 gate: "is another `agent-board-coord` session working right now?" — answering `GATE: RUN` (none) / `GATE: LIVE` (found, detail follows) / `GATE: SKIP` (detection failed, fail-closed). Interface contract = D17 (three states, flags, exit codes), D2/D3 (liveness rule + self-exclusion), threshold default 15 min (D9). No WeKan access of any kind (D16 — the board operand is the agent's LIVE-branch turn, C02).

Prefer cheap project scoping (`projectID`/`location.directory` vs repo root); agent-name filter is the documented minimum (D11: interactive launches SHOULD count).
  - [ ] Contract v3 output (D17), first line machine-readable:

  - [ ] Never echo credential material or raw API bodies on error paths (sanitized one-line reasons).

## Acceptance criteria
1. Fixture matrix (each flips by exactly one fixture/flag change; all rows assert first-line marker AND exit code):
   - (a) no coord sessions at all → `GATE: RUN` / 0.
   - (b) coord stale (updated older than threshold, created older than grace), fresh NON-coord sessions present → `GATE: RUN` / 0.
   - (c) coord fresh (own updated within threshold) → `GATE: LIVE <id>` / 2, naming the id and title.
   - (d) coord own-stale + child (`parentID`) fresh → `GATE: LIVE` / 2 (child rule holds; basis noted in detail lines as child-fresh).
   - (e) fresh coord + `--self <that-id>` → `GATE: RUN` / 0.
   - (f) coord created inside `--grace` (self-equivalent), fresh → `GATE: RUN` / 0.
   - (g) same fixture, `--threshold` above and below the activity age → `GATE: LIVE` vs `GATE: RUN` (tunability proof).
   - (h) two live coords → `GATE: LIVE` naming both (first line = lowest-age one; id list in details).
   - (i) malformed JSON / empty file / unreadable path / non-envelope (`{"nope":1}`, bare array) → `GATE: SKIP <reason>` / 1 for each.
2. `--help` documents every flag, all three markers, the three exit codes, the `GATE_NOW_MS` fixture-only rule, and the fail-closed policy; D17's deleted-surface flags are NOT advertised.
3. Probe items each have a one-line verdict with captured evidence in the RESULT (pagination handled-or-unneeded; active-endpoint verdict; CLI-servers-scheduled-runs confirmed).
4. Live smoke: bare run against the real server exits 0/1/2 with a valid first-line marker when `opencode api` is reachable; skip-with-warning otherwise (intake-ticket t14 precedent). Manual positive control (Review notes, not CI): while a fresh board-coord tree exists (this ticket's coord is the lab), the bare script returns `GATE: LIVE <coord-id>`; a review-run recorded output proves it.
5. `bash -n` clean; shellcheck-clean when present (skip-with-warning convention); `aislop ci --changes` 0 errors on touched files; no `curl`/`wget` invocation anywhere in the script (D16 static pin — grep).
