## Acceptance criteria
1. File parses as YAML; triggers exactly schedule + workflow_dispatch; cron is the quoted
   5-field string `17 6 * * *`; no `push`.
2. Exactly one job `renovate`, guarded `if: vars.ROLE == 'dev'`; no `forgejo.server_url`
   anywhere; `vars.ROLE` occurs only in the `if:` and the diag echo.
3. `container.image` matches `^ghcr\.io/renovatebot/renovate:\d+\.\d+\.\d+$` (no
   `latest`, no rollups) and its line carries no `# renovate:` annotation line above it.
4. env key set exactly the six (plan §Key design decisions), values verbatim; each
   `secrets.RENOVATE_*` reference boundary-anchored exactly-once file-wide; no
   `GITHUB_`/`FORGEJO_`-prefixed secret/var refs (house reserved-prefix rule); no literal
   forge/repo hosts (`git.scifi.farm`, `git.spencerslab.com`, `github.com/`) — `ghcr.io`
   allowed only as the image registry.
5. Zero `uses:` steps; every `run:` begins `set -euo pipefail`; `runs-on: ubuntu-24.04`
   ∈ the five advertised labels.
6. Ruling consistency (replaces round-1's leg-pairing AC): `renovate.json` parsed in-suite
   shows NO packageRule with `matchManagers` containing `github-actions` and no leg text
   mentioning `renovatebot` — i.e. exactly ONE manager (the native github-actions one,
   whose dist-verified default patterns match `.forgejo/workflows/*.yaml`) claims this
   file's pins. Double-match guard.
7. New suite PASS + plan Commands §4 baseline-fingerprint recheck (main-sync/dockerfile-
   pins/system-upgrade green; the two pre-existing REDs unchanged in kind AND count);
   config-validator still green (C02 changes no config, AC6 re-pins it).
8. Live execution is NOT an AC: the dev instance takes no jobs yet (R1/UA4) — first-fire

## Notes for dev

  interleaves the cron line and `workflow_dispatch`); t2 binds the real shape.
- The container job checks out nothing and runs no setup actions — Renovate clones/pushes

  follow-up entrypoint adjustment, not a plan change here.

  only).
