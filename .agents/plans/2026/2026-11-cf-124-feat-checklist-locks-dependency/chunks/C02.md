# C02 — Lock doctrine: a continuation prompt answers the lock-lost question; Executing membership alone means "locked"

size: **M** · wave 1 · depends_on: none · model: `gpu-ai/qwen3.8-flash-next-strata-q4` (both tiers)

## Goal

Write the owner's two assumptions (card ask E, ruled OQ10/OQ11 → D23) into the lock doctrine and
the plugin's stop text: **a later user continuation prompt is what ANSWERS the sanctioned
lock-lost question**, and **a card's membership in `Executing` is itself the evidence that
another run holds it** — with the engine semantics (refusal, no self-reclaim, card-id takeover
key, `after_reap` tagging, no extend verb) left exactly as shipped.

## Ground truth the text must not overstate

- `pipeline_claim` has no extend/renew verb and self-reclaim is refused at every call site; a fresh foreign holder answers `reason:"occupied"` and names the holders; a card-id claim backed by a `.reaped/` record is tagged `after_reap` — "evidence, not a new permission" (`.opencode/plugin/pipeline-locks/index.ts:4-27`, `:113-183`). A continuation prompt therefore **answers a question**, it does not **extend a lease** — and the text must not promise what the engine cannot do.
- `LOCK_LOST_STOP` (`index.ts:178`) is a single constant whose text the engine suite pins; the stop doctrine lives in `boards` L160 (`Human stops (D20/D21)`).
- OQ10 = "Doctrine + stop text" (the planner's recommendation, adopted); OQ11 = "Documented inference".
