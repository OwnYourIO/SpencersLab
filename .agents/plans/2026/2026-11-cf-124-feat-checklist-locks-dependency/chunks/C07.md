# C07 — Backfill engine + runbook: `scripts/board-checklist-backfill.py` (additive, in-place, dry-run default, owner-run `--apply`)

size: **M** · wave 2 · depends_on: **C01**, **C03** · model: `gpu-ai/qwen3.8-flash-next-strata-q4` (both tiers)

## Goal

Ship the machinery that moves the ~90 live cards (everything non-archived, off the **In Process**
swimlane) onto the generation **C01** defined — as an **offline engine plus a runbook the owner
executes** (card ask C, ruled OQ6 → D19). No agent runs the mutation in this ticket; the engine's
`--apply` leg is the owner's. The runbook also states the OQ6/OQ7 boundary in **C03**'s landed words
so "bulk values come from the owner" and "an agent may stamp its own card" are never read as the same
permission.

## Ground truth the engine must respect

- **No board-level checklist entity exists** — one checklist per card, so this is a per-card loop (RESEARCH).
- `POST /api/boards/:b/cards/:c/checklists/:cl/items` accepts an **explicit `sort`** (#6544) and consumers render `sort`-ascending — negative sorts are the sanctioned way to append without disturbing existing items.
- `DELETE /api/boards/:b/checklists/:cl` **cascades every item** (#6816) — delete-and-re-add would destroy all ticks on ~76 legacy cards. The engine must therefore **never** delete a checklist or an item, and must not offer a flag that does.
- Checklist **rename** and item **sort** are not in the MCP surface, so the apply leg is raw REST: `Authorization: Bearer $WEKAN_TOKEN`, JSON bodies, server needs `WITH_API=true`, and **HTTP 200 does not mean success** — parse the body (`skills/wekan-api/references/rest-api-overview.md:25-33`).
- Item vocabulary is **C01**'s landed text: import `CHECKLIST_SPEC`/`LIFECYCLE_ITEMS` from `scripts/provision-board.py` rather than restating the lists (the copied-not-retyped law, D9).
- Live shapes to handle: ~76 cards carry a **legacy 14-item HITL** + a legacy `Research` checklist; **10** are already current-generation; **#65/#66** carry duplicated checklist sets; **#57/#71** have no Lifecycle checklist. Reports, not repairs, on the anomalies.
- `Priority` is a board **NUMBER** field: its write is `setCustomField`-style REST with an **int** (`5`), and the value is a no-op for routing (`null` ≡ default class) — the boundary text lives in C03's `boards` text.
- The live createCard rule still reports provision drift until the owner imports the artifact — the runbook says so (the engine reporting drift is the engine **working**), and no sentence in this chunk may leave an upstream-filing ask standing (D18).

## Tasks

1. **`scripts/board-checklist-backfill.py`** (new, stdlib-only, mirrors `scripts/provision-board.py`'s house style: idempotent plan, `--dry-run` as the DEFAULT, explicit `--apply` **and** `--yes` both required to write):
   - **Input**: `--board <export.json>` (a board export with cards, their checklists/items and `custom_fields`), plus `--out <plan.json>`; the plan is deterministic and diffable (sorted by card number, stable ordering).
   - **Scope filter**: non-archived cards whose list is **not** on the In Process swimlane; `--include-list/--exclude-list` overrides; `Cancelled` excluded by default (never a repair target); an explicit `--card <id>` repeatable narrow-target escape hatch.
   - **Target generation** derived from `provision-board.py`'s `CHECKLIST_SPEC` (imported, not restated): Lifecycle + HITL at 13 items in list order, Services at 19, `Type`/`Model(s)` untouched, the legacy `Research` checklist left in place (it is a documented consumer, not junk).
   - **Additive legs**, all with explicit negative `sort`: (a) **missing item** in an existing checklist of the right title → insert; (b) **existing item** with the same title (whitespace/case-normalized match) → **no-op**, tick state never touched; (c) checklist **absent** on a card that should carry it → create the checklist, then add items in list order; (d) duplicated checklist sets → **report only**; (e) card with **no** Lifecycle at all → report only (the engine creates one only with the explicit `--create-missing-lifecycle` flag, default off, so #57/#71 stay a human call).
   - **`--priority-default 5` leg (default off)**: emits `Priority` writes **only** for cards where the field is unset/`null`, numeric, never overwriting an explicit value; the header of that leg's output restates that this is the **owner-run bulk** path (OQ6) and that an agent's own per-card stamp is a different permission (OQ7/D20).
   - **Hard guarantees, encoded not promised**: the module contains **no** `DELETE` request anywhere (and no `--force-replace`/`--rebuild` flag exists); every write carries the item title + explicit `sort`; every planned action records its card `_id`, checklist `_id`, title, sort and reason; the dry run prints the plan and performs **zero** network calls; `--apply` refuses to run without a `--backup-confirmed` flag naming the backup the owner took; responses are parsed for embedded errors and any failure aborts the run with the completed-action log flushed.
   - **Reports** (stdout + `--report <path>`): per-legacy-generation counts, per-leg counts, the anomaly cards (#57/#71/#65/#66 class), cards whose Lifecycle carries ticks the plan preserves, and a closing reminder that the provision dry-run keeps reporting rule drift until the owner imports C01's artifact.

## Dev notes

- Import the vocabulary (`from importlib import import_module; m = import_module("provision-board")` via `importlib.util.spec_from_file_location` for the dashed filename) — do not paste lists; the copied-not-retyped law is what keeps the engine honest when the generation moves again.
- Sorts: existing items keep their stored sort; new items get a strictly-negative descending sequence so they land after the existing set in ascending order without renumbering anything. Prove the ordering in b2 rather than trusting the API's default.
- Never write `isFinished`. A card's ticks are the human record; a backfill that re-ticks would silently re-approve decisions (this is the reason there is no tick leg — DECISIONS "Deferred").
- Fail loud on partial application: log every attempted action before the call, flush the log on abort, and make the plan resumable by construction (the next dry run must show the remainder, which is what idempotency buys).
- No live board calls in CI, ever — the suite is offline by design; the runbook is the only place a URL/token appears, and it uses env names, never values.
