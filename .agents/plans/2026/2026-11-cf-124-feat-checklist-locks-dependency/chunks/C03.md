## Goal

Revoke the shipped doctrine that the `Priority` custom field is **input-only and NEVER written
back by agents** (owner ruling OQ7 → D20), and state the new permission with its two boundaries
so the lift cannot be over-read: an agent MAY write `Priority` on **its own claimed card** and on
**cards it creates**; **bulk** board-data mutation and every other card still need explicit owner
direction — which is why this ticket's ~90-card value leg stays the owner-run `--apply` run (OQ6/D19,
**C07**). `null` ≡ the default class stays on the record so nobody reads `5` as an urgency change.
