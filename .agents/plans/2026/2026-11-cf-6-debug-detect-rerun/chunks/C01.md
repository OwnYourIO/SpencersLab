## Goal

Switch containers-build PUSH detection from payload-`before` to the last-built
marker (`refs/heads/ci/containers-built` on the Forgejo repo), advance the marker
only after a fully-green push build, make a verified-empty `marker..sha` an
informational exit while every bootstrap/PR posture stays byte-identical — and
land the doc trio + suite pins in the same commit (x5 parity law).

## Acceptance criteria

1. Push arm base chain = marker → all-zero tip-only → before, with the A5
   empty-before `die` running first regardless of marker state (d12 posture
   preserved).
2. Marker missing ⇒ the run's answers/echoes/warnings are byte-equivalent to
   today's shipped behavior (d18 + all existing d/t legs green).
3. Marker set, `marker..sha` empty (incl. marker==sha) ⇒ `[]`, exit 0, ONE plain
   info line, NO `::warning::` (t14 new scenario).
4. Marker set, non-empty ⇒ marker..sha set wins over before..sha whenever they
   differ (d16); stderr names `base=marker`.
5. Unreachable/garbage marker value reaching detect ⇒ git 128, loud, no JSON
   (d19); the YAML resolver reddens with an owner-naming message BEFORE detect
   for the orphan shape (t17).
6. `advance-marker` exists, fires only on a push whose `build-release` job
   SUCCEEDED, pushes `HEAD:refs/heads/ci/containers-built` with no secret
   reference and no force flag; a non-FF advance against a scratch bare remote
   executes red (t16 static + t17 executed).
7. Partial failure ⇒ no advance (needs-gated), marker put ⇒ re-run re-diffs the
   same marker..sha (documented; covered by 6's refusal machinery + d16).
8. PR arm and dispatch arm: byte-identical outputs on their shipped fixtures
   (d14/d15, d1-d8, t14 existing scenarios untouched in expectation).
9. Docs trio carries `marker..sha` + the fallback + advance-on-success law;
   x5's new MARKERS tuple passes on all three; rulesync twin committed together;
   no BANNED phrase introduced (x5/ci-surface green).
10. Suite: `bash tests/services/forgejo-containers-build.sh` = 47 ok / 0 red on
