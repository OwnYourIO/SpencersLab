Land the entire in-repo surface of the reworked cf-119 main-sync design: one Forgejo Actions
workflow with two jobs, each a plain non-force push of `main` — `push-gh` (→ GitHub

`vars.PUSH_URL_*`, tokens from `secrets.PUSH_TOKEN_*`, no URL literals in the file — plus the
offline bash contract suite that pins those invariants with no network. The suite is written
red-first INSIDE this chunk (no separate test session — Test Writing unchecked; P-2 "fine as

## Notes for dev
- Forgejo (not GitHub) semantics: the running instances are 15.0.10 (v15.0 LTS line). The v15.0
  reference's Availability table lists `vars` among the contexts accessible in a job-level
  `if:` — `if: vars.ROLE == 'prod'` is the verified guard shape (plan Authority table).
  Job-level `permissions:` and `continue-on-error` are ignored by Forgejo — don't write them.
- `vars.ROLE` unset renders `''` → the guard is false → nothing fires (fail-safe; OQ-6).
  Expression string comparisons are case-insensitive on this line, so `prod`/`Prod` both match —
  the instance-side value is set to lowercase `prod`/`dev` anyway (UA3).
- `runs-on`: choose one of the five runner labels (`ubuntu-latest`, `ubuntu-24.04`,
  `ubuntu-22.04`, `docker`, `node22`) — `ubuntu-24.04` suggested (explicit over `latest`);
  t7 pins the set, not the member. `ubuntu-26.04` (GitHub-hosted style) routes to nothing.
- The automatic `FORGEJO_TOKEN` is same-repo-only — it serves the checkouts only, and never an
  external push (both `push-gh` and `push-dev` are external; each carries `PUSH_TOKEN_*`).
- Token handling: URL-embedded credentials in the push commands only (step `env` →
  `${PUSH_TOKEN}`); no `git config` credential writes, no tokens in the checkout step. The
  dev-leg credential slot form (`x-access-token:` vs a username) is dev's choice — first-fire
  evidence (V1/V3) settles it if the dev leg 401s.
- Step order within each job: diag → single push step (one destination per job — the rework
  split the old two-step `push-main` into two parallel jobs).
- The workflow will be inert until the owner sets the instance-side config (UA3: `ROLE`,
  `PUSH_URL_*`, `PUSH_TOKEN_*`) AND bootstraps the merged PR onto infra `main` (UA5) — nothing
  in this chunk goes live.
