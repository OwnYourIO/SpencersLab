# C01: `main-sync.yaml` workflow + offline contract suite
size: M   wave: 1   depends_on: []

## Goal

Land the entire in-repo surface of the cf-119 main-sync design: one Forgejo Actions workflow
with two instance-guarded jobs — `push-main` (infra instance only: non-force push of `main` to
GitHub `OwnYourIO/SpencersLab` and to `git.scifi.farm`, failing the job if either push fails)
and `backup-proxy-merge` (dev instance only: merge `main` into `backup-proxy`, creating the
branch from `main` if absent, on the automatic `FORGEJO_TOKEN`, no secrets) — plus the offline
bash contract suite that pins the workflow's invariants (triggers, guards, no-force, targets,
secrets, runner labels) with no network. The suite is written red-first INSIDE this chunk
(no separate test session — Test Writing unchecked; plan P-2 / DECISIONS #4), then the
workflow is written to make it green.

## Notes for dev
- pyyaml (YAML 1.1) parses the top-level `on:` key as boolean `True` — t2 must read the trigger
  block as `doc.get(True) or doc.get('on')`; asserting on the string key `'on'` reddens a
  correct file (plan suite spec, t2 note).
- Forgejo (not GitHub) semantics: the running instances are 15.0.10 (v15.0 LTS line).
  `startsWith` in job `if:` and `forgejo.server_url` are confirmed for that line (plan
  Authority table). Job-level `permissions:` and `continue-on-error` are ignored by Forgejo —
  don't write them.
- `runs-on`: choose one of the five runner labels (`ubuntu-latest`, `ubuntu-24.04`,
  `ubuntu-22.04`, `docker`, `node22`) — `ubuntu-24.04` suggested (explicit over `latest`);
  t7 pins the set, not the member. `ubuntu-26.04` (GitHub-hosted style) routes to nothing.
- The automatic `FORGEJO_TOKEN` is same-repo-only — it may serve the checkouts and Job 2's
  branch push, and never Job 1's external pushes (EXPLORE §2).
- Token handling: URL-embedded credentials in the push commands only; no `git config`
  credential writes, no tokens in the checkout step.
- Step order in `push-main`: diag → GitHub push → dev push (GitHub lands first during the
  expected-red window while the dev instance is down).
- The workflow will be inert until the owner bootstraps it onto infra `main` (plan UA5) and
  sets the two infra Actions secrets (UA3) — nothing in this chunk goes live.
- Comments: why-only, no ticket/round narration (aislop scans both new files on the PR).
