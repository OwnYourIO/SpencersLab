# C02: wekan-mcp container — username+password login support
size: M   wave: 1   depends_on: []

## Goal
Extend `containers/wekan-mcp` so the server can mint its WeKan bearer token at
startup from `WEKAN_USERNAME`+`WEKAN_PASSWORD` (WeKan `POST /users/login`,
JSON body), while still accepting `WEKAN_TOKEN` directly. No GPU behavior
changes: gpu continues to inject only `WEKAN_TOKEN`.

## Tasks
- [ ] `containers/wekan-mcp/wekan_mcp/wekan.py` — `WekanClient.__init__`
      credential resolution, in priority order:
      1. `WEKAN_TOKEN` present → current behavior verbatim (header baked, no login).
      2. else `WEKAN_USERNAME` + `WEKAN_PASSWORD` present → call `login()`
         before returning: `POST /users/login` with JSON `{"username": ...,
         "password": ...}` (JSON, never form data — documented-broken), using
         the unauthenticated path so the 401-retry logic below can't recurse;
         take `token` from the response (`id`/`tokenExpires` also returned per
         the `wekan-api` skill), set the `Authorization: Bearer <token>` header
         on the shared httpx client, and remember the credentials for refresh.
         On login failure raise `WekanError` without echoing the password or
         the returned token into the message (follow `_sanitize_error` rules).
      3. else → raise the existing error, message extended to name both auth
         options.
- [ ] `WekanClient.request` — refresh-on-401: when a request gets 401 AND
      credentials were used for minting (case 2, or case 1 with username/
      password also provided), re-login once and retry the original request;
      a second 401 raises the existing 401 error. Guard against infinite retry
      (single retry per request; login endpoint itself never auto-retries).
      Note: WeKan old tokens stay valid after re-login (issue #1437), so refresh
      is best-effort resilience, not rotation.
- [ ] Keep `WEKAN_MCP_READ_ONLY` gating untouched (server.py) — dev-boards is
      the admin-tier use case; login support is orthogonal.
- [ ] Update the stale docstring in `wekan.py` ("We skip login entirely and
      reuse a pre-obtained bearer token" — no longer universally true) and
      `README.md` + Dockerfile header comment env lists (now
      `WEKAN_BASE_URL` + (`WEKAN_TOKEN` or `WEKAN_USERNAME`+`WEKAN_PASSWORD`)).
- [ ] No `pyproject.toml` version bump (cosmetic only; CI owns tags), no
      Dockerfile base/entrypoint changes, no new dependencies (httpx exists).

## Acceptance criteria
1. `python3 -m py_compile containers/wekan-mcp/wekan_mcp/*.py` passes.
2. `bash tests/containers/wekan-mcp-login.sh` passes (mock WeKan from stdlib
   `http.server`; imports `wekan_mcp.wekan` only — no fastmcp needed; httpx
   available in the environment or installed into a /tmp/opencode venv by the
   script's own fallback, mirroring the helm-download fallback style).
3. `docker build containers/wekan-mcp -t wekan-mcp:contract` succeeds (buildx
   not required; plain `docker build`; docker 29.x is available in the run
   environment).
4. Backward compatibility: with `WEKAN_TOKEN` set and username/password absent,
   the code path is behaviorally identical to today (no login POST).
5. Grep: no plaintext credential logged — `WEKAN_PASSWORD`, the minted token,
   and login response bodies must never appear in log/format strings
   (verify by reading the diff for f-strings containing those values).

## Tests (agent-test writes, review runs)
Contract script `tests/containers/wekan-mcp-login.sh` — stdlib mock server +
python heredocs, five cases (run from repo root):
- t1 [AC1]: `python3 -m py_compile` on every `wekan_mcp/*.py`.
- t2 [mint]: env BASE_URL→mock, USERNAME/PASSWORD set, no TOKEN → `WekanClient().validate()`
  returns `_id`; mock saw exactly one `POST /users/login` with JSON
  content-type and correct body; `GET /api/user` carried the minted bearer.
- t3 [precedence]: TOKEN + USERNAME/PASSWORD all set → `validate()` succeeds,
  mock login-endpoint hit count == 0, Authorization == fixed TOKEN.
- t4 [refresh-on-401]: mock rejects initial token once, serves new token on
  login → request succeeds after exactly one re-login; negative variant: mock
  401s everything → `WekanError` raised, login hit count stays bounded (<=2).
- t5 [no-creds]: neither auth pair set → `WekanError` message mentions
  `WEKAN_TOKEN` (and the new env alternatives). Covers AC5 partially.
- t6 [AC3]: `docker build` exit 0 (skip-with-warning if no docker binary, same
  convention as helm-download fallback in `tests/services/dev-forgejo-runner.sh`).

## Notes for dev
- Login endpoint shape (verified against the `wekan-api` skill): response
  contains `id`, `token`, `tokenExpires`; 401-with-JSON on bad creds. Treat
  missing `token` in the response as a login failure, not a crash.
- `httpx.Client` headers are mutable (`client.headers["Authorization"] = ...`)
  — simplest way to apply the minted token without reconstructing the client.
- The pod is `readOnlyRootFilesystem`-free today (no volume mounts on gpu's
  wekan entries); don't add persistence.
- CI builds PRs without pushing (`docker-build.yaml` `push:` gate) — the local
  `docker build` test is the pre-merge proof; `:main` appears after the user
  merges.
