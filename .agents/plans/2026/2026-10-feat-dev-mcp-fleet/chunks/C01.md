# C01: searxng backend on dev
size: S   wave: 1   depends_on: []

## Goal
Deploy `charts/searxng` on the dev cluster as a dev-local JSON-search backend
(for the later `searxng` MCP entry AND a LAN host `searxng.scifi.farm` — user
decision 2026-10-24, direct dev-traefik ingress, no proxy-remote). Mirrors the
gpu deployment: internal chart entry in `charts:` + chart-level `bitwardenIds`
fed via the top-level `searxng:` values slice from custom-values.

## Tasks
- [ ] `services/dev/prod/values.yaml`: add under `charts:` (internal-charts
      section, next to the other no-version entries):
      ```yaml
      searxng:
        namespace: default
        ServerSideApply: "false"
      ```
      (gpu pattern: `services/gpu/prod/values.yaml:50-52`.)
- [ ] `custom-values/dev/prod-values.yaml`: add a top-level `searxng:` slice —
      ```yaml
      searxng:
        bitwardenIds:
          # dev-searxng LOGIN item (password = secret_key) — NEW ITEM, user
          # action (plan User action 2). Placeholder until pasted.
          searxng: OVERRIDE_NEEDED
      ```
      This slice is what base's `appset-charts.yaml` generator extracts into
      the `dev-searxng` Application (values flow verified in
      `skills/helm-chart-creation/references/values-and-appset.md` "Cluster-wide
      charts" + live gpu file `custom-values/gpu/prod-values.yaml:60-62`).
- [ ] `services/dev/prod/values.yaml`: add `ingress.subdomains.searxng` —
      user decision 2026-10-24 (approval round): `searxng.scifi.farm` reachable
      from the local network, NOT routed via proxy-remote. The plain
      key-derived form does exactly that: `generic-ingress.yaml` renders
      `{{name}}.{{domain}}` (no `clusterBase`, no `serviceName`) → host
      `searxng.scifi.farm`, TLS `wildcard-cert`, no external-dns
      proxy-remote target (live precedent: `git`, `research` entries):
      ```yaml
      searxng:
        service: dev-searxng
        port: 8080
      ```
      (gpu's entry also sets `serviceName: searxng` — omit it: on dev the
      key-derived top-level host already IS `searxng.scifi.farm`.)

## Acceptance criteria
1. `helm lint charts/searxng` passes (run from the /tmp/opencode copy after
   `helm dependency update`; worktree untouched).
2. `helm template searxng charts/searxng --set domain=test.example.com --set
   bitwardenIds.searxng=test-uuid` renders: ExternalSecret `searxng` with
   `remoteRef.key: test-uuid`, `property: password`, `storeRef: bitwarden-login`;
   target Secret data contains `settings.yml` with `formats: [html, json]`;
   Service on port 8080; PVC claim `searxng`; and `grep OVERRIDE_` on the output
   is empty.
3. `services/dev/prod/values.yaml` has `charts.searxng` with `namespace: default`
   and `ServerSideApply: "false"` (yaml-parse assert, not just grep).
4. `custom-values/dev/prod-values.yaml` has top-level `searxng.bitwardenIds.searxng`
   (key presence + placeholder documented; value not asserted — UUID is the
   user's to paste).
5. `services/dev/prod/values.yaml` `ingress.subdomains.searxng` exists with
   `service: dev-searxng`, `port: 8080`, and WITHOUT `clusterBase`/`serviceName`
   (so `generic-ingress.yaml` renders the LAN host `searxng.<domain>` directly,
   not proxied) — user decision 2026-10-24.

## Notes for dev
- The searxng chart ships its own bitwardenIds sentinel in its values.yaml —
  do not edit the chart; the UUID flows only via the custom-values slice.
- `SEARXNG_BASE_URL` renders `https://` empty (app-template top-level-values
  gotcha, documented in helm-chart-creation skill). Known-cosmetic; out of scope.
- Pod will not become Ready until the user creates the dev LOGIN item —
  expected interim state, not a failure of this chunk.
