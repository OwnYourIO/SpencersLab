## Notes for dev
- The whole loop file body (comments included) becomes the OpenChamber task
  prompt — keep comments factual and short; the prompt sentence is the last
  plain-text block (D30 pattern).
- Two tasks can run concurrently (API :00, Local :30): the lease-lock surface
  already serializes card claims. Labeled cards split cleanly by provider.
  UNLABELED cards have one planned scheduled taker — the Local task — which
  blocks on the provider question at claim until the human answers
  (question-notify pushes it); the API task's walk never takes them, so only
  a MANUAL API run the user initiates hits the ask. Do not "fix" the blocking
  by guessing a provider.
- Do NOT flip `enabled:` to false on either file "to be safe" — the shipped
  posture is `enabled: true` with human-owned scheduler hygiene (main
  080c9878a precedent).
