- [ ] `pipeline-role-coord` SKILL.md — new step after the step-9 report:
      **work-complete cleanup** (batched-round refined shape). First decide
      whether the ticket's changes LANDED in main — CONTENT-based, never
      ancestor-clean (squash/merge-PR landings leave the branch history
      "awful" but the code in main; the ancestor test
      `git branch --merged main` is NOT the gate): take the paths the branch
      changed against its merge base
      (`git diff $(git merge-base main HEAD) HEAD --name-only`) and compare
      exactly those paths between the branch and main
      (`git diff main HEAD -- <paths>`); empty diff ⇒ landed (a landed PR
      counts). Then:
      - **Landed** → warm the origin destination, `session_move` to the run's
        origin checkout (STATE.json `kickoff.origin_dir`, captured at
        kickoff), `opencode worktree_remove` the ticket worktree, then delete
        the branch (a `-D`-equivalent is safe once the content is in main).
      - **NOT landed** → ask the user ONCE whether to delete branch +
        worktree — default KEEP (the branch may be wanted for a PR push);
        obey the answer, never force; the warm → `session_move` home still
        happens so the session ends in the main tree either way.
      The `-deploy` variant closes its OWN worktree at hand-back; this step
      owns the ticket run's surfaces.

## Notes for dev
- Do NOT reorder or reword the marker recipe itself — the archive PATCH is a
  NEW step after it (marker first, then archive), mirroring the read-merge-
  write mandate the marker already carries.
- `session_move` into an unwarmed destination bricks the session (kickoff
  warm lesson, pipeline-kickoff) — the cleanup step MUST warm first; cite
  that bullet, never restate the mechanics.
- Branch deletion follows the CONTENT landing check, never ancestry: a
  squash-merged ticket branch fails `git branch -d`/`--merged` while its
  code is safely in main — the changed-paths diff vs main is the gate. Only
  delete after that gate passes (or the user explicitly says so on the
  not-landed ask); record every outcome verbatim in RESULT.
- One commit; the six permission edits ride with the skill text they enable.
