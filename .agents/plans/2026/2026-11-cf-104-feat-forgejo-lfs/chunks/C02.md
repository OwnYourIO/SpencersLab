# C02: dev activation — LFS on the SeaweedFS gateway over the public endpoint
size: S   wave: 2   depends_on: [C01]

## Goal

Switch Git LFS on for the **dev** instance and point its object store at
`https://s3.spencerslab.com` (dev has no local gateway — EXPLORE §3.1). Everything
lands in `custom-values/dev/prod-values.yaml` under the existing `forgejo:` app
key, which is the designed place for per-instance differences (EXPLORE §1,
`charts/base/templates/appset-charts.yaml:32-36`).

## Tasks
- [ ] `custom-values/dev/prod-values.yaml`, `forgejo.bitwardenIds`: add
      `forgejo-s3: <UUID>` with a trailing comment naming the Bitwarden item
      (`forgejo-s3`) and the store mapping (username = access key id, password =
      secret access key). Real UUID from UA4 — `OVERRIDE_NEEDED` is forbidden for
      this key (plan D11: the credential `secretKeyRef` sits on the init
      container, so an unresolved ExternalSecret means the pod cannot start).
- [ ] `forgejo.forgejo.gitea.config.server`: add `LFS_START_SERVER: true`
      (Forgejo's default is `false`; the section already renders).
- [ ] `forgejo.forgejo.gitea.config.lfs`: add the three per-instance keys —
      `STORAGE_TYPE: minio`, `MINIO_ENDPOINT: s3.spencerslab.com` (bare host:
      minio-go builds `https://<host>` and Go defaults to 443 — verified in
      v7.0.99 `utils.go:109-128`), `MINIO_USE_SSL: true`.
- [ ] Touch nothing else in the file: the instance identity block
      (`APP_NAME`, `DOMAIN`, `ROOT_URL`, `admin.email`) and the other apps'
      slices stay byte-identical.
- [ ] Do **not** set `MINIO_BUCKET`, `MINIO_BUCKET_LOOKUP`,
      `MINIO_CHECKSUM_ALGORITHM` or `SERVE_DIRECT` here — C01 ships them once for
      both instances; repeating them here would fork the two instances silently.

   produces an `[lfs]` section equal to exactly:
   `MINIO_BUCKET=git-lfs`, `MINIO_BUCKET_LOOKUP=path`,
   `MINIO_CHECKSUM_ALGORITHM=default`, `MINIO_ENDPOINT=s3.spencerslab.com`,
   `MINIO_USE_SSL=true`, `SERVE_DIRECT=false`, `STORAGE_TYPE=minio`.
2. Same render's `[server]` section carries `LFS_START_SERVER=true` beside the
   existing `DOMAIN/ROOT_URL/SSH_PORT=22222` keys, and no `storage`/`attachment`/
   `picture` section appears (attachments stay on the PVC).
3. The rendered ExternalSecret `forgejo-s3-secret` reads the UUID from the
   custom-values file (no sentinel, no placeholder string).
4. `bitwardenIds.forgejo-s3` matches a UUID shape;
   `grep -rn OVERRIDE_NEEDED custom-values/dev` shows nothing for the forgejo
   slice (t8; the plan's deliberate exception to the interim-placeholder
   precedent).
5. Sentinel sweep unchanged: dev umbrella render `grep -c OVERRIDE_` == **1** (the
   pre-existing home-assistant wart) and the forgejo Application's values JSON
   contains no `OVERRIDE_*`.
6. dev's other custom-values slices and `services/dev/prod/values.yaml` are
   untouched (`git diff --stat` shows one file; no ingress/proxy change → the
   trio's proxy leg is legitimately untouched because `SERVE_DIRECT=false` means
   no client ever contacts the storage host).
7. `bash tests/services/infra-forgejo.sh` → exit 0 / 33 ok (regression; the dev
   parity legs there must survive the added keys).
8. `bash tests/services/forgejo-lfs.sh` → t5, t8, t9 green; t6 (infra) remains
   red until C03.

## Notes for dev
- The app-slice extraction step in the plan's Commands is what makes the merge
  visible: the Application receives the **contents** of the top-level `forgejo:`
  key, so `forgejo.forgejo.gitea.config.lfs` in the file = `gitea.config.lfs` in
  the chart. Wrapping the slice again renders nothing (proven during planning).
- Helm deep-merges maps and **replaces lists**: the `lfs` map merges with C01's
  keys, but `additionalConfigFromEnvs` must never be re-declared in
  custom-values — a partial list would drop the DB password leg.
- If the UUID is not in hand when this chunk runs, stop and report NEEDS_INFO —
  shipping a placeholder here is a production outage risk, not a cosmetic wart
  (D11 + risk list).
- Rollout truth to state in the RESULT: this chunk only changes GitOps input.
  Nothing is live until the user merges and ArgoCD syncs, and the plan's UA1–UA3
  + PF1 must already be done at that point.
