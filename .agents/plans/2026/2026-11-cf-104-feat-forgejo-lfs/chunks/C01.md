# C01: Chart plumbing — `forgejo-s3` secret path + inert `[lfs]` shape
size: M   wave: 1   depends_on: []

## Goal

Give the forgejo wrapper chart the whole LFS surface **except the activation
switch**: a Bitwarden-backed S3 credential secret, the two `additionalConfigFromEnvs`
legs that deliver those credentials into `[lfs]`, and the instance-independent
`[lfs]` shape keys. After this chunk the chart can deploy to a cluster that has
no bucket and no credentials and behave exactly as it does today (LFS stays on
local storage), which is what makes the rollout order in the plan safe.

## Tasks
- [ ] `charts/forgejo/values.yaml`: add the `forgejo-s3: OVERRIDE_VIA_CUSTOM_VALUES`
      sentinel to the existing `bitwardenIds` map, with a why-comment naming the
      item shape (Login: username = access key id, password = secret access key).
- [ ] `charts/forgejo/values.yaml`: add `forgejo.gitea.config.lfs` with exactly
      `MINIO_BUCKET: git-lfs`, `MINIO_BUCKET_LOOKUP: path`,
      `MINIO_CHECKSUM_ALGORITHM: default`, `SERVE_DIRECT: false`. **No
      `STORAGE_TYPE`** (that key, plus `MINIO_ENDPOINT`/`MINIO_USE_SSL` and
      `server.LFS_START_SERVER`, is per-instance and belongs to C02/C03).
- [ ] `charts/forgejo/values.yaml`: append the two env legs to
      `additionalConfigFromEnvs` — `FORGEJO__LFS__MINIO_ACCESS_KEY_ID` and
      `FORGEJO__LFS__MINIO_SECRET_ACCESS_KEY`, both
      `secretKeyRef → forgejo-s3-secret/{access_key_id,secret_access_key}`.
- [ ] New `charts/forgejo/templates/secret-forgejo-s3.yaml`: ExternalSecret
      `forgejo-s3-secret` (`creationPolicy: Owner`, `refreshInterval: 1h`),
      `bitwarden-login` store, `remoteRef.key = {{ index .Values "bitwardenIds" "forgejo-s3" }}`,
      `access_key_id ← property: username`, `secret_access_key ← property: password`,
      with the `conversionStrategy: Default` / `decodingStrategy: None` /
      `metadataPolicy: None` boilerplate. Follow `secret-forgejo.yaml`'s style
      (ungated, fixed names), not Loki's gated form.
- [ ] Comments on the `[lfs]` block must carry the two facts that stop a future
      editor from "simplifying" it: credentials are read from the section that
      declares `STORAGE_TYPE` (a `[storage]` section would also move
      attachments/avatars/packages to S3), and the default bucket in code is
      `gitea` so `MINIO_BUCKET` is never left unset. No ticket narration.

## Notes for dev
- `export PATH=$HOME/.local/bin:$PATH` first; `helm dependency update
  charts/forgejo` before lint/template (`charts/**/charts` is gitignored, the dep
  is OCI).
- Do **not** probe the env list with
  `--set forgejo.gitea.additionalConfigFromEnvs[2].name=…` — helm's indexed set
  nulls the existing entries (the render shows `- null` and the DB password would
  silently disappear). Assert on the committed values instead.
- `helm template --show-only templates/secret-forgejo-s3.yaml` failing "could not
  find template" is a closed-gate proof, not an error (repo convention).
- The `[lfs]` keys must sit under the wrapper's `forgejo:` subchart key
  (`charts/forgejo/values.yaml:34`), not at the file's top level.
- Nothing in this chunk may add a `[storage]` section — leg t2 is the guard and
  the reviewer should try the hostile (add it, watch t2 fail).
