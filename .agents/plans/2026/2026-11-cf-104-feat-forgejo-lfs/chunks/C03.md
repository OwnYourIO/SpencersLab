# C03: infra activation — LFS on the SeaweedFS gateway over the in-cluster endpoint
size: S   wave: 3   depends_on: [C02]

## Goal

Switch Git LFS on for the **infra** instance (the lab's canonical git:
`git.spencerslab.com`) against the same `git-lfs` bucket, reached in-cluster at
`seaweedfs-s3.default.svc.cluster.local:8333` — the gateway lives on this cluster,
so routing it through its own public Traefik entry would be a needless hairpin
(RESEARCH §Q5). Lands in `custom-values/infra/prod-values.yaml` only.

## Tasks
- [ ] `custom-values/infra/prod-values.yaml`, `forgejo.bitwardenIds`: add
      `forgejo-s3: <UUID>` (same item as dev under plan D6 / until Q3 rules
      otherwise; real UUID, never `OVERRIDE_NEEDED`).
- [ ] `forgejo.forgejo.gitea.config.server`: add `LFS_START_SERVER: true`.
- [ ] `forgejo.forgejo.gitea.config.lfs`: `STORAGE_TYPE: minio`,
      `MINIO_ENDPOINT: seaweedfs-s3.default.svc.cluster.local:8333`,
      `MINIO_USE_SSL: false`.
- [ ] Leave the infra-only extras alone: the mailer block, `APP_NAME`, the
      dedicated `infra-forgejo{,-admin,-pg,-sso}` UUIDs.
- [ ] No new service, ingress or gateway manifest: the `s3.spencerslab.com`
      Ingress already comes from `services/infra/prod/values.yaml:79-82` and this
      chunk deliberately uses the ClusterIP service instead.

## Notes for dev
- Read `chunks/C02.md` first: the same key set, only the endpoint and TLS flag
  differ; if the two slices drift, t5/t6 catch it — do not paper over it by
  repeating shared keys.
- dev and infra share the ExternalSecret name `forgejo-s3-secret` because they
  are separate clusters and separate releases; do not "disambiguate" it into
  per-cluster names, which would fork the chart interface for no benefit.
- Availability fact to carry into the review notes, not into code comments:
  `seaweedfs-s3` is a 1/1 Deployment, so infra's LFS is as available as that pod
  plus the filer behind it.
