(`app-template.controllers.radiance.initContainers.radiance-fetch`, §D3b.1: init block

becomes the §D3b.4 equality gate — the ONE replacement shape:
```sh

  echo "radiance staging: sha256 MISMATCH expected=$LFS_SHA actual=$actual"
  exit 1
fi

```
(the two-space compute form is what BOTH applet families print — `printf("%s  %s\n")`;
`cut -d' ' -f1` yields bare hex on both; `touch "$MARKER"` stays the exact success artifact
AFTER the guard, exactly as before). PRESERVED SEMANTICS, stated as invariants:
- wrong/partial digest → the MISMATCH line names BOTH `expected=` and `actual=` + `exit 1`
  (loud, non-zero, marker unreachable) — the only recommended shape whose failure log names
  the digests;

  a missing file makes BusyBox/GNU print `can't open`/`cannot open` on stderr AND the
  pipeline's `cut` yields EMPTY stdout → `actual=""` which can never equal the 64-hex
  `LFS_SHA` → MISMATCH + exit 1; a truncated file hashes differently → same path. (Guard
  omitted deliberately — it would add a branch that cannot fire before the equality does;
  adjudication recorded in D27);
- `set -e` posture UNCHANGED; marker-skip gate (328-331), fetch/echo lines, rc-0/33
  tolerance (333-342) all byte-kept;

  ~95 MB/s start to finish, §D3.6). Say it plainly in the commit; do not "harden" flags.
REJECTED shapes (recorded, with their source reasons — see D27):
