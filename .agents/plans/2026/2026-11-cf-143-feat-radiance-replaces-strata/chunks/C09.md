## Root cause (one paragraph, §D1 citations — for the commit message)
The pinned image (`docker.io/rocm/k8s-device-plugin:1.31.0.12`, manifest digest
`sha256:6437c74f…` = the values ledger, so config blob `sha256:740b1675…` IS the pinned
bytes) ships **NO ENTRYPOINT** — the binary lives in CMD's first element
(`./k8s-device-plugin` at WORKDIR `/root/` → absolute `/root/k8s-device-plugin`,
Dockerfile@v1.31.0.12). K8s semantics: `args` replaces CMD; declaring args without command
makes args[0] the exec path → `exec: "-logtostderr=true": executable file not found`,
StartError/exit 128 (live pod `gpu-ai-amd-gpu-device-plugin-daemonset-kfvnr`, 5 restarts,
spec matches the local render field-for-field). The C07 vendored template emitted
args-ONLY (a81989b47^ — the bug was BORN there), the parity oracle
`tests/evidence/pre-c08-deviceplugin-ds.yaml` captured that same broken shape (no
`command:` key anywhere), and app-template 5.0.1 emits command ONLY from the values key
(_command.tpl 4-23, _spec.tpl 15-17 — no entrypoint-providing default). "Parity, not
improvement" executed perfectly against an oracle that predates any successful live run
of that shape. The values comment at 105-110 ("CMD trio restated in full") encoded the
same misreading: CMD is binary + trio; the binary half was silently dropped.
