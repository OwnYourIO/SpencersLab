# C01: hivetools chart migration to the TOML `--config` surface (both tiers)
size: M   wave: 1   depends_on: []

## Goal

Replace the dead runtime flags on `mcp.kubernetes-readonly` /
`mcp.kubernetes-admin` with a mounted ConfigMap TOML config, keeping both
tiers' semantics byte-for-byte equivalent, image pins untouched.

## Interface contract (dev writes EXACTLY this; test asserts against it)

New template `charts/hivetools/templates/generic-mcpconfigmap.yaml` —
mirrors `generic-mcpserver.yaml`'s range/gate shape:

- range over `.Values.mcp`; render ONLY for entries that have
  `configFile` (entries without it must render nothing — non-regression).
- one ConfigMap per such entry: `metadata.name: mcp-<name>-config`,
  `metadata.namespace: {{ .Values.namespace | default "default" }}`.
- `data:` exactly one key, `config.toml`, whose value is
  `$config.configFile.content` verbatim (`nindent` — no re-indenting of the
  literal block content; YAML `|` keeps the trailing newline).

Values edits on BOTH kubernetes entries in `charts/hivetools/values.yaml`:

```yaml
    args:
      - "--config"
      - "/etc/kubernetes-mcp-server/config.toml"
    configFile:
      content: |
        port = "8080"
        stateless = true
        read_only = true          # readonly tier ONLY — admin content has 2 lines, no read_only
```

(`read_only = true` line and its trailing comment are not part of admin's
content; keep values comments minimal and factual.)

And inside each entry's existing `podTemplateSpec.spec`:

```yaml
        volumes:
          - name: tmp
            emptyDir: {}
          - name: mcp-config
            configMap:
              name: mcp-kubernetes-readonly-config   # per tier: …-admin-config for the admin entry
        containers:
          - name: mcp
            # existing securityContext unchanged
            volumeMounts:
              - name: tmp
                mountPath: /tmp
              - name: mcp-config
                mountPath: /etc/kubernetes-mcp-server
```

Contract-critical values (tests bind to these):

| item | readonly tier | admin tier |
|---|---|---|
| ConfigMap | `mcp-kubernetes-readonly-config` | `mcp-kubernetes-admin-config` |
| data key | `config.toml` | `config.toml` |
| TOML bytes | `port = "8080"\nstateless = true\nread_only = true\n` | `port = "8080"\nstateless = true\n` |
| args | `["--config", "/etc/kubernetes-mcp-server/config.toml"]` | same |
| mount | dir `/etc/kubernetes-mcp-server` (directory mount, NOT subPath — subPath projections never refresh; the dir mount shadows the image-baked config.toml) | same |
| image | `ghcr.io/containers/kubernetes-mcp-server:v0.0.69` (unchanged) | unchanged |

Why the arg path resolves under a dir mount: the volume projects the CM key
`config.toml` as a file at `<mountPath>/config.toml`.

## Acceptance criteria
1. `helm lint` passes on a /tmp copy of the chart after
   `helm dependency update` (t1).
2. Standalone chart-default render: both MCPServers `mcp-kubernetes-{readonly,
   admin}` have `spec.args == ["--config","/etc/kubernetes-mcp-server/config.toml"]`
   and no arg contains `--port`, `--stateless` or `--read-only` (t2).
3. Rendered ConfigMaps `mcp-kubernetes-readonly-config` /
   `mcp-kubernetes-admin-config` exist with the exact TOML bytes of the table
   above (readonly has `read_only = true`; admin does NOT; `port` value is the
   quoted string `"8080"`) (t3).
4. Each MCPServer's `podTemplateSpec` container `mcp` mounts a volume whose
   `configMap.name` is that tier's ConfigMap and whose `mountPath` is the
   dirname of the `--config` arg; the CM key equals the `--config` basename
   (t4).
5. Both MCPServer `spec.image` values remain exactly
   `ghcr.io/containers/kubernetes-mcp-server:v0.0.69` (t5).
6. No stray ConfigMaps render (exactly the two new ones in the
   chart-default render) and `generic-mcpconfigmap.yaml` renders nothing for
   `configFile`-less entries; `postgresMcp`/other default docs unchanged
   (t6).
7. Repo-wide sweep: every `mcp:` / `hivetools.mcp:` entry anywhere in
   `charts/`, `services/`, `custom-values/` whose image is
   `ghcr.io/containers/kubernetes-mcp-server` passes only the `--config` pair
   and pins `v0.0.69`; no occurrence of the removed flags with this image (t7).

## Notes for dev
- Environment facts (sibling FRICTION): helm at `~/.local/bin` only; never run
  `dependency update` inside the worktree; `--set` with `/`-in-value breaks —
  use extracted `--values` files if you need overrides.
- MCPServer CRD `spec.volumes` is hostPath-only — the volume MUST live inside
  `podTemplateSpec.spec.volumes` (RESEARCH F4). Do not add top-level
  `volumes:` to the mcp entry.
- Unknown TOML keys fail startup hard — do not "helpfully" add
  `kubeconfig`/`toolsets`/`bind_address` lines; defaults are correct
  (in-cluster config via ServiceAccount; toolsets `["core","config"]`).
- Helm deep-merge: service-level `hivetools.mcp.<name>` blocks that DON'T
  touch the kubernetes entries leave these values intact; the `--set`-based
  fleet overrides don't exist. If you must simulate one, use `-f` values file.
