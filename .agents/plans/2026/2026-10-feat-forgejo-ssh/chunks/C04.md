User-directed follow-up after final review (DECISIONS.md 2026-10-24): the
vendored raw CRD template is not the desired tracking form — CRDs must be
pinned like chart dependencies. Ground truth: `RESEARCH-gateway-crd-chart.md`
(companion note in this folder) — `gateway-api-crds` v1.2.5 from
`https://charts.christianhuth.de`, experimental channel, tcproutes-only
scoping, rendered CRD spec-identical to the vendored one (re-verified during
C04 planning, evidence in Notes below).

## Goal

Replace `charts/base/templates/gateway-tcproute-crd.yaml` (the C02 vendored
experimental-channel tcproutes CRD) with a PINNED CHART DEPENDENCY:
`gateway-api-crds` 1.2.5 in `charts/base/Chart.yaml` + committed
`Chart.lock`, tracked by renovate's standard helm manager. The replacement
gating is STATIC VALUES, not a template gate — a chart dependency cannot sit
inside `{{- if }}`:

- base's default values carry `gateway-api-crds: {enabled: false,
  standard.enabled: false, experimental.enabled: false}` — the Chart.yaml
  `condition: gateway-api-crds.enabled` then skips the subchart on every
  cluster. (GOTCHA, empirically proven: helm loads a conditioned subchart
  when the condition path is ABSENT. Probe without the default block: an
  uninvolved cluster rendered the chart's default 10-CRD experimental
  bundle. The keys must exist in base's values.yaml, not just the condition
  in Chart.yaml.)
- dev + infra service values re-enable EXACTLY the experimental tcproutes
  CRD (+ `helm.sh/resource-policy: keep`), flowing into base via the appset
  valueFiles/valuesObject alongside `gitSshPort: 22222`.
- the `gitSshPort` template gate on the traefik-config.yaml HelmChartConfig
  block stays exactly as C02 built it. gitSshPort remains the single
  SEMANTIC gate (the human toggle); the `gateway-api-crds:` block is its
  static companion wiring — ungated in the values files (values are static
  per service anyway), kept adjacent to `gitSshPort:` with a comment naming
  it, added/removed in lockstep with it.

After this chunk the open-gate base render for dev/infra is semantically
unchanged (same HelmChartConfig surface, same CRD spec + one added
`helm.sh/resource-policy: keep` annotation), and every other cluster still
renders nothing gateway-related.

## Interface (the exact values contract — researcher-verified, probe-verified in planning)

`charts/base/Chart.yaml` — third dependency:

```yaml
# Pinned source of the experimental-channel tcproutes CRD (traefik 3.7's
# gateway provider watches TCPRoute at v1alpha2, which only the experimental
# channel serves). The condition key is default-off in values.yaml; helm
# loads a conditioned subchart when the condition path is ABSENT, so the key
# must stay present there. Renovate's built-in helm manager tracks this dep
# (HTTP repo, like argo-cd/cert-manager above) — no # sourceUrl: annotation,
# the repo's override manager would double-extract it.
- name: gateway-api-crds
  version: 1.2.5
  repository: https://charts.christianhuth.de
  condition: gateway-api-crds.enabled
```

`charts/base/values.yaml` — default OFF (all clusters):

```yaml
# Experimental-channel Gateway API CRDs as a pinned chart dependency
# (Chart.yaml). Default OFF on every cluster: the Chart.yaml condition on
# this key gates the dependency, and helm loads a conditioned subchart when
# the condition path is ABSENT — so these keys must stay present and false
# here, or every base-managed cluster gets the chart's default CRD bundle.
# dev + infra re-enable exactly the experimental tcproutes CRD in their
# service values (companion wiring to gitSshPort — keep them in lockstep).
#
# Ownership overlap (accepted, unchanged from the vendored design): k3s's
# traefik-crd helm release owns the same CRD object (the standard variant).
# k3s re-applies it only at boot/chart-change; ArgoCD selfHeal restores this
# experimental variant within one refresh (~3 min), and a transient TCPRoute
# watch gap in that window is accepted. tcproutes-only scoping keeps the
# overlap at exactly this 1 CRD. If ArgoCD ServerSideApply ever hits a
# field-manager conflict, remediate at the ArgoCD Application layer (the CRD
# is dependency-rendered now — there is no repo template to annotate).
gateway-api-crds:
  enabled: false
  standard:
    enabled: false
  experimental:
    enabled: false
```

`services/dev/prod/values.yaml` + `services/infra/prod/values.yaml` — the
enable block, directly after the `gitSshPort:` block:

```yaml
# Companion wiring for gitSshPort (keep adjacent — the two move together):
# the gitssh gateway needs the experimental-channel tcproutes CRD (traefik
# 3.7 watches TCPRoute at v1alpha2), served by the base chart's
# gateway-api-crds dependency. Scoped to tcproutes only, so the ownership
# overlap with k3s's traefik-crd release stays at exactly 1 CRD (full
# overlap note: charts/base/values.yaml).
gateway-api-crds:
  enabled: true
  standard:
    enabled: false
  experimental:
    enabled: true
    crds:
      # experimental tcproutes ONLY (tcproutes stays at its chart default
      # true; every other toggle off) — all other gateway CRDs stay owned
      # by k3s's traefik-crd release.
      backendtlspolicies: false
      gatewayclasses: false
      gateways: false
      grpcroutes: false
      httproutes: false
      listenersets: false
      referencegrants: false
      tlsroutes: false
      udproutes: false
      xbackends: false
      xbackendtrafficpolicies: false
      xlistenersets: false   # no template in the chart today; explicit for forward-compat
      xmeshes: false
  global:
    resourcePolicy:
      keep: true   # uninstalling the base release must not cascade-delete a CRD that k3s also owns
```
