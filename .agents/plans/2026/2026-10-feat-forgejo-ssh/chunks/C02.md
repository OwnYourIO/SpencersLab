# C02: Gateway API surface in the base chart (dormant)
size: L   wave: 1   depends_on: []

## Goal

Add the complete Gateway API exposure surface for git-SSH to `charts/base`,
gated behind a top-level `gitSshPort` value so it renders NOTHING on any
cluster until C03 sets the value in the dev/infra service umbrellas. Two
pieces in the base chart: (1) the repo-managed k3s traefik HelmChartConfig
gains the `kubernetesGateway` provider (+ experimentalChannel), a `gitssh`
port/entrypoint, and a chart-rendered Gateway listener; (2) a new template
vendors the EXPERIMENTAL-channel `tcproutes` CRD (v1.6.3) that traefik 3.7's
v1alpha2 TCPRoute client requires. After this chunk, `helm template
charts/base` with the default values is byte-for-byte unchanged for the
HelmChartConfig and renders no CRD — the gate is closed everywhere.

- [ ] Add `charts/base/templates/gateway-tcproute-crd.yaml`: the vendored

## Interface (the values contract C03 and the tests rely on)

Gate: top-level `gitSshPort` (integer). Inside the HelmChartConfig
`valuesContent`, all of the following appear ONLY under
`{{- if index .Values "gitSshPort" }}`:

1. Under the EXISTING `providers:` key (no duplicate YAML keys):
   ```yaml
   kubernetesGateway:
     enabled: true
     experimentalChannel: true
   ```
2. Under the EXISTING `ports:` key (same pattern as the `seaweedvolume`
   block):
   ```yaml
   gitssh:
     port: {{ index .Values "gitSshPort" }}
     expose:
       default: true
     exposedPort: {{ index .Values "gitSshPort" }}
     protocol: TCP
   ```
   (the chart derives the `gitssh` entrypoint from `ports.*` — do NOT add to
   the existing `entryPoints:` block; it is chart-ignored dead weight)
3. A new top-level `gateway:` key. The k3s-stock chart renders a Gateway
   named `traefik-gateway` in kube-system from it; the chart's default
   `web` listener must be explicitly removed (YAML null) so the lab Gateway
   carries ONLY the git-SSH listener:
   ```yaml
   gateway:
     listeners:
       web: null
       gitssh:
         port: {{ index .Values "gitSshPort" }}
         protocol: TCP
         namespacePolicy:
           from: All
   ```
   (`namespacePolicy.from: All` → allowedRoutes from any namespace; the
   TCPRoutes live in `default` next to the forgejo Services while the
   Gateway lands in kube-system next to traefik.)

CRD template `gateway-tcproute-crd.yaml`:
- Gate: `{{- if index .Values "gitSshPort" }}` (same key, same clusters).
- Content: the gateway-api **v1.6.3 experimental-channel**
  `gateway.networking.k8s.io_tcproutes.yaml` vendored verbatim
  (source: raw.githubusercontent.com/kubernetes-sigs/gateway-api/v1.6.3/
  config/crd/experimental/gateway.networking.k8s.io_tcproutes.yaml,
  sha256-recorded at fetch time). It MUST keep both served versions:
  `v1` (storage) and `v1alpha2` (served, deprecated) — traefik 3.7 lists
  v1alpha2; the forgejo subchart's TCPRoute template is v1alpha2.
- A short WHY-comment above the gate: traefik 3.7's gateway provider lists
  TCPRoute at v1alpha2, k3s's standard-channel bundle doesn't serve it, so
  the lab vendors the experimental CRD; k3s's traefik-crd release owns the
  same object (overlap caveat — see plan Risks).
