# C10: Calendar chart versions in the bump loop (Y.M.N, local N)
size: M   wave: 2   depends_on: [C09]

## Goal

Replace the bump leg's "patch above BOTH tree and published index" rule
(D17 shape) with the owner's calendar scheme: `2026.11.1++`, N derived
LOCALLY from the chart's own tree version + the run's month stamp
(owner ruling Q1 "Simple: local N only" — STATE.round4_directive),
migration per chart on its next change — no sweep, no cutover commit
(RESEARCH.md:1255-1263 (d)). Legality is evidence-set: `2026.11.1` is
normal semver end-to-end (helm package validates via Masterminds
`NewVersion`; cr/ArgoCD/Renovate handle version as an opaque string —
RESEARCH.md:1171-1194 (a) [75][76][84][88][79][81]) and the repo's own
`ver()` already tuple-parses 4-digit majors (RESEARCH.md:1192-1194, repo
release.yaml:186-190).

## Design (code shape; the exact rule)

Inside the bump loop's python derivation, per chart (one clock stamp per
run, containers-build's `month=` law — RESEARCH.md:1230-1231, :1248-1250
midnight-straddle):

```
STAMP = bash-computed ONCE in the step, passed to python:
        Y, M = $(date -u +%Y.%-m)          # UNPADDED month — hard law
        # Masterminds NewVersion rejects leading zeros: "2026.07.1" is
        # invalid semver and dies at helm package (RESEARCH.md:1178-1182
        # [88]) — the D15 lesson reborn. One stamp, no per-chart date call.

per chart (tree = ver(Chart.yaml version); published = today's same-indent
index parser result for the chart's NAME key — parser unchanged, role
demoted from derivation term to collision guard):

  if (tree.major, tree.minor) == (Y, M):  cand = (Y, M, tree.patch + 1)   # same-month walk
  elif tree < (Y, M, 0):                  cand = (Y, M, 1)                # month rollover,
        # legacy 1.0.203 -> 2026.12.1 first calendar stamp on its fire,
        # and first-ever calendar chart — all the same arm
  else: raise SystemExit(f"{path}: tree version {tree} is ahead of the
        clock stamp ({Y},{M},0) — refusing to walk backwards")           # FAIL LOUD
  while published.get(key, (0,0,0)) >= cand:   # bounded collision walk
      cand = (Y, M, cand.patch + 1)             # (never re-mint a
                                                # published version)
  write f"{cand[0]}.{cand[1]}.{cand[2]}" — numeric formatting, so a
  padded stamp cannot leak into the file.
```

- **What the owner's "local N" replaces:** the `base = max(tree,
  published)` derivation term. The published-index fetch (curl,
  `--retry 3` — t20) and the same-indent pairing parser (t15) STAY: the
  index now feeds only the skip-when-already-published guard above, so
  "a published version is never re-minted" (D17 law half) survives
  without the dual walk (launch directive: "KEEP the tree-comparison
  idempotency and the skip-when-already-published guard"; RESEARCH.md:
  1226-1229, :1246-1251).
- **FF-loop idempotency re-derived:** each attempt re-fetches + resets to
  main tip, so a competing runner's advanced tree feeds the next
  derivation — same-month walk yields N+1 off the NEW tree (monotone, the
  D17 loop law itself, RESEARCH.md:1249-1251); a re-run of an old event
  mints one benign extra N (RESEARCH.md:1245-1247). Re-derivation every
  push rejection stays the safety property; `concurrency` stays
  opportunistic.
- **Instance index: excluded from N derivation (evidence-set, not just
  research rec):** reading it in bump would drag `FORGE_PUSH_TOKEN` into
  the bump job, violating the shipped t7 pin "no named secret in the bump
  job" (automatic-token-only law) — RESEARCH.md:1241-1244 recommendation
  + tests/services/forgejo-release.sh t7 (secrets ban). The instance
  registry keeps its existing skip-if-present guard in forgejo-publish
  (unchanged — the tree leads it by construction since bump commits precede
  publishes).
- **Year width: 4-digit** (`2026.11.1`, owner literal; sorts fine, avoids
  collision with genuine 26.x majors — RESEARCH.md:1308-1311). 2027
  rollover is safe by arithmetic (same rule, stamp changes, N resets).
- **cr/index pairing law interaction: none.** The pairing guard is
  name/indent-based and version-string-blind (C01 BLOCKER-3 derivation);
  4-digit majors parse under the same `ver()`. The t15 battery is
  RE-AIMED (fixtures' expectations move from "base = max(...)" to
  "collision guard"), not deleted.
- **test-build's local "Patch-bump Chart.yaml" smoke step stays
  byte-unchanged** (research (c) end: on a converted chart it walks N
  locally; on a legacy chart it previews patch+1 — it is a never-pushed
  lint/package fixture, and t-pins read its shape) — do NOT "calendarize"
  it in this chunk.
