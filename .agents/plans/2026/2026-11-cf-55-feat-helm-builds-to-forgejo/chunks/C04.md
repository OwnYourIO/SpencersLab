# C04: Enable the instance package registries (helm + OCI) repo-side in infra custom-values

size: S   wave: 1   depends_on: []

## Goal

The prod (infra) Forgejo instance serves the Helm package registry and the OCI
container registry that C01/C02 push to, declared repo-side per the chart's
established per-instance config pattern — `custom-values/infra/prod-values.yaml`
`forgejo.forgejo.gitea.config.*` (the LFS opt-in precedent: "that declaration is
the gate", charts/forgejo/values.yaml:92-100). Dev instance stays un-enabled
(decision D20: prod only; migration is the owner's pace).

## Tasks

- [ ] Add to `custom-values/infra/prod-values.yaml` under
  `forgejo.forgejo.gitea.config` a `packages:` block:
  - `ENABLED: "true"` (the `[packages]` section gates BOTH the helm registry and
    the OCI container registry — RESEARCH [13][14]; V-3 [16]: it ALREADY
    defaults true in v15.0, so this declaration is the explicit-on posture —
    keep it, pinned by the suite).
  - Size keys deliberately ABSENT (decision D24): v15.0 has NO generic
    `LIMIT_SIZE` key (declaring one would render into app.ini and be silently
    ignored by the binary); the per-type keys `LIMIT_SIZE_HELM` /
    `LIMIT_SIZE_CONTAINER` default `-1` = unlimited [16] — declaring caps is
    scope creep; owner adds them to the same block later if hygiene bounds are
    wanted (UA-4).
  - string-typed values matching the existing config blocks' style (server/lfs
    keys show it); a `#` comment naming this as the cf-55 dual-publish target
    enablement + pointing at the deliberate non-touch of `[storage]` (chart law:
    a `[storage]` section would drag attachments/avatars/packages to S3).
  - No other keys (visibility/quota left at instance defaults — `[quota]`
    defaults disabled [16], no action; anonymous-read behavior is a
    first-fire/observation for the migration card — no consumer reads it yet).
  - Dev instance stays un-enabled (decision D20: prod only).
- [ ] Write `tests/services/forgejo-packages.sh` (skeleton per Tests below).
