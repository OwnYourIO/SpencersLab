- N1 (nit, comment accuracy) `Dockerfile:184-185` — "/home/coder is hardcoded because Docker would expand $HOME from the base image (=/root) at build time." The pinned debian:13-slim image config sets only `PATH`; `$HOME` is unset, so a build-time expansion would be empty, not `/root`. The conclusion (hardcode) is correct under either mechanism. Suggested fix: drop the parenthetical, e.g. "…because Docker expands `$HOME` at build time from the base image env, which does not set it."
- N2 (nit, robustness) `workspace-startup.sh:29` — the new `nohup setsid "$@" … | sed … &` leaves `sed` outside the `nohup`/`setsid` protection, unlike the old template's `nohup setsid sh -c 'cmd | sed …'`. No practical impact (non-interactive shells do not HUP background jobs on exit; the Coder agent runs the script non-interactively), but wrapping the whole pipeline in `sh -c` under `nohup` would restore parity.
- N3 (nit, convention) `workspace-startup.sh` repo mode is 644; `COPY --chmod=0755` makes the in-image mode correct and tests run via `bash`, so this is cosmetic. `chmod +x` in the repo would allow direct local execution.
