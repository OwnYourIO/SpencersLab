  1. *What this is / what it is not*: relay drives API syncs on push; the
     `services.<cat>.selfHeal="false"` annotations stay untouched (OQ1 ruling); no appset,
     no `charts/base`, no automated-policy changes anywhere. Ref model (OQ7 ruling): the
     relay fires only for refs in its `allowed_refs` CONFIG LIST (shipped default
     `["refs/heads/main"]` — the only branch revision in use per the plan's revision
     grounding), and per fired ref syncs only apps whose live `spec.targetRevision` matches
     it; widening for a future `stage` branch = one `allowedRefs` values edit + PR + sync,
     no code change — document the procedure. Pointer to the ticket folder + RESEARCH for
     background, k3s 2026-10-20 incident note as the WHY of non-force.
  2. *Step 0 — secrets (human, POST-merge — OQ5 ruling "merge first, fill later")*: create
     Bitwarden item `argocd-hook` (login item, password = fresh random high-entropy GitHub
     HMAC secret) and item `argocd-hook-tokens` (custom fields, one per category:
     `dev,gpu,gpu-ai,grow,home,infra,media,monitoring,proxy-local,proxy-backup,
     proxy-remote`); on EACH cluster mint an mcp-bot token (admin
     `argocd account generate-token --account mcp-bot` or UI; human) and paste into the
     matching field; replace both `OVERRIDE_NEEDED` lines in
     `custom-values/proxy-local/prod-values.yaml` with the real item UUIDs in a follow-up
     commit at the owner's convenience — the branch MERGES with the sentinels (ruled).
     Until the UUID commit exists AND root `proxy-local` has been synced after it, the
     relay cannot come up: `proxy-local-argocd-hook` crash-loops visibly — ruled-in
     designed behavior, harmless to everything else; the runbook recommends Step 0 before
     Step 1 so bootstrap starts clean in one pass.
  3. *Step 1 — bootstrap (after Step 0 ideally)*: land the PR (owner merges; repo never
     advances main by agent); sync root app `proxy-local` manually (one last manual act),
     then sync the new child `proxy-local-argocd-hook` once the appset generates it;
     verify pod Ready + `GET /health` 200 through the hub route. If a root sync happened
     before the UUID fill: the expected CrashLoopBackOff resolves itself after the UUID
     commit + one further root sync (appset re-renders the child) — no other remediation.
  4. *Step 2 — GitHub webhook (human)*: repo `OwnYourIO/SpencersLab` → Settings → Webhooks:
     Payload URL `https://argocd-hook.spencerslab.com/`, Content type **application/json**
     (form-encoded unsupported — RESEARCH [4]), Secret = the `argocd-hook` item password,
     event = push. GitHub-side note: repo ArgoCD tracks is GitHub (main-sync copies from
     Forgejo — hook fires on the GitHub push landing).
  5. *Step 3 — smoke before trusting*: (a) GitHub "Test" ping → relay logs 200, no syncs;
     (b) signed synthetic `refs/heads/main` push POST via curl from a mesh host (HMAC recipe
     in the runbook) → 202, log shows per-target lines, `proxy-local` root syncs;
     (b′) signed synthetic push of a NON-`allowed_refs` ref (e.g. `refs/heads/smoke-x`) →
     200 no-op, no sync log lines (proves the config-list filter live);
     (c) real no-op-ish PR merge (docs bump) → every reachable root reaches Synced within
     well under the old ≤3-min poll path; record observed latency.
  6. *Preflight table* (task 1 output): per cluster {root syncPolicy observed | child sample
     state | OutOfSync list | probe status}; explicit `infra-seaweedfs` accept-before-first-
     push note (pointer `.agents/notes/2026-11-10-seaweedfs-incident-findings.md`) and the
     "first push will sync it like your manual button does" framing.
  7. *Rollback*: disable/remove the GitHub webhook (instant source stop; Recent Deliveries
     + redeliver documented) → optionally revert the two proxy-local values entries + chart
     dir via PR and manually sync root `proxy-local` once. State plainly: nothing else
     changes anywhere — syncPolicy posture never moved, no prune was ever run, the fleet is
     exactly back at today's manual workflow.
  8. *Limitations*: missed/rejected deliveries during relay downtime are NOT replayed
     (fallback = manual sync, as today); `prune=false` (OQ6 ruling) — git-removed resources
     linger; only refs in `allowed_refs` fire (OQ7 ruling; shipped set `["refs/heads/main"]`
     = every revision in use) and only apps tracking the fired ref are synced; token
     rotation = re-mint + re-store + reloader restarts the pod (annotation shipped in C02).
