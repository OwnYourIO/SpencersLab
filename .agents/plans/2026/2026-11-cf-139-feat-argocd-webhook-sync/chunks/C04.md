# C04: main-sync `hook-relay` job — signed fan-out trigger after push-gh (R1, option (c))
size: S   wave: 5   depends_on: [C01-fix]

## Goal

Teach `.forgejo/workflows/main-sync.yaml` to trigger the relay itself: a final job,
gated the file's own way and running only after `push-gh` has advanced GitHub (the origin
ArgoCD actually reads — probe [P §1]), POSTs a GitHub-shaped push payload signed with the
shared HMAC in `X-Forgejo-Signature` plain-hex form (R3's new dialect). No external
webhook is created anywhere; the mirror workflow is the webhook. First-ever `.forgejo/**`
change in this ticket — validation is the existing static contract suite, extended.

## Tasks

- [ ] New job `hook-relay` in `.forgejo/workflows/main-sync.yaml`:
  - `needs: [push-gh]` (runs only on push-gh SUCCESS ⇒ GitHub already advanced — this
    ordering IS the race resolution) and the byte-exact guard `if: contains(vars.ROLE,
    'prod')` (dev instance / unset ROLE fire nothing; the dependent-on-guard-skipped chain
    makes this belt-and-braces, pin it anyway per the suite's exact-bytes convention).
  - `runs-on: ubuntu-24.04` (suite t7 set), NO `actions/checkout` (payload comes from the
    Actions context only; no repo content needed), steps: one `diag` (echo ROLE, matches
    neighbors) + one run block starting `set -euo pipefail` (t6).
  - env (instance-side, per the file's "no URL, no token in the file" convention):
    `RELAY_URL: ${{ vars.ARGOCD_HOOK_URL }}`, `RELAY_SECRET: ${{ secrets.ARGOCD_HOOK_SECRET }}`,
    plus context fields `EVT_REF/EVT_BEFORE/EVT_AFTER/EVT_FULL_NAME` from
    `github.event.*` and `GH_SHA/GH_REPO/GH_REF/RUN_TAG` from `github.sha/repository/ref/
    run_id`+`run_attempt`.
  - skip guard: `RELAY_URL` or `RELAY_SECRET` unset ⇒ `::warning:: hook-relay not
    configured (instance vars.ARGOCD_HOOK_URL / secrets.ARGOCD_HOOK_SECRET) — fan-out
    trigger skipped, manual sync or the next push covers it` and exit 0 — unset never
    breaks the mirror (fail-safe, same philosophy as this file's unset-ROLE posture;
    pinned best guess per plan OQ section).
  - payload: `python3 -c` json.dumps from env (no shell quoting of values), keys exactly
    `ref`, `before`, `after`, `repository.full_name`; dispatch/first-push fallbacks:
    `ref → refs/heads/main`, `after → $GH_SHA`, `full_name → $GH_REPO`, `before` may be
    `""` (the relay consumes ONLY `ref` — [P §4] re-verified against `main.py:379`; the
    rest is delivery identity, covered by the signature).
  - signature: `SIG=$(printf '%s' "$BODY" | openssl dgst -sha256 -hmac "$RELAY_SECRET" |
    awk '{print $NF}')` — lowercase plain hex, NO `sha256=` prefix (the file must contain
    no `sha256=` and no `X-Hub-Signature-256` literal — this caller speaks forge dialect;
    the hub dialect stays for the R2 future-GitHub-webhook door only).
  - POST: `curl` (sS, `-o /dev/null -w '%{http_code}'`, `--max-time 15 --retry 3
    --retry-delay 5 --retry-all-errors`) with headers `Content-Type: application/json`,
    `X-Forgejo-Event: push`, `X-GitHub-Event: push` (the relay's unchanged event gate —
    real Forgejo webhooks send this family; the job mirrors it so NO relay event-handling
    change is needed), `X-Forgejo-Delivery` + `X-GitHub-Delivery: $RUN_TAG`,
    `X-Forgejo-Signature: $SIG`, `--data "$BODY"`. Guarded so nothing aborts the job:
    non-2xx-after-retries or unexpected code ⇒ distinct `::warning::` lines (401 ⇒
    "relay secret disagrees with the Actions vault"; never echo secret or body), job exits
    0 regardless — R1 limitation: fan-out failure ⇒ that push lands as no-op at the old
    revision; next push self-heals (fan-out syncs every OutOfSync app tracking the ref,
    SHA-agnostic).
  - audit echo: `ok: relay accepted code=… delivery=$RUN_TAG` on success.
