# C01: `argocd-hook` relay container (HMAC verify → allowed_refs config-list filter → async API-sync fan-out)
size: M   wave: 1   depends_on: []

## Goal

Ship `containers/argocd-hook/`: a small stateless webhook relay that GitHub points at. It
verifies the shared `X-Hub-Signature-256` HMAC of a push hook, ignores any ref outside the
`allowed_refs` config list (default `refs/heads/main`), answers 202 within GitHub's 10s
budget, then asynchronously drives ACTUAL
SYNCs of each fleet cluster's ArgoCD via its REST API — root app first, then every still
OutOfSync app sourced from the repo — using per-cluster `mcp-bot` bearer tokens. No
automated-syncPolicy change anywhere: this is the ruling-compliant way to make "pushed to
main" land (OQ1 kill-switch kept; webhooks-only-refresh does nothing without it — RESEARCH
[4][10]).

## Tasks

- [ ] `containers/argocd-hook/main.py` (stdlib-only `http.server.ThreadingHTTPServer` +
      `hmac`/`hashlib` + `urllib.request` — glue pattern of `containers/traefik-mqtt-allowlist/`;
      Python over Go deliberately: locally unit-testable without a toolchain gamble):
  - [ ] POST `/` webhook handler: constant-time HMAC verify against the shared secret file;
        401 on bad/missing signature; JSON parse failure → 400. Non-push `ping` event → 200
        no-op (GitHub "Test" button sanity). Ref filter = the `allowed_refs` CONFIG LIST from
        targets.json (OQ7 ruling "wider filter"): push `ref` ∉ list → 200 no-op; `refs/tags/*`
        never fire; missing/empty `allowed_refs` → default `["refs/heads/main"]` (the only
        in-use branch revision per the plan Context grounding; stage branches are added by
        config, not code). Valid allowed ref → enqueue per-target fan-out on a worker thread,
        answer 202 IMMEDIATELY (10s budget, RESEARCH Agenda 2 shape C).
  - [ ] Fan-out per target, REMOTE CLUSTERS FIRST, the `local: true` proxy-local entry LAST
        (self-sync can restart the relay mid-run): (1) `GET <url>/api/v1/applications` once
        — eligible set = apps with a source where `repoURL == target.repo` AND
        `spec.targetRevision == <fired ref tail>` (spec-driven: the same call answers "does
        this cluster even track the ref that fired?" — no eligible root ⇒ target skipped
        with a log line, so a widened stage ref never sync-fires prod clusters); (2) `POST
        <url>/api/v1/applications/<rootApp>/sync?prune=false` with `Authorization: Bearer
        <token>` if the root (`config.rootApp`) is eligible; (3) settle delay (config,
        default ~10s so the appset regenerates children from the new git), then re-GET and
        sync each eligible app with `status.sync.status != Synced` (skip the root, already
        done): `POST …/applications/<name>/sync?prune=false`. `prune=false`, NEVER force
        (root apps lack the `RespectIgnoreDifferences` syncOption — plan Context). Path/
        namespace-qualified variants (`/applications/{name}` vs `/applications/{namespace}/{name}`)
        per ArgoCD v3.5 API docs — verify against the docs, apps live in `default`.
  - [ ] Error posture: HTTP 409 / "another operation is already in progress" = SUCCESS;
        per-target timeout (default 60s) and per-target try/except so one dead cluster never
        aborts the rest; one structured log line per target per push (name, root, children
        count, ok/failed + reason) — the audit trail for "the relay skipped it".
  - [ ] `GET /health` (200 + config validity) for chart probes.
  - [ ] Config from files, never env-carried secrets: `--config /config/targets.json` —
      top-level OBJECT `{"allowed_refs": ["refs/heads/main"], "targets": [{name, url,
      rootApp, tokenKey, repo, local?}]}` (absent `allowed_refs` → default
      `["refs/heads/main"]`; `repo` = the git origin that cluster's ArgoCD tracks, matched
      against app `spec.source.repoURL`; the accept-list decides *whether* a push fires the
      relay, per-app `spec.targetRevision`
      matching decides *which apps* a fired push syncs — revision truth lives in the live
      app specs, not duplicated config) — and `--secrets-dir /secrets` (`github-webhook` key
      file + one file per `tokenKey`). `--check` flag loads config, runs an internal HMAC
      sign/verify round-trip, validates the roster + `allowed_refs` shape, prints the target
      table, exits 0/1 — no network. Env only for the tunables (`SETTLE_SECONDS`,
      `TARGET_TIMEOUT_SECONDS`).
- [ ] `containers/argocd-hook/Dockerfile` per container-creation skill: pinned
      `python:3.11-slim-bookworm` (renovate docker datasource manages bumps), layer order
      (deps→code→user), non-root uid 65532 via `groupadd/useradd` (name-collision rule),
      `PYTHONDONTWRITEBYTECODE=1`, ENTRYPOINT `python3 -u /app/main.py`, EXPOSE 8080, no
      pip deps (stdlib only ⇒ no requirements.txt).
- [ ] `containers/argocd-hook/README.md` (3–6 lines: what it does, config contract — the
      chart and runbook reference it).
- [ ] Local validation WITHOUT a docker daemon: `python3 -m py_compile`, `--check` run
      against a sample config fixture, in-process mock tests (C02's agent-test harness —
      the pattern `tests/containers/wekan-mcp-login.sh` already proves); capture
      build-critical facts from the pinned base image's GHCR layer tar-listing/manifest
      digest; record `docker build => no-daemon, CI-deferred` (designed passing shape —
      `.forgejo/workflows/containers-build.yaml` on the pushed branch is authoritative).

## Notes for dev

- The relay replaces the RESEARCH refresh-fan-out idea wholesale: `/api/webhook` forwarding
  is NOT implemented (useless with automated off — plan Scope decision). If a refresh call
  looks necessary, it is not; sync resolves git at operation time.
- No persistence, no queueing: a restart losing an in-flight fan-out is accepted (fallback =
  today's manual sync; logged). Do not add redis/PVC.
- Keep securityContext-friendly: bind 8080 unprivileged, write nothing to disk (set
  `readOnlyRootFilesystem` compatibility as a given — C02 will set it).
- Comments: WHY-style only; run `comment-slop` discipline; aislop gate on edits.
- `--check` must never dial the network (harness depends on it).
- Commit is coord's job; dev leaves the tree ready and reports `commands_run`.
