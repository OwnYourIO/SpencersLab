# C02: `charts/argocd-hook` + proxy-local service trio (chart, appset entry, crowdsec-only subdomain, secrets)
size: M   wave: 2   depends_on: [C01]

## Goal

Deploy the relay onto the proxy-local hub the repo's standard way: a bjw-s app-template
chart consuming the C01 image, wired through the full service trio — `charts:` ApplicationSet
entry in `services/proxy-local/prod/values.yaml`, a crowdsec-only public `argocd-hook`
subdomain entry on the hub, and ExternalSecret + Bitwarden secrets with the
`OVERRIDE_VIA_CUSTOM_VALUES` ⇄ `custom-values/proxy-local/prod-values.yaml` 1:1 pairing.
Zero changes to any appset gate, `charts/base`, or other clusters.

## Notes for dev

- app-template 5.0.1 API: read the shipped chart's `values.schema.json`/templates if a key
  shape is uncertain — do not guess 4.x idioms. `helm template` is the truth-teller.
- Remember FRICTION.md: render WITHOUT vendored deps silently renders nothing for
  charts/base — same trap class applies here; always `helm dependency update`/`build`
  before lint/template and grep that the render is non-empty.
- Domain injection in configMap data: if the library can't interpolate `$.Values.domain`
  into a configMap string, the sanctioned fallback is a plain chart `templates/configmap-
  targets.yaml` (Go template building URLs from `.Values.domain`) consumed as
  `additionalVolumeMounts`/`existingConfigMap` — keep the file contract `/config/targets.json`
  identical either way (C03 documents whichever shape shipped).
- ExternalSecret templates must target the stores the base category wiring uses
  (`bitwarden-login` / field store per `references/storage-and-secrets.md`); the token item
  is one LOGIN-style item with custom fields — mirror `secret-argocd-sso.yaml` mechanics.
- Never flip any live thing; nothing in this chunk applies to clusters — git + helm render
  only.
- comment-slop discipline; aislop gate; commit is coord's.
