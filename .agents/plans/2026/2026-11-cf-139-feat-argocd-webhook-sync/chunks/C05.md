   only (no yaml/requests/pip) — provable by grep of `^import|^from`.
2. `bash tests/argocd-fanout/behavior.sh` fully green (legs t1–t12 below).
3. `--check` with a valid roster + matching vault env exits 0 printing
   `argocd-fanout --check: OK`, the 11-line category/URL table, allowed_refs and
   tunables — and opens ZERO sockets (fixture server reports zero requests).
4. Every config-error class exits 1 with an `argocd-fanout config:` stderr line naming
   the category/field and NO token value: unknown record category, roster category
   without a token, non-JWT token, record without `:`, empty env, malformed/unreadable
   roster JSON, `refs/tags/*` in allowed_refs, duplicate target name, bad url scheme.
5. Live-run shape (fake transport): root sync first, then settle, then only children
   whose live `spec.targetRevision` equals the ref tail AND whose repoURL byte-matches
   `tracked_repo` AND sync status ≠ Synced; sync POST carries `prune=false` in the query
   AND `{"prune": false}` in the body; a 409 response audits `root=in-progress` as
   success; eligible-but-NotFound root ⇒ `skipped` with the pinned detail.
6. Per-target isolation: one target timing out / answering 401 / answering garbage JSON
   yields `result=failed` for it while all other targets complete; exit code stays 0;
   summary line counts reconcile.
7. Ref gate: `--ref refs/heads/other` (not in allowed_refs) ⇒ one log line, zero
   requests to the fixture, exit 0.
8. Secret hygiene: the fixture token values appear NOWHERE in combined
   stdout+stderr across every leg, including config errors; no fixture token appears in
   the process argv of any leg invocation.
9. `--dry-run`: fixture records GETs and ZERO POSTs; per-target eligibility lines are
   printed; exit 0.
10. All-skipped arm (roster `tracked_repo` deliberately ≠ what the fixture apps carry):
    audit lines all `skipped`, `::warning::` summary present, exit 0.
11. Roster hosts pin [P2]: the 11 urls in `scripts/argocd-fanout.json` equal, byte for
    byte, the [P2 §1] measured table (the route-truth doctrine leg).

### major

- **M1 — `scripts/argocd-fanout.py:142-144`: the unknown-category message can echo a real
  token.** `cat` is whatever precedes the first `:` in a vault record, so a reversed paste
  (`token:cat` — the classic two-field swap) prints the whole JWT. Proven:
  `ARGOCD_SYNC_TOKENS='eyJ…DEVSECRETTOKENxKq:dev'` → stderr
  `argocd-fanout config: record for unknown category "eyJ…DEVSECRETTOKENxKq"`. AC8's rule is
  "nothing echoes the token"; the message shape is pinned by the plan, but only for the normal
  typo case, so guarding this branch does not contradict the contract. The leak is also
  UNMASKED in CI: [26] registers each secret LINE, and the echoed value is the line minus its
  `:dev` tail, so no registered string matches it. Fix (keeps every t4 arm green): before
  interpolating, if `JWT_RE.match(cat)` → `raise ConfigError("vault record looks reversed
  (token before category) — expected cat:token")`; optionally bound the echo (`cat[:64]`),
  since an unbounded field is also a log-spam surface (proven: a 300-char cat prints whole).
  The harness has no arm for this class — t12's sweep only greps the legs t4 happens to run.
- **M2 — no redirect containment (`api_request:213-214`): the bearer token is re-sent to
  whatever host a 3xx points at, and a 301/302/303 on the sync leg audits as SUCCESS.**
  `urllib.request.urlopen` with the default opener follows redirects and copies the
  `Authorization` header to the new target. Stub proof (front door → separate-origin login
  origin, both recorded): the list leg on **307/301/302/303** all landed at the login origin
  carrying `Bearer eyJ…CROSSTOKENxKq`; and with the sync POST answered 301/302/303, urllib
  converted POST→GET, followed, got a 200 HTML page, and the run audited
  `target=proxy-local result=ok … detail=root synced, 0 children synced` with **no sync
  performed** — a false green in the one channel operators trust (`result=ok`). Today's live
  shapes: `https://cluster.proxy-local.spencerslab.com/api/v1/applications` answers **307 →
  `login.spencerslab.com/realms/SpencersLab/…`** even with a bearer header present
  (curl, re-measured in this review), while the other 10 hosts answer 401/timeout — so
  proxy-local is the target that will actually 3xx from the runner, and its mcp-bot token goes
  to the SSO edge on every push (307 is followed on GET; for POST urllib does NOT follow 307, so
  that leg honestly audits `sync HTTP 307`). Inherited byte-for-byte from `main.py`'s
  `api_request`, but the vantage changed: the relay dialed mesh hosts, the fan-out dials
  SSO-fronted public routes. Fix (small, and it makes the posture strictly more honest, not
  less): build a no-follow opener —
  `class _NoRedirect(urlrequest.HTTPRedirectHandler): redirect_request = staticmethod(lambda *a: None)`
  / `urlrequest.build_opener(_NoRedirect).open(...)` — so any 3xx surfaces as
  `applications list HTTP 307` / `sync HTTP 307` in the existing `failed` lanes, no token ever
  leaves the rostered origin, and the `result=ok` channel can no longer be earned by an HTML
  page. Coordinate with the test session for a 3xx arm; and see Deferred: the route itself may
  need an owner call.

### minor

- **m1 — the all-skipped `::warning::` is emitted mid-line, so the runner never makes it an
  annotation (`argocd-fanout.py:347` via `log()` at 59-60).** `log()` prefixes
  `time.strftime(...)`, so the row reaches the job log as `<ts> ::warning::all N targets
  skipped — …`, and the command grammar is line-anchored: the act-lineage runner source read in
  this review (`act/runner/command.go`, gitea mirror, commit 12dc9d26a2) compiles
  `commandPatternGA = "^::([^ ]+?)( (.+?))?::([^\r\n]*)[\r\n]*$"`, and GitHub's runner issue
  #4692 frames the expectation as "`::command::` … recognised only at the start of a line". The
  trap sentence IS in the log (readable, greppable — not silence), which is why this is minor
  rather than major, and the repo already treats `::warning::` as job-log legibility rather than
  a UI-chip claim (`tests/services/forgejo-containers-build.sh:1045`). But every shipped
  annotation in this repo is printed at column 0 (`main-sync.yaml:111,146-147`,
  `forgejo-container-detect.sh:60`), so the one-line fix — `print("::warning::…", flush=True)`
  instead of `log(...)` — costs nothing and restores the announced-ness AC10 was written for.
  t11's substring grep passes either way, so it is coord's/owner's call whether to require it.
- **m2 — `allowed_refs: []` is a legal roster that silently disables everything
  (`load_roster:77-84` + gate `main:394-398`).** `all()` over an empty list passes, then every
  push hits the gate line and exits 0 with zero dials — proven (`EMPTY allowed_refs []: rc=0
  dials=0`). main.py defaulted an empty/absent list to `["refs/heads/main"]`
  (`validate_config:103-104`); the port dropped the default but kept presence-only validation,
  turning a roster typo into exactly the permanent silent no-op the exit-posture doctrine goes
  RED for. Fix: `if not refs: raise ConfigError("allowed_refs must list at least one full ref")`.
- **m3 — unknown top-level roster keys are accepted (`load_roster:73-75` checks only
  `ROSTER_KEYS - set(raw)`).** Proven: a roster carrying `clusterHosts` and `tokenKey` (the
  relay-era keys the disposal wave is supposed to retire) parses and prints `--check: OK`. The
  per-target branch right below (102) DOES reject extras (`set(t) != {…}`) — the asymmetry is
  the tell. Fix: reject `set(raw) - ROSTER_KEYS` too, so a C06/C07 leftover can't linger green.
