# C05: charts/forgejo-run-watchdog — schedule-failure watchdog (DEFERRABLE)
size: M   wave: 3   depends_on: [C04]

## Goal

Close the runner route's one genuinely worse-than-CronJob property: schedule
triggers are the fragile leg of Actions-type systems (silent-disable class,
RESEARCH-forgejo-runner §1.1). A small home-cluster CronJob checks that the
site repo's workflows keep succeeding and notifies when they don't. Research
implication 6: "the watchdog is part of the plan." DEFERRABLE: the owner may
cut this chunk at plan approval without affecting the pipeline; everything
else ships unchanged.

## Behavior contract

- Hourly CronJob (`concurrencyPolicy: Forbid`), image pinned
  `docker.io/curlimages/curl:<tag>` (renovate), script via ConfigMap:
  1. Freshness check, in preference order:
     a. Forgejo runs API: `GET {forgejoUrl}/api/v1/repos/{owner}/{repo}/actions/runs`
        (PAT from the SAME `cf-sync-forgejo` Bitwarden item as C04 —
        `write:repository` covers reads) → newest successful run of the sync
        workflow within `watchdog.maxAgeHours` (default 2 = 2× hourly cadence;
        value-tunable).
     b. FALLBACK (if the runs endpoint 404s — run-list API may need Forgejo
        ≥v16; target instance version unverified): Netlify deploys API
        `GET https://api.netlify.com/api/v1/sites/{siteId}/deploys` with the
        NETLIFY token (same items as C04) → newest `ready` deploy within
        `watchdog.maxAgeDays` (default 2 — prod cadence is merge-driven, so
        this leg is a liveness floor, not a freshness promise).
  2. Stale → notify: `POST {watchdog.notify.url}` with a JSON body (run name,
     last-success age, pointer to Actions UI). Channel is a VALUE, not a
     hardcode: BG = Home Assistant REST webhook/notify endpoint — note HA is
     deployed from services/grow (cross-cluster from home), so the owner points
     the URL at whatever receiver they prefer (HA/n8n/gotify/ntfy). Optional
     bearer via a Bitwarden item ONLY if the receiver needs it (skip the item
     otherwise).
  3. Healthy → exit 0 silent. One alert per stale window (state file on the
     pod's emptyDir is fine — re-alerting hourly while stale is acceptable and
     simpler; values comment says so).
- Same chart conventions as C04: drop-ALL, reloader, no ingress, version 1.0.0,
  wiring into services/home + custom-values/home (bitwardenIds reuse C04's
  items — `forgejo-pat` + `netlify`; NO new mandatory items).
