# C01: Immich sync + Forgejo publish tooling — albums INTO existing pages, additive-only
size: M   wave: 1   depends_on: []

## Goal

The core logic of the pipeline, implemented as two dependency-free Python
modules in `containers/forgejo-host-runner/` (directory name = image name,
plan-locked). Owner answer 9 pivots the seam: an allowlisted album maps INTO
an EXISTING page bundle — sync writes gallery-name-sortable derivative files
there, additive-only, never destructively editing anything that already
exists. `forgejo_publish` keeps the single-PR mechanics. Card #11's E2E is
fixture-based (fake Immich server in tests — DECISIONS R2), because the real
Immich API is unreachable from this ticket's dev/gpu position (card #88 owns
the network path).

## Allowlist schema (`sync-albums.yaml`, shipped by C06; read by this tool)

```yaml
albums:
  - name: "Aeroponics Current"            # Immich album name (exact)
    page: plants/aeroponics/current-grows # bundle dir relative to content/ (PRIMARY)
    prefix: ""                            # optional filename prefix (see Glob fit)
  - name: "Web Only Shots"                # no `page:` → OPTIONAL secondary posture:
    slug: web-shots                       #   creates content/photos/<slug>/
```

## Contract (C06 depends on exactly this)

**Entry points** (installed by C02 to `/usr/local/bin/`):
- `immich-hugo-sync` → `sync/immich_sync.py main()`
- `immich-hugo-publish` → `sync/forgejo_publish.py main()`

**immich-hugo-sync env config** (CLI flags mirror every env var; flags win):
`IMMICH_URL` (req), `IMMICH_API_KEY` (req), `SITE_DIR` (req; repo checkout
root), `ALBUMS_FILE` (path to the allowlist), `ALBUMS` (optional
comma-separated name override = dispatch input; entries not in the file error
loud), `FORCE` (`true` re-syncs unchanged albums), `STATE_DIR` (default
`/data/state`; state file `curatedforest-sync.json`), `PHOTOS_SECTION`
(default `photos` — secondary posture root).

**Behavior:**
1. Selection: resolve allowlist names → albums via `GET /albums?isOwned=true`
   (paginate; exact name match). Unresolved name = error naming the album.
2. Probe: per album compare `lastModifiedAssetTimestamp` against state; skip
   unchanged unless FORCE.
3. Target resolution (per entry):
   - `page:` → bundle dir `SITE_DIR/content/<page>` MUST exist and contain
     `index.md` or `_index.md` — else loud error (never create human pages).
   - no `page:` → `SITE_DIR/content/<PHOTOS_SECTION>/<slug>/` (created on
     demand, machine-owned; section `_index.md` created machine-owned
     draft:true if absent — the ONLY files sync may create fresh besides
     derivative images).
4. Pull: changed albums → `POST /search/metadata {albumIds:[id], type:"IMAGE"}`
   (paginate); target file name per asset:
   `{prefix?}{YYYYMMDD}-{HHMMSS}_{checksum8}_{safeOriginal}.jpg` — prefix
   + `-` when set; date/time from the asset's local capture time (DTO field
   fallback chain), `checksum8` = first 8 hex of `AssetResponseDto.checksum`
   (base64→hex), `safeOriginal` = original basename ASCII-folded,
   non-`[A-Za-z0-9._-]`→`_`, lowercased, extension forced `.jpg`.
5. Glob fit (answer 9 key correctness; N2): parse the target page's
   `{{< gallery ... >}}` call(s) (regex over the md file). For each call with
   a `match`/glob arg, check that the prospective filenames satisfy ≥1 glob
   (no-glob call = `.ByType "image"` → always fits). If NO call would include
   the files → REFUSE the album with a loud error naming the globs (never
   write invisible files). Multiple gallery calls: a file included by any call
   is fine.
6. Write: download missing derivatives (`GET /assets/{id}/thumbnail?size=preview`,
   streaming temp→rename); existing files (same name) never re-downloaded,
   never overwritten.
7. Removals (album shrinkage): ONLY files sync itself wrote — the deletion set
   is the state-recorded machine file list minus the current asset set. State
   lost → NO deletions (additive-only floor). Never pattern-infer deletions.
8. Front matter (N1 BG policy): existing target pages → append-only machine
   marker keys if absent (`immich_synced: {albums: [...], at: <date>}`);
   NEVER modify/delete any existing key, never set/flip `draft`,
   `author_reviewed`, `editor_reviewed` on existing pages (adding draft:true
   would un-publish = destructive); body untouched. Machine-created pages
   (secondary posture) → full machine front matter: title/date/weight/`type:
   docs`/`draft: true`/`author_reviewed: false`/`editor_reviewed: false` +
   body = album description + `{{< gallery sort="desc" >}}`; create-once,
   never modified afterwards.
9. Slug/path stability: state maps albumId → resolved target path (renamed
   albums keep their target).
10. State file JSON `{albums: {<id>: {target, slug, lastModified, lastSync,
    files: [...]}}}` written atomically (tmp+rename). `files` is the machine
    file ledger (drives #7). Corrupt/missing state → full re-probe, no
    deletions (checksum naming keeps re-runs diff-empty).
11. Exit signal: `changed`/`unchanged` to `$OUTPUT_FLAG` when set; summary
    line `SYNC_RESULT albums=<n> added=<n> removed=<n> changed=yes|no`;
    exit 0 on success, non-zero on error.

**HARD GUARDS** (generalized, each test-covered):
- NEVER modify, move, or delete any existing non-machine file (content,
  config, templates — all of it); machine files = files in the state ledger
  (or machine-created pages per #8).
- NEVER writes outside `SITE_DIR/content/`; NEVER edits hugo.yaml, layouts,
  netlify.toml, .gitattributes, .forgejo (path-normalization enforced).
- The two manual derivatives in `current-grows` (and everything human) are
  protected by the ledger rule — no special-casing needed, test asserts.
- Albums with zero IMAGE assets skipped (no empty writes).

**immich-hugo-publish** — unchanged from the approved plan: `SITE_DIR`,
`BRANCH` (default `immich-sync`), `FORGEJO_URL`, `FORGEJO_REPO` (`owner/name`
— owner = the Forgejo org per answer 6), `FORGEJO_PAT`, `PR_TITLE`/`PR_BODY`
(+ `SUMMARY`), `GIT_IDENTITY_NAME`/`_EMAIL`. Idempotent create-or-update of
ONE PR: `git checkout -B <branch>` → `git add content/` → commit (nothing
staged → exit `unchanged`, no push) → `git push -f origin <branch>`
(bot-owned branch, force-push exempt — answer 4) → Forgejo API: open PR with
head=<branch> exists → update body, else create. Print `PR_URL=...`.

**Shared HTTP layer:** stdlib `urllib`, injectable transport for tests,
`x-api-key` for Immich, `Authorization: token <PAT>` for Forgejo, timeout +
one 5xx retry. PLUS a `FakeImmichServer` test double (stdlib http.server)
serving fixture album/search/thumbnail responses — the fixture-E2E spine.

## Acceptance criteria

1. `python3 -m pytest containers/forgejo-host-runner/tests/ -v` all pass,
   including the fixture E2E (fake Immich → scratch site replica → gallery
   inclusion asserted).
2. Stdlib only; no network in any test (fake server is localhost-bound or a
   pure transport fake).
3. Every HARD GUARD has a dedicated test; the generalized no-destructive-edit
   guard proven on a fixture bundle containing human files + manual
   derivative-shaped files.
4. Glob-fit refusal fires (loud, non-zero) for a semantic-glob page when the
   names don't match, and passes with a fitting `prefix`.
5. Re-run idempotency: second run = `changed=no`.
6. No file outside `containers/forgejo-host-runner/` touched; aislop +
   comment-slop clean.

## Tests (agent-test writes, review runs)

pytest, fixtures + FakeImmichServer (NO network):
- t1 naming: checksum8 (base64→hex), capture-time date, safeOriginal
  sanitization, prefix assembly (`prefix-date-time_checksum_name.jpg`).
- t2 selection/allowlist: name resolution, unresolved → non-zero naming it,
  `ALBUMS` override, page-less entries route to the photos posture.
- t3 probe/skip: lastModifiedTimestamp skip; FORCE bypass.
- t4 pagination: multi-page search fully fetched.
- t5 additive writer: missing derivative fetched (temp→rename); existing file
  untouched (byte-compare); no overwrites ever.
- t6 target resolution: `page:` must exist with index/_index (loud error
  otherwise); machine photos bundles created only for page-less entries.
- t7 glob fit: no-glob page → fits; jpg-case-glob page → fits; semantic-glob
  page without fitting prefix → REFUSED naming the globs; with fitting prefix
  → written and matched.
- t8 removals: ledger-recorded file absent from album → deleted; human files
  and non-ledger machine-shaped files NEVER deleted; state lost → zero
  deletions.
- t9 front-matter policy (N1 BG): existing page gets append-only
  `immich_synced` marker; every pre-existing key byte-identical; draft/
  author_reviewed/editor_reviewed never set on existing pages; machine page
  (secondary posture) created once with full machine front matter, untouched
  on re-run.
- t10 guards: writes outside content/ rejected (incl. `../`); hugo.yaml/
  layouts/.forgejo byte-identical after a full sync over a fixture repo.
- t11 publish: branch reset+commit; nothing staged → `unchanged` no push;
  PR created when absent / body updated when present (single-PR invariant);
  force-push used; auth header shape.
- t12 HTTP layer: 5xx single retry; 4xx clean error.
- t13 FIXTURE E2E: scratch replica of the real site shape (no-glob
  sort=desc bundle + semantic-glob bundle + draft stub) × FakeImmichServer
  serving two albums (one mapped, one page-less) → run sync end-to-end:
  files land in the right bundles, gallery inclusion regex-proven on the
  rendered-or-source contract, PR step stubbed at the git boundary; second
  run `changed=no`.
