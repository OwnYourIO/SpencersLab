# C01: Immich sync + Forgejo publish tooling (Python stdlib, baked into the runner image)
size: M   wave: 1   depends_on: []

## Goal

The core logic of the pipeline, implemented as two dependency-free Python
modules in `containers/forgejo-host-runner/` (directory name = image name,
plan-locked): `immich_sync` pulls Immich v3 preview derivatives into Hugo page
bundles under `content/photos/`, and `forgejo_publish` does the git/PR
mechanics. C02 packages them into the runner image; C06's workflows call them.
SpencersLab is the machinery home (research round-4 placement; testability in
agent sessions) — the site repo holds workflows + content only.

## Contract (C06 depends on exactly this)

**Entry points** (installed by C02 to `/usr/local/bin/`, importable as modules):
- `immich-hugo-sync` → `sync/immich_sync.py main()`
- `immich-hugo-publish` → `sync/forgejo_publish.py main()`

**immich-hugo-sync env config** (CLI flags mirror every env var; flags win):
`IMMICH_URL` (req), `IMMICH_API_KEY` (req), `SITE_DIR` (req; repo checkout
root), `ALBUMS_FILE` (optional path to YAML allowlist; shape:
`albums: [{name: "...", slug: "...optional..."}, ...]` — plain list entries
`- Album Name` also accepted), `ALBUMS` (optional comma-separated override,
workflow_dispatch input), `FORCE` (`true` re-syncs unchanged albums),
`STATE_DIR` (default `/data/state`; state file `curatedforest-sync.json`),
`OUTPUT_SECTION` (default `photos`).

**Behavior:**
1. Selection: resolve allowlist names → albums via `GET /albums?isOwned=true`
   (paginate; exact name match). Unresolved name = error with the name in the
   message (fail loud).
2. Probe: per album compare `lastModifiedAssetTimestamp` against state; skip
   unchanged unless FORCE.
3. Pull: changed albums → `POST /search/metadata {albumIds:[id], type:"IMAGE"}`
   (paginate `page`/`size`); per asset target name
   `{YYYYMMDD}-{HHMMSS}_{checksum8}_{safeOriginal}.jpg` where date/time come
   from the asset's local capture time (fall back to fileCreatedAt/mtime field
   present in the DTO), `checksum8` = first 8 hex chars of
   `AssetResponseDto.checksum` (base64→hex normalized), `safeOriginal` =
   original filename basename, ASCII-folded, non-`[A-Za-z0-9._-]`→`_`,
   lowercased, extension forced `.jpg` (previews are JPEG).
   Missing file in `SITE_DIR/content/<section>/<slug>/` → download
   `GET /assets/{id}/thumbnail?size=preview` (streaming write to temp then
   rename).
4. Reconcile removals: inside each managed bundle delete ONLY files matching
   `^\d{8}-\d{6}_[0-9a-f]{8}_.+\.jpg$` that are no longer in the album's
   current asset set. Never delete anything else.
5. `index.md` CREATE-ONCE: written only if absent, front matter
   `title` = album name, `date` = album startDate (or oldest asset date),
   `weight` = (allowlist index + 1) * 10, `type: docs`, `draft: true`,
   `author_reviewed: false`, `editor_reviewed: false`; body = album
   description (if any) + `{{< gallery sort="desc" >}}`. NEVER modified
   afterwards (human gate protection).
6. Slug stability: state maps albumId → slug (slug = allowlist override or
   slugified name: lowercase, non-alnum→`-`, trimmed, collapsed). Renamed
   albums keep their slug from state.
7. State file JSON `{albums: {<id>: {slug, lastModified, lastSync}}}` written
   atomically (tmp+rename). Missing/corrupt state → full re-probe (safe:
   checksum naming makes re-runs diff-empty).
8. Exit signal: writes `changed`/`unchanged` to `$OUTPUT_FLAG` file when the
   env var is set, prints a machine-parseable summary line
   `SYNC_RESULT albums=<n> added=<n> removed=<n> changed=yes|no`; exit 0 on
   success either way, non-zero on error.

**HARD GUARDS** (each covered by a test):
- Writes/deletes ONLY under `SITE_DIR/content/<OUTPUT_SECTION>/`.
- NEVER touches `content/plants/**` (protects the two manual derivatives and
  all hand-curated bundles) — path normalization required (no `../` escape).
- NEVER modifies an existing `index.md` or any non-machine-named file.
- Albums with zero IMAGE assets are skipped (no empty bundles).

**immich-hugo-publish env config:** `SITE_DIR` (req), `BRANCH` (default
`immich-sync`), `FORGEJO_URL` (req), `FORGEJO_REPO` (req, `owner/name`),
`FORGEJO_PAT` (req), `PR_TITLE`/`PR_BODY` (defaults incl. the sync summary
passed via `SUMMARY` env), `GIT_IDENTITY_NAME`/`_EMAIL` (defaults
`Immich Sync Bot` / `immich-sync@curatedforest.local`).

**Behavior:** idempotent create-or-update of ONE PR:
`git checkout -B <branch>` → `git add content/<section>` (LFS filter already
installed by the workflow; new JPEGs pass through `filter=lfs` clean) →
commit (skip commit + exit `unchanged` when nothing staged) →
`git push -f origin <branch>` (machine branch; plan-locked force-push
exception, DECISIONS) → Forgejo API with PAT: list open PRs with
head=<branch> (`GET /repos/{o}/{r}/pulls?...`), create if none
(`POST /repos/{o}/{r}/pulls` with body = summary), else update body
(`PATCH`). Single-PR invariant by construction. Print `PR_URL=...`.

**Shared HTTP layer:** one small client (stdlib `urllib`) with injectable
transport for tests (`Api(transport=...)`), `x-api-key` header for Immich,
`Authorization: token <PAT>` for Forgejo, timeouts + one retry on 5xx.

  never written (fixture with a plants dir stays byte-identical); existing
  `index.md` never modified even when album metadata changes.
- t8 index.md: created with exact front-matter contract (draft:true,
  author_reviewed:false, editor_reviewed:false, type docs, weight formula);
  body has `{{< gallery sort="desc" >}}`; create-once.
- t9 slug stability: renamed album keeps state slug; empty IMAGE album skipped.
- t10 state: atomic write; corrupt state → full re-probe no crash; re-run
  idempotent (`changed=no`).
- t11 publish: branch create/reset + commit; nothing staged → exit
  `unchanged` no push; PR created when none open; PR body updated when one
  exists (single-PR invariant); auth header shape; force-push used.
- t12 HTTP layer: 5xx single retry; non-retryable 4xx → clean error.
