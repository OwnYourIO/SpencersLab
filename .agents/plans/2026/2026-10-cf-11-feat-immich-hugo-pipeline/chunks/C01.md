# C01: Immich sync + Forgejo publish tooling — albums INTO existing pages, machine-marked gallery integration
size: M   wave: 1   depends_on: []

## Goal

The core logic of the pipeline, implemented as two dependency-free Python
modules in `containers/forgejo-host-runner/` (directory name = image name,
plan-locked). Owner answers 9+N2+N3 pin the seam: every allowlisted album
maps into an EXISTING page bundle (`page:` REQUIRED — no fallback posture);
sync writes gallery-name-sortable derivative files and, where the page's
existing gallery call(s) would not include them, extends the page with a
machine-marked gallery call (owner override N2 — auto-extend, not refuse).
Front-matter markers are append-only (N1 as-recommended). `forgejo_publish`
keeps the single-PR mechanics. Card #11's E2E is fixture-based (fake Immich
server in tests — DECISIONS R2), because the real Immich API is unreachable
from this ticket's dev/gpu position (card #88 owns the network path).

## Allowlist schema (`sync-albums.yaml`, shipped by C06; read by this tool)

```yaml
albums:
  - name: "Aeroponics Current"            # Immich album name (exact)
    page: plants/aeroponics/current-grows # REQUIRED: bundle dir relative to content/
    prefix: ""                            # optional: fit an authored gallery glob
```
`page:` is REQUIRED on every entry (N3) — an entry without it is a loud
schema error naming the entry. There is NO content/photos/ fallback posture.

## Contract (C06 depends on exactly this)

**Entry points** (installed by C02 to `/usr/local/bin/`):
- `immich-hugo-sync` → `sync/immich_sync.py main()`
- `immich-hugo-publish` → `sync/forgejo_publish.py main()`

**immich-hugo-sync env config** (CLI flags mirror every env var; flags win):
`IMMICH_URL` (req), `IMMICH_API_KEY` (req), `SITE_DIR` (req; repo checkout
root), `ALBUMS_FILE` (path to the allowlist), `ALBUMS` (optional
comma-separated name override = dispatch input; entries not in the file error
loud), `FORCE` (`true` re-syncs unchanged albums), `STATE_DIR` (default
`/data/state`; state file `curatedforest-sync.json`).

**Behavior:**
1. Selection: validate the allowlist FIRST (missing `page:` / missing `name:`
   → non-zero exit naming the entry); resolve names → albums via
   `GET /albums?isOwned=true` (paginate; exact name match). Unresolved album
   name = error naming it (fail loud).
2. Probe: per album compare `lastModifiedAssetTimestamp` against state; skip
   unchanged unless FORCE.
3. Target resolution: bundle dir `SITE_DIR/content/<page>` MUST exist and
   contain `index.md` or `_index.md` — else loud error (never create pages).
4. Pull: changed albums → `POST /search/metadata {albumIds:[id], type:"IMAGE"}`
   (paginate); base file name per asset
   `{YYYYMMDD}-{HHMMSS}_{checksum8}_{safeOriginal}.jpg` — date/time from the
   asset's local capture time (DTO field fallback chain), `checksum8` = first
   8 hex of `AssetResponseDto.checksum` (base64→hex), `safeOriginal` =
   original basename ASCII-folded, non-`[A-Za-z0-9._-]`→`_`, lowercased,
   extension forced `.jpg`.
5. Gallery integration — THREE outcomes, checked in order (N2 pinned shape):
   - **auto-included**: any gallery call on the page has no `match` arg
     (`.ByType "image"` takes everything) OR the prospective filenames
     (incl. an allowlist `prefix:`) satisfy an existing call's glob → files
     land UNPREFIXED (chronological inside the authored Name-sort); NO page
     edit.
   - **machine-marked call**: nothing would include the files → sync manages
     its own block on that page, EXACTLY this shape (pinned), one per
     (page, album), appended after the file's last line:
     ```
     <!-- immich-sync:album="<Album Name>" slug=<albumslug> -->
     {{< gallery match="sync-<albumslug>-*" sort="desc" >}}
     <!-- immich-sync:end:<albumslug> -->
     ```
     and this album's files carry the matching prefix:
     `sync-<albumslug>-{YYYYMMDD}-{HHMMSS}_{checksum8}_{safe}.jpg`
     (fixed prefix → chronological WITHIN the machine call; albumslug =
     slugified album name, stable via state). Authored calls are NEVER
     rewritten — the only body edit is this machine block.
   - **block lifecycle (idempotent, N2-a)**: blocks are recognized by their
     markers; re-runs update in place, never stack; if integration becomes
     auto-included later (owner edited the page), sync REMOVES its own block
     and renames its own prefixed files to unprefixed via ledger ops
     (machine content managed by the machine; nothing human touched).
   - Allowlist `prefix:` stays available for the owner who wants files inside
     an AUTHORED glob (zero-edit path) instead of a machine block.
6. Write: download missing derivatives (`GET /assets/{id}/thumbnail?size=preview`,
   streaming temp→rename); existing files (same name) never re-downloaded,
   never overwritten.
7. Removals (album shrinkage): ONLY files sync itself wrote — the deletion set
   is the state-recorded machine file ledger minus the current asset set.
   State lost → NO deletions (additive-only floor). Never pattern-infer.
8. Front matter (N1 as-recommended): existing target pages → append-only
   machine marker keys if absent (`immich_synced: {albums: [...], at:
   <date>}`); NEVER modify/delete any existing key, never set/flip `draft`,
   `author_reviewed`, `editor_reviewed` on existing pages (draft:true would
   un-publish = destructive); page body untouched except §5 machine blocks.
   The gate for photos added to published pages = the PR + farm preview.
9. Slug/path stability: state maps albumId → resolved target path + albumslug
   + integration mode + machine file ledger (renamed albums keep their target).
10. State file JSON written atomically (tmp+rename). Corrupt/missing state →
    full re-probe, no deletions, blocks re-recognized by markers (checksum
    naming keeps re-runs diff-empty).
11. Exit signal: `changed`/`unchanged` to `$OUTPUT_FLAG` when set; summary
    line `SYNC_RESULT albums=<n> added=<n> removed=<n> blocks=<n>
    changed=yes|no`; exit 0 on success, non-zero on error.

**HARD GUARDS** (generalized; permitted edits enumerated, everything else
forbidden — each test-covered):
- Permitted edits to existing files: (a) append-only `immich_synced`
  front-matter marker keys, (b) machine-marked gallery blocks (§5 — add/
  update/remove sync's OWN blocks only). NOTHING else.
- Machine files = ledger-recorded files (incl. renames on mode transitions).
- NEVER writes outside `SITE_DIR/content/`; NEVER edits hugo.yaml, layouts,
  netlify.toml, .gitattributes, .forgejo (path normalization enforced).
- The two manual derivatives in `current-grows` (and everything human) are
  protected by the ledger rule — no special-casing; test asserts.
- Albums with zero IMAGE assets skipped.

**immich-hugo-publish** — unchanged: `SITE_DIR`, `BRANCH` (default
`immich-sync`), `FORGEJO_URL`, `FORGEJO_REPO` (`owner/name` — owner = the
Forgejo org per answer 6), `FORGEJO_PAT`, `PR_TITLE`/`PR_BODY` (+ `SUMMARY`),
`GIT_IDENTITY_NAME`/`_EMAIL`. Idempotent create-or-update of ONE PR:
`git checkout -B <branch>` → `git add content/` → commit (nothing staged →
exit `unchanged`, no push) → `git push -f origin <branch>` (bot-owned branch,
force-push exempt — answer 4) → Forgejo API: open PR with head=<branch>
exists → update body, else create. Print `PR_URL=...`. Every gallery-block
edit lands in this same PR → farm preview shows it (N2-c).

**Shared HTTP layer:** stdlib `urllib`, injectable transport for tests,
`x-api-key` for Immich, `Authorization: token <PAT>` for Forgejo, timeout +
one 5xx retry. PLUS a `FakeImmichServer` test double (stdlib http.server)
serving fixture album/search/thumbnail responses — the fixture-E2E spine.

## Notes for dev

- v3 shapes per RESEARCH.md R2.3 + RESEARCH-curatedforest-repo.md [29]; never
  `size=original` (deprecated). `checksum` is base64 → hex via b64decode.
- Gallery-call parsing is a best-effort regex over `{{< gallery ... >}}`
  (documented limitation: multi-line/exotic quoting unsupported → treat the
  page as no-fit and use the machine block; the block itself is written from
  scratch, never by mutating authored syntax).
- Hugo's `.Resources.Match` globs are the reference semantics for fit checks
  (the shortcode contract, RESEARCH-curatedforest-repo.md [8]).
- The fixture site replica under tests/fixtures/ is hand-built SMALL (tiny
  generated JPEGs, a handful of md files mirroring the real contracts incl.
  the two manual-derivative names and a six-glob page) — not a copy of the
  live repo.
- No docker anywhere; the image is C02. Real-Immich live E2E belongs to
  card #88's post-network-path validation, not this ticket.
