# C04: charts/forgejo-secret-seed — Bitwarden → Forgejo repo-secret seeder
size: M   wave: 1   depends_on: []

## Goal

Keep Bitwarden the single source of truth for the pipeline's Forgejo repo
secrets: a small home-cluster chart renders them via ExternalSecret and an
idempotent CronJob PUTs them to the Forgejo Actions secrets API
(`PUT /api/v1/repos/{owner}/{repo}/actions/secrets/{name}`). This satisfies
the ticket's secrets rule (ExternalSecret+Bitwarden for the Immich API key,
NETLIFY_AUTH_TOKEN + site ids, and the sync PAT) — research-forgejo-runner
§6.5/§8.4 recommendation; manual Forgejo-UI entry stays documented as the
break-glass fallback only.

## Secrets seeded (Forgejo repo-secret name ← Bitwarden source)

| Forgejo secret | Bitwarden item (owner creates) | store | property |
|---|---|---|---|
| `IMMICH_API_KEY` | `cf-sync-immich` | bitwarden-login | `password` |
| `NETLIFY_AUTH_TOKEN` | `cf-sync-netlify` | bitwarden-login | `password` |
| `NETLIFY_SITE_ID` (prod .com) | `cf-sync-netlify` | bitwarden-fields | field `site_id_com` |
| `NETLIFY_SITE_ID_FARM` (.farm) | `cf-sync-netlify` | bitwarden-fields | field `site_id_farm` |
| `FORGEJO_SYNC_PAT` | `cf-sync-forgejo` | bitwarden-login | `password` |

(Item/field shapes follow storage-and-secrets.md; the exact field names are
owner-visible and documented in the chart values comment.)

## Chart shape (charts/forgejo-secret-seed — new chart)

- `Chart.yaml`: version **1.0.0** (new-chart rule), app-template 5.0.1
  dependency (repo standard), `Chart.lock` committed.
- `values.yaml`: `bitwardenIds: {immich-api-key, netlify, forgejo-pat:
  OVERRIDE_VIA_CUSTOM_VALUES}`; `seed: {forgejoUrl, repoOwner, repoName}` —
  forgejoUrl BG `https://git.spencerslab.com`, repoOwner/repoName BG
  `CuratedForest`/`CuratedForest.com` (owner confirms; commented; these are
  config, not sentinels — they render as-is and are corrected post-confirmation).
- `templates/secret-forgejo-seed.yaml`: ONE ExternalSecret (engineVersion v2)
  with per-source `sourceRef` (bitwarden-login + bitwarden-fields in the same
  object — precedent `charts/immich-analyze` + `charts/archon`) rendering a
  Secret with keys `immich_api_key`, `netlify_auth_token`,
  `netlify_site_id`, `netlify_site_id_farm`, `forgejo_pat`.
- Controller: `type: cronjob` (precedent `charts/spotdl`): daily schedule,
  `concurrencyPolicy: Forbid`, `ttlSecondsAfterFinished`, `restartPolicy:
  OnFailure`, container = pinned `docker.io/curlimages/curl:<tag>` (renovate
  docker datasource), command = sh script from a ConfigMap (`templates/configmap-seed.sh`):
  for each (name, file): `curl -fsS -X PUT -H "Authorization: token $(cat
  /secrets/forgejo_pat)" -H 'Content-Type: application/json' --data-binary
  @<(jq-free static body built with printf) …` — NO jq needed (bodies are
  static `{"data":"<value>"}`; response code is the only check; Forgejo PUT
  is idempotent create-or-update). Secret mounted at `/secrets` (files).
  Non-zero exit on any failed PUT (visible in pod logs/events).
- Also reloader annotation; drop-ALL security context; no ingress (internal).
- Wiring: `services/home/prod/values.yaml` charts entry (+ top-level slice if
  seed values need per-release pinning) + `custom-values/home/prod-values.yaml`
  `forgejo-secret-seed: bitwardenIds: {…: OVERRIDE_NEEDED}` (owner pastes UUIDs
  after creating items).

## Notes for dev

- Forgejo secret API body shape (`{"data": "<value>"}` per v17 swagger [7] in
  RESEARCH-forgejo-runner) — dev re-verifies against the TARGET instance's
  swagger during live verification; if it differs, only the printf format
  strings change (test t3 pins the repo's expectation).
- The job needs egress to the Forgejo URL from the home cluster (BG via
  public host; if the owner's instance choice changes reachability, the URL
  value is the only edit).
- Rotation story: update Bitwarden → ExternalSecret refresh (1h) → next daily
  run re-PUTs. Documented in values comment; no extra machinery.
