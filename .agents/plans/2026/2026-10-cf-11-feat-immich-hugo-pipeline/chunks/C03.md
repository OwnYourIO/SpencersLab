# C03: charts/forgejo-runner host-backend mode + home cluster release wiring (forgejo-runner-cf)
size: L   wave: 1   depends_on: []

## Goal

Extend the EXISTING `charts/forgejo-runner` with a `runner.backend: docker|host`
toggle (default `docker` — the deployed dev release renders unchanged) and wire
a new host-backend release `forgejo-runner-cf` on the **home** cluster,
registered against the Forgejo instance the owner picks (URL is a values key;
BG `https://git.spencerslab.com` — Open question 1). Host mode = the locked
spine (DECISIONS: PVC-mounted runner, host backend, no privileged DinD): jobs
run as processes in the pod with the toolchain image, PVC holds workdir + act
cache + sync state.

## Chart changes (charts/forgejo-runner)

**values.yaml — new keys (all under existing `runner:`):**
- `runner.backend: docker` (default; dev release unchanged)
- `runner.labels:` (list, rendered into config.yaml) — docker default = the
  current hardcoded 5-label act set (moved from the template into values so
  the dev render is byte-identical); host releases override.
- Everything backend-conditional keys off `runner.backend`.

**values.yaml — app-template conditionals (docker-only today):**
- `initContainers.dind`, VCT `docker-data`, persistence `socket` (emptyDir),
  env `DOCKER_HOST`, `CREDENTIALS_DIRECTORY` stays both modes — each gated so
  host mode renders NONE of them.
- VCT `data`: docker 2Gi (unchanged); host release overrides size via its
  service slice to 20Gi (workdir + LFS checkouts + hugo cache + state).

**templates/secret-runner.yaml — config.yaml becomes backend-aware:**
- docker: exactly today's config (`container: {privileged: false}` + labels
  from values).
- host: no `container:` block; adds `host: {workdir_parent: /data/workdir}`
  and `cache: {enabled: true, dir: /data/cache}`; labels from values
  (host release: `["cf-host:host"]`).
- Everything else identical (capacity 1, timeout 30m, shutdown_timeout 5m,
  uuid/token_url/server.connections.default, release-named ExternalSecret).

**Image:** host release overrides the container image via its top-level slice
(`ghcr.io/ownyourio/forgejo-host-runner`, `tag: main`, `pullPolicy: Always` —
no pinned tag exists yet; pin `:v<run>` + renovate once CI publishes,
per image-tag rule). No probes on the runner container in either mode (no
health endpoint — verified against runner source by the predecessor ticket).

## Service wiring (home)

`services/home/prod/values.yaml`:
- `charts.forgejo-runner-cf: {namespace: default, ServerSideApply: "false", chart: forgejo-runner}`
- top-level slice (the appset merge flows ONLY top-level keys to the release):
  ```yaml
  forgejo-runner-cf:
    runner:
      url: https://git.spencerslab.com   # BG — owner confirms instance (Open Q1)
      backend: host
      labels: ["cf-host:host"]
    app-template:
      controllers:
        runner:
          statefulset:
            volumeClaimTemplates:
              - name: data
                accessMode: ReadWriteOnce
                size: 20Gi
                storageClass: local-path
                globalMounts: [{path: /data}]
          containers:
            runner:
              image: {repository: ghcr.io/ownyourio/forgejo-host-runner, tag: main, pullPolicy: Always}
  ```
  (exact nested merge shape verified against appset-charts.yaml semantics by
  the test script; if the appset merge cannot flow nested app-template keys,
  fall back to chart-level `runner.image*` values keys — dev decides, records.)
- Client-only: NO ingress.subdomains entry (copy the dev precedent comment).

`custom-values/home/prod-values.yaml`:
```yaml
forgejo-runner-cf:
  bitwardenIds:
    # Item home-forgejo-cf-runner (username=runner uuid, password=registration
    # token) — created at registration (owner action). NEVER forgejo-token.
    runner-token: OVERRIDE_NEEDED
```

## Acceptance criteria

1. `helm lint charts/forgejo-runner` + `helm template charts/forgejo-runner
   --set bitwardenIds.runner-token=<uuid>` pass (export PATH first).
2. Docker-mode render (dev-shaped values) is byte-identical to pre-change:
   `bash tests/services/dev-forgejo-runner.sh` green WITHOUT modification.
3. Host-mode render: no dind initContainer, no docker-data VCT, no socket
   emptyDir, no DOCKER_HOST, no `container:` block in config.yaml, has
   `host.workdir_parent: /data/workdir` + `cache.dir: /data/cache`, labels
   exactly `cf-host:host`, image = forgejo-host-runner:main.
4. Home umbrella renders with the new entry; sentinel sweep 1:1
   (`OVERRIDE_VIA_CUSTOM_VALUES` in service values ↔ key in custom-values/home;
   `OVERRIDE_NEEDED` only as documented user-fill).
5. No OVERRIDE_* sentinels in any rendered manifest.
6. No ingress/proxy entry for the runner (client-only assertion in the script).

## Notes for dev

- The top-level-slice merge mechanics are load-bearing (predecessor lesson:
  "appset merge flows ONLY top-level keys"). If deep app-template overrides
  don't flow, add `runner.image.repository/tag/pullPolicy` chart values and
  let the secret/values templates consume them — keep docker default = stock
  `data.forgejo.org/forgejo/runner:13.2.0` so dev stays unchanged.
- Home node capacity: hugo+netlify bursts (≈1 CPU / 1–2Gi) are modest; limits
  follow the existing chart (2 CPU / 4Gi).
- MTU risk (forgejo-runner#1779) applies to action clones in host mode too —
  mitigation is runtime (hostNetwork/MTU), not chart work; record in FRICTION
  if hit during live verification.
- Do NOT touch the dev release's values or the pending forgejo-runner-infra
  relocation surface.
