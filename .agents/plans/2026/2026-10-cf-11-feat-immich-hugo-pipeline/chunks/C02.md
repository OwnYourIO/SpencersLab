# C02: forgejo-host-runner toolchain image (runner + hugo + netlify-cli + git-lfs + sync tooling)
size: M   wave: 2   depends_on: [C01]

## Goal

`containers/forgejo-host-runner/Dockerfile` builds the ONE image the
host-backend runner pod runs as: Forgejo runner binary + everything a job
needs in host mode (git, git-lfs, curl, jq, zstd, python3, hugo extended
0.151.0 = the site's pinned version, node 22 for JS actions, netlify-cli) +
C01's sync/publish tooling. CI-primary build posture (no docker daemon in
agent sessions): `docker build => no-daemon, CI-deferred` is the designed
passing gate; build-critical facts verified from the pinned base images'
published manifests/layer listings.

## Image contract (C03 chart depends on these paths)

- `/bin/forgejo-runner` and `/usr/bin/dumb-init` present — the existing chart
  `command: [dumb-init, /bin/forgejo-runner, daemon, -c, /data/config/config.yaml]`
  stays valid for BOTH backends.
- `/usr/local/bin/hugo` — hugo **extended** `0.151.0` (matches site
  `netlify.toml` pin; verified local `hugo version` = 0.151.0+extended).
- `/usr/local/bin/netlify` — netlify-cli pinned version (Node ≥18.14 satisfied
  by node:22 base).
- `/usr/local/bin/immich-hugo-sync` + `/usr/local/bin/immich-hugo-publish` —
  wrappers over C01 modules (COPY `sync/` → `/opt/immich-hugo-sync/`).
- `git`, `git-lfs`, `curl`, `jq`, `zstd`, `python3` on PATH.
- `USER node` (uid 1000 — matches the chart's fsGroup 1000 convention and the
  upstream runner image's uid); `ENV HOME=/data` (act cache + dotfiles land on
  the PVC — chart comment contract).
- Non-root build stages keep writable dirs (HOME, /opt tooling) uid-1000-owned.

## Dockerfile shape (multi-stage)

```
# renovate: datasource=docker depName=forgejo/runner registryUrl=https://data.forgejo.org
FROM data.forgejo.org/forgejo/runner:13.2.1 AS runner-src   # binary donor only

FROM docker.io/library/node:22-bookworm-slim
ARG HUGO_VERSION=0.151.0
# renovate: datasource=github-releases depName=gohugoio/hugo
ARG NETLIFY_CLI_VERSION=<newest-published at build>
# renovate: datasource=npm depName=netlify-cli
  1) apt: git git-lfs curl jq zstd python3 ca-certificates dumb-init
     (+ rm -rf /var/lib/apt/lists/* same RUN)
  2) hugo extended linux-amd64 tarball → /usr/local/bin/hugo (checksum verify)
  3) npm install -g netlify-cli@${NETLIFY_CLI_VERSION}
  4) COPY --from=runner-src /bin/forgejo-runner /bin/forgejo-runner
  5) COPY sync/ /opt/immich-hugo-sync/ + wrapper scripts
  6) ENV HOME=/data; USER node; ENTRYPOINT ["/usr/bin/dumb-init","/bin/forgejo-runner","daemon"]
```

- No secrets in any layer; no `COPY . .` from repo root (build context is the
  container dir — workflow convention).
- `.dockerignore` excludes `tests/`.
- Renovate: FROM pins tracked by the built-in dockerfile manager; ARG pins via
  the repo's renovate-annotation convention (container-creation skill).
  Fallback note: if data.forgejo.org registry probing fails for renovate,
  leave a manual-pin comment + FRICTION entry.

  on git.scifi.farm); the gpu prod runner (card #88) reuses the same image —
  nothing in here is dev-specific.

  until the first pinned tag exists (image-tag-pinning rule).

  checksum verification).
