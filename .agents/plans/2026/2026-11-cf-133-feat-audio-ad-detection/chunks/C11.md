### Deferred (out of C11 scope — pre-existing, exposed by the first-ever
app execution)
**The `StopAsync`-without-`base` class leaves the `ExecuteAsync` token
uncancelled.** The independent smoke exposed `warn: broker run loop still
running 10s after stop` (the full `StopWait` consumed,
MqttPublisher.cs:148) with the broker absent. Mechanism, **empirically
confirmed on this SDK (10.0.404) by a minimal hosted-service probe**: a
derived `StopAsync` that does not call `base.StopAsync(cancellationToken)`
never cancels the token `BackgroundService` passes to `ExecuteAsync` —
the probe read `tokenCancelled=False` 500 ms into the host stop, and the
host stop still completed (504 ms) because it only awaits the override's
returned task, orphaning the ExecuteAsync loop until process exit.
`BrokerPublisher.StopAsync` (MqttPublisher.cs:143-151) is that shape;
its comments assert the opposite ("the loop then exits on the host stop
token"; `WaitSessionAsync` / `BackoffDelayAsync`: "host stop — the loop
exits on its ct check"). Consequences (observed case read-derived):
  - **Broker absent at stop** (the smoke, observed): the backoff path
    keeps the loop alive — the full 10 s `StopWait` is consumed, the
    warning fires, the loop is abandoned at process exit.
  - **Broker reachable at stop** (read-derived, same mechanism):
    `DisconnectAsync` ends the session wait, then `continue` re-enters
    `ConnectAsync` — the loop RECONNECTS to the live broker (its only
    exit is the never-cancelled token), blocks on the fresh session,
    and `OnConnectedAsync` re-publishes the retained `online` — so EVERY
    graceful shutdown burns the full 10 s of the 30 s K8s grace, logs
    the warning, blips the entity back to online for the seconds before
    process exit, and leaves the re-opened session to die abnormally
    (the LWT covers the offline).
`SnapClientSupervisor.StopAsync` (`:282`) is the same shape, but its
respawn loop is protected by the `_shutdownStarted` guard (set by
`ShutdownChildAsync`), so it breaks instead of respawning — protected
by the explicit flag, not the token. C11's ACs exclude this file ("no
other behavior changes; no other file touched") and the run was green
(exit 0, every T2 leg verbatim), so this is deferred, not a C11
objection. **Recommendation (open question to the coord):** a small
follow-up chunk — call `base.StopAsync(cancellationToken)` in both
overrides (or wire the supervisor loop to `_loopCts`) and fix the
comments that assert the uncancelled-token mechanism; the cycle-4 pod
restart exercises the real-broker path.
