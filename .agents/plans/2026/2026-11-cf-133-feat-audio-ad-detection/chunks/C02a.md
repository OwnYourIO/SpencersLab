# C02a: Fingerprint engine (resample → chunk → realtime query, Snapshot, RMS + last-match tracking)
size: M   wave: 2   depends_on: [C01]

## Goal
Turn C01's PCM pipe into exactly-10,240-sample @5512 mono chunks fed to an
`IRealtimeQueryCommand` over an `InMemoryModelService` loaded from / written
to the model dir, with per-chunk RMS and last-match tracking (the inputs
C02b's auto-capture consumes) and the metrics surface completed. Introduce the
`IAdEventSink` interface (C01 logs events; C03 adds the MQTT implementation).
The `seed`/`promote` CLI moves to C02b.

## Tasks
- [ ] Audio path: s16le→float (`v / 32768.0f`) + stereo→mono (`(L + R) * 0.5f`)
      per pipe read; resample to 5512 mono float via NAudio.Core 3.3.0
      low-level `NAudio.Dsp.WdlResampler` **only when the input rate ≠ 5512**
      (`SetRates(48000, 5512)`, `SetFeedMode(true)`, `SetMode(false, 0, true,
      64)` — Sinc64); the default `5512:16:*` lane is a pass-through (no
      resampler in the hot path). Do NOT use the 3.3.0 `WdlResamplingSampleProvider`
      wrapper (it is IIR-only with no quality selector — R3 §2)
- [ ] Per-chunk bookkeeping (C02b inputs): rolling RMS (dBFS) per 10,240-sample
      chunk exported as the `aad_audio_rms_db` gauge; last-confident-match
      timestamp + last matched track meta (the no-match span state C02b's
      capture state machine consumes — this chunk exposes it as
      `IStreamState`: `LastMatchAt`, `LastMatchMeta`, `CurrentRmsDb`)
- [ ] Chunking: accumulate exactly 10,240 resampled mono floats (1.8578 s) →
      `new AudioSamples(chunk, "", 5512)` → `BlockingCollection` →
      `BlockingRealtimeCollection` → `IRealtimeQueryCommand`. **No
      producer-side chunk overlap** (R1 implication 1 — the library's internal
      prefix handles FFT continuity); treat a supervisor respawn as a stream
      discontinuity (hot-source contract: re-enumeration resumes at the current
      position, never replays — R1 §1, R2 implication 5)
- [ ] Model service: `InMemoryModelService` loaded from `MODEL_DIR` at startup
      when the snapshot exists (restart = file load, not re-fingerprint — R1 §3);
      `Snapshot($MODEL_DIR)` on graceful shutdown (C03); the snapshot API is the
      directory form (verified in 17.4.0 source; 18.0.0 parity is the Post
      Research verification focus — plan risk note); the **empty-startup case is a
      working state** (auto-capture bootstrap: nothing matched yet — R1 caveat
      carried consciously)
- [ ] Realtime query config (SoundFingerprinting **18.0.0** pin, Q4):
      `SeamJumpPolicy.NewOccurrenceAbove($NEW_OCCURRENCE_ABOVE)` (default 120 —
      the library's own broadcast-agent value, R1 §1); a
      `QueryMatchLengthFilter` / `TrackCoverageLengthEntryFilter` at
      `COVERAGE_SECONDS` (default 5, the TVEyes 40%-coverage emission bar, R1 §2);
      `OngoingEntryStalenessCeiling` (default 120 s) so stale ongoing entries
      close promptly; `ad_detected` events emit on entries whose track meta says
      `kind=ad` (the ongoing filter feeds "what's playing" to the sink)
- [ ] `IAdEventSink` interface + a logging implementation (the only sink in this
      chunk); the awaited `SuccessCallback` calls the sink (backpressure is
      natural — the command awaits the callback's task before the next chunk —
      R1 implication 2); `OngoingCallback`/`ErrorCallback` wired (error logged
      after backoff)
- [ ] Metrics completion: `aad_capture_candidates_total` counter registered
      (C02b registers the auto-promotion counters on the same surface)

**Backpressure / memory math (verified):** pipeline queue 256 × 10,240 × 4 B = exactly 10.0 MiB = 475.6 s ≈ 476 s of 5512 mono; supervisor queue 256 × 65,536 B ≤ 16 MiB (≈761 s at 5512:16 stereo); both bounded, no unbounded growth. Backpressure chain: slow query → `AddAsync` blocks → pipeline stops draining the supervisor channel → `TryWrite` drops oldest (never blocks) → read loop keeps draining the kernel pipe → snapclient's writer is never blocked by worker queues (only by the 64 KiB kernel pipe, which resolves as silence-on-underrun per R2/R3 — "detection delay + brief source gaps, not silent data loss"). R3's tight-read-loop / hand-off-immediately contract holds.
