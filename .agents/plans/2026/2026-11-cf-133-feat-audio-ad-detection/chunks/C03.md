# C03: MQTT publisher + shutdown ordering + Snapshot on exit
size: M   wave: 2   depends_on: [C01]

## Goal
Publish ad events to Home Assistant over MQTT (MQTTnet 5.2.x): retained
device-discovery registration, never-retained event state, LWT + `expire_after`
liveness, availability; and the full graceful-shutdown ordering ending in
`Snapshot()` + exit 0.

## Tasks
- [ ] MQTT publisher (MQTTnet 5.2.0.1603): connect to `MQTT_BROKER_HOST:
      MQTT_BROKER_PORT` (default `home-mosquitto:1883`) **anonymous by default
      (Q1 verdict (a) confirmed)**; MQTT 5.0; clean session; reconnect with
      backoff; QoS 1; the optional `MQTT_USERNAME`/`MQTT_PASSWORD` code path
      (authenticate only when both are set) is retained so the recorded
      fallback (c) costs no code change — this run renders no credentials
      material anywhere (no ExternalSecret, no sentinels; plan's one-paragraph
      fallback)
- [ ] Device discovery (R4 §3 sample shape, retained, published once at
      startup after connect): `homeassistant/device/audio-ad-detector/config`
      with `dev` (ids/name/mf/mdl/sw), `o` (origin, required), `cmps`:
      - `p: "binary_sensor"`, `uniq_id: "ad_playing"`, `dev_cla: "sound"`
        (no `ad` class exists — R4 §3), `stat_t`, `av_t`, `exp_aft`
      - `p: "sensor"`, `uniq_id: "last_ad"`, `stat_t`, `av_t`, `exp_aft`
      - `p: "event"`, `uniq_id: "ad_event"`, `stat_t`,
        `evt_typ: ["ad_detected"]`, `av_t`, `exp_aft`
      (`exp_aft` default 300 s; the worker re-publishes the discovery payload
      on every connect so a broker restart re-registers)
- [ ] Liveness: LWT `offline` (retain, QoS 1) on `audio-ad-detector/lwt` set at
      connect; `online` published on connect; entity liveness via LWT +
      `expire_after` — **never silence-based** (R4 §3)
- [ ] Event publishing: **inside the awaited `SuccessCallback`** (via C02a's
      `IAdEventSink` implementation) — a never-retained JSON payload
      (`event_type: ad_detected` + track meta/attributes) to the event
      `stat_t`; the binary_sensor state topic tracks ad playing (on/off from
      match start/end); `last_ad` sensor = the last matched track meta
      (never retained). Event state messages must never be retained (R4 §3)
- [ ] `/readyz` extension: ready = C01 pipe-delivering + C02a model/query +
      MQTT connected
- [ ] Graceful shutdown (completing C01's SIGTERM handler): cancel the
      realtime query token → stop the read loop → SIGTERM the snapclient child
      (~5 s grace, then SIGKILL) **before closing the pipe read end** (avoids
      the SIGPIPE race — R3 implication 7) → MQTT graceful disconnect →
      `Snapshot($MODEL_DIR)` → exit 0. Everything lands well inside the 30 s
      K8s grace
