## Candidate weighing (recorded — the dev decides on this evidence)
- **(a) `ADD <url> /tmp/snapclient.deb`** — zero-binary; the repo's
  precedent (`okd-enketo`, built on this forge); ARG expansion in the ADD
  src is BuildKit-supported; the version-stable URL string (t3's `grep
  -qF` pin) stays byte-identical; the comment+ARG renovate pair untouched;
  hadolint `DL3020` (the "prefer COPY over ADD" warning) is warning-level
  and t9 runs at the **error** threshold — clean; the URL-ADD is the
  documented `ADD` use. Cost: the 592 KB deb persists as a layer (plain
  `docker build`, no squash; a later `RUN rm` cannot remove an ADD layer's
  file) — trivial at this image size.
- **(b) stage the fetch in the build stage** (has `wget`/`curl`, verified)
  — the final image stays clean, but a runtime OS asset lives in the SDK
  stage, the fetch egress couples to the publish cache, and the diff is
  larger (fetch RUN + `COPY --from=build` of the deb).
- **(c) apt-install `curl`, use it, purge** — defeats zero-binary (purged
  package files persist), and separate/multiple apt legs are a named
  antipattern in the skill's Antipatterns section; the most moving parts.
- **(d) `COPY --from=ghcr.io/curlimages/curl:8.14.1 --link /curl`** — a
  new tag-pinned `FROM` (off-idiom: forgejo-runner pins digests) = a new
  renovate-tracked surface + `--link` BuildKit-frontend machinery; more
  than (a) buys.
- **Planner's lean: (a)** — zero-binary, repo-precedented, minimal diff,
  every pin preserved. (b) is the fallback if (a) misbehaves on the forge
  runner (the `okd-enketo` precedent says it will not).
