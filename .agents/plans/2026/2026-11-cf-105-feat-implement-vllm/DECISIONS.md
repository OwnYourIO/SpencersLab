## Post Research decision note (2026-11-04 — RESEARCH.md Post Research, sources 140–156)

Verdict: `plan_impact: none` — the GDN-hybrid qwen3.8-27b family (`Qwen3_5ForConditionalGeneration`) is natively registered and fully implemented in vLLM v0.33.0 (in-tree since Feb 2026, ROCm-capable GDN kernel path), so **no locked decision is overturned: no pin bump, no model change, no weight-format change**. The verdict mandates three chunk-level corrections, applied in place to the approved chunk files (no re-chunking, `plan_status` unchanged):

1. **C01 — plugin pin = git ref + import patch.** The `vllm-gguf-plugin` pin cannot be a PyPI release: the newest release v0.0.5 (2026-08-10) has no Qwen3.5 GGUF adapter (PR #98 landed on main only, 2026-08-18), and plugin main (HEAD `e454affe0ca23c9dc8754ec3033270cb30622ed5`) is import-broken against the pinned base — it imports `vllm.transformers_utils.configs.qwen3_5`, a module vLLM removed in #60623 (2026-10-09), absent from v0.33.0 (raw-404 verified). C01 now: pin the plugin to a git ref (main ≥ that SHA, or the first future release carrying PR #98 + the import fix) via the in-repo git-refs ARG shape (renovate `git-refs` comment above the `ARG …=<sha>` line, `containers/gpt-researcher` precedent) with a `git+https://…@${REF}` pip install, PLUS the vendored 2-line import-compat patch (strata `carry/` carry-patch precedent) redirecting the plugin's config import to the layout vLLM #60623 introduced (configs now from `transformers`, as vLLM v0.33.0's own `models/qwen3_5.py` does); ref + patch recorded in the README ledger; AC#3 and test t5 updated to the git-ref form; the C06 step-3 import probe is the acceptance.
2. **C02 — `VLLM_SERVER_DEV_MODE: "1"` container env.** The vLLM `/sleep`, `/wake_up`, `/is_sleeping`, `/release_kv_cache_memory` HTTP endpoints are dev-gated in v0.33.0 (attached only when `envs.VLLM_SERVER_DEV_MODE` is true, default False) — without it HR6's operator time-sharing has no HTTP surface. Added to the env task, AC#2, and the test_render env-set assertion.
3. **C06 — on-target probe gates added to the runbook step groups:** (a) patched-plugin import probe (`python -c "import vllm_gguf_plugin"` in the C01 image) + GGUF serve + first token — the first engine gate (does the patched plugin load the qwen3_5 GGUF on gfx1201; no public RDNA run exists); (b) weight presence `find /models -name 'Qwen3.8-27B-UD-Q4_K_XL.gguf'`; (c) the sleep sequence `POST /sleep` → verify VRAM reclamation on the R9700 (documented ROCm caveat: unreclaimed VRAM at wake must coexist with the woken allocation — ~2× peak — and OOMs `cuMemCreate` at `gpu_memory_utilization` 0.95) → `POST /wake_up` → Strata re-pin; plus the image-side `rocminfo` gate (R9700 at ROCr index 0 under the v0.33.0-rocm100 image).
