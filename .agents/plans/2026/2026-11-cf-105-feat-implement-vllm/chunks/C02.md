size: L   wave: 1   depends_on: []

## Goal

The vLLM service on gpu-ai: a standalone bjw-s app-template chart (repo standard
app-template **5.0.1**) deploying one `vllm serve` container on the R9700 with the D4
engine recipe, warmup-sized probes, the D8 scrape annotations, the R5 access-log
suppression flag, the dev-mode sleep/wake env (D5 — `VLLM_SERVER_DEV_MODE`, the HTTP
surface behind the HR6 time-sharing discipline), and persistence (existing 500 GiB
`llama-swap` PVC read-only for weights + a small cache PVC). The gpu-ai ApplicationSet entry + `vllm:` values block go
in the same chunk (trio legs 1+3; leg 2 — the proxy entry — is deliberately skipped with
a ruling comment: internal-only, D7/Q4, strata precedent at
`services/gpu-ai/prod/values.yaml:45-50`). No secrets → no custom-values entry.

## Acceptance criteria

1. `helm lint charts/vllm` clean; `helm template` (chart-defaults render AND the
   service-level `-f` render) produces valid manifests with **no `OVERRIDE_*`
   sentinels** anywhere.
2. Rendered Deployment carries: every D4 serve arg (incl. `--scheduling-policy
   priority`, `--served-model-name qwen3.8-27b-vllm`, `--enforce-eager`,
   `--enable-sleep-mode` by default, the access-log suppression flag); the container
   env set — `ROCR_VISIBLE_DEVICES`, `TRITON_CACHE_DIR`, `HUGGINGFACE_HUB_CACHE`, and
   `VLLM_SERVER_DEV_MODE: "1"` (the dev-gated sleep/wake HTTP surface, REQUIRED
   alongside `--enable-sleep-mode`); containerPort
   named `http: 8000`; `hostIPC: true`; 8Gi Memory emptyDir; `amd.com/gpu: "1"` limit;
   the securityContext trio (Unconfined / runAsGroup 44 / SYS_PTRACE) +
   `allowPrivilegeEscalation: false`; **exactly two** `k8s.grafana.com/*` annotations
   (scrape + metrics.portNumber — and NO `metrics.scrapeInterval` key: the 60 s
   v4 feature default governs, Q5 ruling); startup probe failureThreshold ≥ 90 on
   `/health:8000`.
3. Service `gpu-ai-vllm`-shaped ClusterIP (release name `<cluster>-vllm`) with port 8000;
   peer-hop URL `http://gpu-ai-vllm.default.svc.cluster.local:8000` (no `/v1`) is the
   one C03 consumes.
4. Persistence renders: `models` → existingClaim `llama-swap` read-only at `/models`;
   `cache` → existingClaim `vllm-cache` at `/data`; the hand-written
   `pvc-vllm-cache.yaml` renders one RWO claim named `vllm-cache` with size from
   `cachePvcSize` (default 10Gi).
5. `services/gpu-ai/prod/values.yaml`: `charts.vllm` entry present with
   `namespace: default` + `ServerSideApply: "false"`; the `vllm:` block present;
   **no** `ingress.subdomains.vllm`; the skip-ruling comment present;
   `custom-values/gpu-ai/` and `services/gpu/` byte-unchanged.
6. Chart metadata: `version: 1.0.0` exactly; `Chart.lock` + vendored
   `charts/common-5.0.1.tgz` committed; image `tag: main` + `pullPolicy: Always` +
   PIN-ME comment (first `:v<run>` post-merge).
7. `.github/workflows/vllm-render-tests.yaml` exists with the trigger paths above and
   the exact CI step ladder; the workflow YAML parses (`python3 -c "import yaml,sys;
