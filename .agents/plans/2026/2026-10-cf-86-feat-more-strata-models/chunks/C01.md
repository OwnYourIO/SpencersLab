   `ghcr.io/ownyourio/strata`, built FROM
   `ghcr.io/niko1221/strata:0.2.7-rocm-gfx120x`, which upstream builds

   (`containers/strata/Dockerfile:59`), and its verify step pins exactly two
   init tools — `command -v git`, `command -v c++` (Dockerfile:88-89) — because
   "a missing tool fails the build, not the boot" (values.yaml:1096-1103).
   Nothing anywhere bakes or verifies `curl`, and no other step in the strata
   init has ever used it (setup downloads via Python urllib; the curl download
   pattern lives in the *llama-swap* image's init, a different base). Ubuntu's
   official image ships no curl, and `git` pulls only libcurl, not the CLI.
   Consequence at deploy: `abl_pack` reaches `abl_dl`, the shell reports
   `curl: not found`, `fail` exits 1 under `set -eu`, the `model-fetch` init
   fails, and the strata Deployment (strategy Recreate) never starts — the
   already-serving `-strata`/`-strix` arenas go down with it.
   Fix (in scope, pick one): (a) drop the new tool dependency — stage the two
   shards with the interpreter the pack step already requires, e.g.
   `"$SRC/.venv/bin/python"` + `urllib.request` (same downloader class setup's
   own `download()` uses; the C02 gated fetch needs the same code path with an
   `Authorization` header, so this fix is durable across chunks); or (b) keep
   curl but add the loud precondition probe
   `command -v curl >/dev/null 2>&1 || fail "abl pack: image has no curl -
   containers/strata must bake it (git/c++ rule, verify step)"` and route the
   `containers/strata` apt + `command -v curl` verify bake as its own change
   (out of C01's file scope — coord routes it; C02 needs it anyway per R-d).
2. **minor — the pack preconditions are checked after the ~76 GB download.**
   values.yaml:1147-1151 (`$SRC/.venv/bin/python`, `$ggufpy` guards) run only
   after both `abl_dl` calls (1140-1141), which contradicts the block's own
   stated intent ("name the precondition loudly instead of booting a
   half-provisioned arena"): a missing venv/gguf-py costs a full download pass
   before failing. Move both guards (and the finding-1 downloader probe) to the
   top of `abl_pack`, before `mkdir`/`abl_dl`.
3. **nit — a fully-downloaded-but-un-moved `.part` wedges the boot.** If the
   pod dies between `curl` success and `mv "$2.part" "$2"` (values.yaml:1136-
   1138), the next run re-enters `abl_dl` and `curl -C -` on a complete file
   exits non-zero → `fail` on every boot until a human deletes the `.part`.
   Cheap remedy: `rm -f "$2.part"` before starting, or retry once without `-C -`.
