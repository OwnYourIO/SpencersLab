## THE ordering/compat adjudication (chart+image land in one commit, image builds in CI)

Decision (planner, this round — recorded in DECISIONS): **single atomic commit, accept the bounded self-heal window, loud boot guard, no fallback script.** Rationale:
1. One commit carries chart + image files; coord commits it; `docker-build.yaml` builds `containers/strata/` on the PR (build-verify includes the new files) but pushes NOTHING until merge (container-creation law). PR-green build = strong evidence the merge push succeeds.
2. On merge: docker-build pushes `:v<run>` + `:main` (~minutes); ArgoCD syncs the chart. If ArgoCD's pod replacement beats the `:main` push, the new init starts against the OLD image and fails at container-start with `exec: "/opt/strata/bin/fetch_models.sh": no such file` — loud, no half-provisioning (exec form = zero script executed, markers untouched). Because `pullPolicy: Always` + restart backoff re-pull on every attempt, the NEXT attempt after CI's push succeeds and the run completes — **self-heal inside the CI build window, zero human action**. Idempotency markers + `.part` resume semantics make the interrupted boot re-entrant by design (C01/C02 laws).
3. Blast radius: only the strata pod's init (the llama.cpp trio and every other pod don't touch this image; peers routing strata 503s for minutes worst-case).
4. REJECTED alternatives: keeping the old chart script until the image is verified (doubles the logic, keeps values.yaml bloat, hides staleness — the suite would pin two sources of truth); a chart-side `[ -f … ] && old || new` wrapper (a fallback that silently prefers stale logic at boot is the exact failure class this repo's bake+verify law kills).
5. Human runbook gate (owner-side, never agent): merge when a minutes-long strata-pod boot-failure window is tolerable, or hold ArgoCD sync until docker-build's `:main` push completes. Recorded as a user follow-up in every C07 RESULT.
