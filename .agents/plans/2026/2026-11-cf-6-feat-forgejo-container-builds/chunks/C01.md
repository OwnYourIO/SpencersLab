## Goal

Ship `.forgejo/workflows/containers-build.yaml` — the Forgejo port of `.github/workflows/docker-build.yaml` (which C02 narrows to a `workflow_dispatch`-only manual fallback) — with changed-folder detection, per-container matrix, the D3–D5/D8 tag + push + cache + auth scheme, and the offline contract suite that pins its invariants. Everything validates offline; the authoritative build test is the live Forgejo run post-merge.

## Tasks

- [ ] `scripts/forgejo-container-detect.sh` — pure-shell helper, three subcommands, no jq/python dependency:
  - `detect`: env `EVENT_NAME` (`push|pull_request|workflow_dispatch`), `EVENT_BEFORE`, `SHA`, `BASE_SHA`, `HEAD_SHA`, `MANUAL_CONTAINERS`; run at repo root over the checked-out history; stdout a sorted JSON array (`[]` when nothing qualifies). Push: diff `EVENT_BEFORE..SHA` (all-zero/empty before → `HEAD^..HEAD`); PR: `BASE_SHA..HEAD_SHA`; dispatch: manual list only (comma/space normalized, sorted unique; empty input → `[]`). Always pass the DNS-safe gate `^[a-z0-9]+(-[a-z0-9]+)*$` (2nd path segment) **and** the `containers/<name>/Dockerfile` gate — the gate applies to manual names too.
  - `next-n`: stdin ghcr `tags/list` JSON body + env `YYMM` (`26.11`); stdout `max(yy.mm.*)+1` (1 when none match). Pure parse — sed-extract, no jq.
  - `sanitize`: branch name in, Docker-safe rolling/PR component out: lowercase, `/`→`-`, any remaining non-`[a-z0-9._-]`→`-`, collapse repeats, cap total tag length ≤128.
- [ ] `.forgejo/workflows/containers-build.yaml` — house style per `.forgejo/workflows/main-sync.yaml` (terse why-only header comment, diag step, `set -euo pipefail` in every run block):
  - `on:`: `push` branches `[main]` paths `['containers/**']`; `pull_request` branches `[main]` same paths; `workflow_dispatch` input `containers` (string, default `''`, rebuild escape hatch). NO `dev` leg (D7).
  - `concurrency: { cancel-in-progress: false }` top level (mandatory, RESEARCH TL;DR-2).
  - `detect-changes` job: infra guard `if: startsWith(forgejo.server_url, 'https://git.spencerslab.com')`, `runs-on: ubuntu-24.04`, `actions/checkout@v6` with `fetch-depth: 0`, calls `detect`, emits `changed-containers` output via `$GITHUB_OUTPUT`/`$FORGEJO_OUTPUT`.
  - `build-and-push` job: same guard, `needs: detect-changes`, `if` skips on `'[]'`, `strategy.matrix.container: ${{ fromJSON(...) }}` + `fail-fast: false` + per-cell unique `name:` (matrix caveat, RESEARCH C); diag step echoing `forgejo.server_url`, `docker info` (dind), `docker buildx version`, `env | grep ACTIONS_ || true` (first-fire recorder, OQ-8).
  - Tag compute via `sanitize` + inline curl legs: month = `date +%y.%m`; anonymous pull token + `GET /v2/ownyourio/<img>/tags/list` (curl + sed, no jq) piped to `next-n`; existence-advance loop (`HEAD .../manifests/<tag>` until 404, bounded) — GHCR tags are fully mutable, so the loop + an in-file comment state the re-run semantics (RESEARCH D).
  - Tags pushed: push→main = `yy.mm.N` + `latest` + `main`; PR = `pr-<sanitized-head_ref>-<short-sha>` ONLY (D5; a PR must never touch a rolling or calendar tag). Short sha via `git rev-parse --short`.
  - Build/push: plain `docker build -t <each tag> containers/<img>` + `docker login ghcr.io -u OwnYourIO --password-stdin <<< secrets.GHCR_PUSH_PAT` + `docker push` per tag. No buildx cache flags (cache = the persistent dind docker-data VCT, D8), no `docker/*` actions, only mirror-proven `actions/checkout@v6`.
  - Comment notes: same-repo-PR-only secret availability (fork heads get empty secrets); capacity-1 serialization; 30-min job timeout is the runner cap.
- [ ] `tests/services/forgejo-containers-build.sh` — see Tests below; the `forgejo-main-sync.sh` template verbatim in shape (red-first, ok/fail counters, `cd "$(git rev-parse --show-toplevel)"`, no network, pyyaml `doc.get(True) or doc.get('on')` handling of the YAML-1.1 `on:` key).

### major-1 — a failed detector is masked at the emit site (`containers-build.yaml:79-80`)

`echo "changed-containers=$(bash scripts/forgejo-container-detect.sh detect)" >> "${GITHUB_OUTPUT:-$FORGEJO_OUTPUT}"`
— a command substitution inside `echo`'s argument, so under `set -euo pipefail`
its non-zero status is **discarded**. Verified directly:

```
bash -c 'set -euo pipefail; echo "changed-containers=$(bash -c "echo boom >&2; exit 128")" >> "$out"'
  => boom / STEP CONTINUED, exit=0 / emitted: [changed-containers=]
```

(The standalone-assignment form does propagate it — same probe gave `outer-exit=128`.)

Why it matters: this defeats the loud-failure invariant the detector's own
comment (`.sh:48-50`) states — "a range that fails to resolve must fail the
job, not be reported as 'nothing changed' and silently skip the builds it
covers". The detector fails loudly, but the consumer swallows it: the detect
job goes **green** with an empty value, `'' != '[]'` is true so the build job
is *not* short-circuited, and the matrix receives `fromJSON('')` — at best a
confusing downstream failure, at worst an empty matrix and the silent skip the
comment exists to prevent. Same shape applies to a PR event with an unresolved
`BASE_SHA` (verified: detector exits 128).

Concrete fix (keeps the chunk's `:-` guard for the output file):

```bash
changed=$(bash scripts/forgejo-container-detect.sh detect)   # assignment propagates the exit
echo "changed-containers=$changed" >> "${GITHUB_OUTPUT:-$FORGEJO_OUTPUT}"
```

### major-2 — a never-pushed image cannot compute its first calendar tag (`containers-build.yaml:132-141`)

`token=$(curl -fsS "https://ghcr.io/token?scope=repository:ownyourio/<img>:pull")`
403s for an image that has never been published, `curl -f` exits 22, and
`set -euo pipefail` kills the step before `next-n` ever runs. Verified live:

```
GET /token?scope=repository:ownyourio/cf6-never-pushed-xyz:pull → HTTP 403 {"code":"DENIED"}
workflow's exact shape  → curl: (22) … 403, exit 22, no n= line
```

All 13 current `containers/*` dirs return token=200/tags_list=200, so the
cutover's first fire and the owner's `traefik-mqtt-allowlist` smoke are
unaffected — but the next new container's *first* merge fails the build leg,
contradicting D3/`next-n`'s "1 when none match" (the "none" is unreachable)
and the repo's documented add-a-container flow (the GitHub original reads
nothing from the registry, so this is new to the port, not a ruled decision).

Concrete fix: distinguish "no such repository" from a registry malfunction —
fetch the token/tags list without `-f`, check the code, and treat 401/403/404
as "no calendar tags this month" (`n=1`, then the existing advance loop handles
collisions); keep any other transport error loud.

**No validation covers either major.** They are composition/transport facts,
not detector-unit facts, so t/d can't see them. Options for coord (test-session
work, never mine): a static leg asserting the assign-then-emit shape, and one
