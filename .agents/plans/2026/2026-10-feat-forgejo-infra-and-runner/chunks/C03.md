# C03: Item B — `charts/forgejo-runner` + dev service wiring
size: L   wave: 1   depends_on: []

## Goal
New hand-rolled bjw-s app-template chart `charts/forgejo-runner` (v1.0.0) that
runs a Forgejo Actions runner on the dev cluster as a single-replica
**StatefulSet** with a privileged **DinD sidecar initContainer**
(`restartPolicy: Always`), declarative registration
(`server.connections` + `token_url: file:…`, RESEARCH.md ground truth — NO
`register` CLI, NO env-var registration), 2 PVCs (runner identity `/data`,
docker image cache `/var/lib/docker`), and a Bitwarden-backed token
ExternalSecret. Wired into `services/dev` + `custom-values/dev`.

## Notes for dev
- **Registration is declarative only** (RESEARCH.md Q2, contradiction C3):
  `server.connections.<name>` with `uuid` + `token_url: file:…`; the `.runner`
  identity file on the `data` PVC makes a restart a re-attach. The `register`
  CLI and `FORGEJO_INSTANCE_URL`/`FORGEJO_RUNNER_REGISTRATION_TOKEN` env
  vars do NOT work on runner v13 — a test asserts their absence.
- `.runner` + config + `~/.cache/actcache` all live under `/data` (image
  `HOME=/data`) — that's why the `data` VCT mount is `globalMounts` (both
  containers) while `docker-data` is dind-only via `advancedMounts`.
- The config's static values (capacity, cache, container.privileged) are
  inlined in the ExternalSecret template on purpose: ESO is "not a templating
  engine" beyond remoteRef substitution (dev plan round-4 note), so the whole
  file is one template entry; only `uuid` is dynamic.
- Verify the runner's internal API port (headless service port) against the
  v13.2.0 source/docs at implementation; if there is no stable health
  endpoint, prefer a TCP probe on the API port or leave the runner container
  probe-less (the dind sidecar carries the pod's observable liveness) —
  record whichever in a comment.
- The dev node root-fs check (`df -T /`, user action) gates DinD overlay2 on
  local-path PVs; if the user reports overlay, this chunk needs the DinD
  `storage-driver: vfs` env before sync — surface as NEEDS_INFO rather than
  guessing.
- `ServerSideApply: "false"` follows gpt-researcher (app-template app
  workload on dev); the StatefulSet's VCTs are plain K8s resources with no
  operator webhook, so no SSA annotation gymnastics are needed.
