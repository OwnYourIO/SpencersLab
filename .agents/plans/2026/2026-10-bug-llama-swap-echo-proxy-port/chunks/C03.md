### RENOVATE MECHANISM DEVIATION — falsified plan recon (read this first)
The chunk's Task said "NO renovate manager matches this image today" and
prescribed a NEW customManager (inline annotation + regex over
repository:/tag: pairs). **FALSIFIED**: the built-in `helm-values` manager
(rev 44.181.5, npm package source read this session) matches
`/(^|/)values\.ya?ml$/` and extracts docker deps from any
`image: {repository, tag}` object — it has been tracking this image pair all
along. Proof it is live in THIS repo: commit `dbaaadced` ("Update python
Docker tag", renovate[bot], 2026-10-25) bumped `python:3.12.15→3.15.1` in
`charts/llama-swap/values.yaml` — the same repository/tag shape. The main
image never proposed updates because (1) `unified-vulkan-266` does not parse
under the manager's default `docker` versioning, and (2)
`pinDigests: false` makes the in-place 262 rebuild invisible. A NEW
customManager on top would double-extract the same dep (duplicate-dependency
warnings every run) AND sweep in `charts/ilias/values.yaml`'s two
pre-annotated image pairs (same convention, currently untracked) under a
llama-swap-specific versioning — an out-of-scope behavior change.
Implementation therefore uses a **packageRule** instead of a customManager:
`matchPackageNames [ghcr.io/mostlygeek/llama-swap]` + `matchDatasources
[docker]` + `versioning "regex:unified-vulkan-(?<major>\d+)$"`. Same goal
(chunk: "Renovate must be able to propose unified-vulkan-267+ when it
appears"), no double-matching, ilias untouched. The inline
`# renovate: datasource=docker depName=...` annotation (ilias convention) is
kept as documentation — YAML comments are parser-invisible, so it is inert
to every manager.
