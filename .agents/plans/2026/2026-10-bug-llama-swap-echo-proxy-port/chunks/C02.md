# C02: renderer — emit proxy only when the final cmd carries ${PORT}
size: M   wave: 2   depends_on: [C01]

## Goal
Make the rendered config valid under the validator-bearing llama-swap binary:
`llama-swap.declaredConfig` emits the default `proxy: http://localhost:${PORT}`
ONLY when the model's final composed cmd — after llama-swap-style user-macro
expansion — contains `${PORT}` (the exact semantics of macros.go, which checks
post-expansion). Echo entries render without a proxy key; live entries keep
their proxy line byte-for-byte.

## Notes for dev
- Composed live cmds carry `${server-cmd}` (macro value holds `--port ${PORT}`);
  whisper/rana raw cmds carry literal `--port ${PORT}`; echo cmds carry no
  `${...}` tokens at all. A naive literal `contains($cmd, "${PORT}")` check
  WITHOUT macro expansion would strip proxy from every live entry — that breaks
  criteria 3/4. Expansion awareness is the whole trick.
- `${PORT}` itself is never a user macro; it survives expansion as the signal.
- Dropping proxy from echo entries also stops llama-swap allocating ports for
  them (macros.go allocates only when cmdHasPort || proxyHasPort) — harmless,
  matches pre-check intent.
- Record the post-fix gpu + default CM shas in the chunk's review notes for
  the audit trail.
