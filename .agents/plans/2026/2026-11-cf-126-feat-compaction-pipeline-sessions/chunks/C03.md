## Goal
Landing the card's asks (d) and (e): instead of fighting a compaction, the compaction EVENT triggers a custom instruction for EVERY session in this repo (the plugin hook, repo-wide scope — the OQ3 ruling 2026-11-17; there is no agent-facing compaction-instruction surface, RESEARCH §2): the `*-coord` variants and the dispatcher get the FULL handoff (the summary becomes a compact handoff pointer — deliberately omitting what's-done/what's-next — that is in the discovered context — and the session then hands the card + planning folder to a fresh successor session and closes), the other agents get the generic leg (the pointer-shape summary + a successor-bootstrap note — no lock/card protocol); subagents notify the coordinator via the built-in failure report and are relaunched FRESH (the doctrine leg — no per-subagent hook); the sliding window is the `keep.tokens` convention; a failed compaction is treated as the PRIMARY signal (the documented upstream failure class), not a success.
