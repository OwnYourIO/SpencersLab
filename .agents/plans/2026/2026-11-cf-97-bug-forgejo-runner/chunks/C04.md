# C04: Pin `mergePolicy: Merge` on the runner ExternalSecret + why-comment
size: S   wave: 1   depends_on: []   owner: agent

## Goal
Make the chart say what its authors meant: the ExternalSecret target template
relies on fetched data keys surviving alongside the template output, but the
`mergePolicy` was never pinned — the ESO operator chart's v2.14.0 bump
(`582c96488`, landed the same day the chart was authored, `5853be497`) defaults
it to `Replace` at CRD admission, discarding every fetched key the template
does not re-emit. Live consequence (2026-11-02 audit): the Secret carries only
`{config.yaml, token}` — the fetched `uuid` key is invisible, and that blinded
the empty-uuid diagnosis for a full day (byte arithmetic: rendered
`uuid: ""` ⇒ 924 raw = 1232 b64, matching the live `config.yaml` length; a
filled uuid would be 1280 b64). Pinning `Merge` removes the default-flip
hazard and restores key-dump observability.

Honesty clause for everyone downstream: **this chunk does not fix the crash.**
Render inputs are unaffected by the policy (template refs see fetched keys
regardless — the same ESO rendered the real token), so the daemon keeps
crashing until C01's V1/V2 probe resolves what the `bw serve` snapshot
returns for `username`. C04 is the repo-side defect the audit found on the
way, worth fixing independent of the crash.
