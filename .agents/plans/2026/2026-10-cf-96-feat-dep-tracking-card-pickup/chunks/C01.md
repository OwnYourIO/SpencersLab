## Tasks
- [ ] T1 Five dependency tools, each 1:1 to a RESEARCH 1.3 route:
  `list_board_dependencies(board_id)` (GET board-wide lines incl. titles +
  cardNumbers), `list_card_dependencies(board_id, card_id)`,
  `add_card_dependency(board_id, card_id, target_card_id, type=None, color=None,
  icon=None)` (document the UPSERT semantics: repeat-add UPDATES, never
  duplicates; accept the `dependsOn` body alias route),
  `edit_card_dependency(board_id, card_id, target_card_id, type/color/icon)`,
  `remove_card_dependency(board_id, card_id, target_card_id)` (third destructive
  op — docstring-marked like `remove_rule`/`delete_checklist_item`).
  Client-side validation mirrors the 7-type list
  (`related-to|blocks|is-blocked-by|fixes|is-fixed-by|duplicates|is-duplicated-by`),
  rejecting unknowns BEFORE the request (the `create_label` color-gate posture).
  Writes register through `_write_tool` (readonly tier hides them by
  construction); reads are bare `@mcp.tool`.
- [ ] T2 `preload_board(board_id)`: ONE `GET /api/boards/:boardId/export?attachments=false&fields=…`
  call (fields trimmed to `board-header,labels,custom-fields,dependencies,sort`
  — unselected sections arrive as empty arrays; verify the exact vocabulary
  against RESEARCH S11 at impl time), reshaped to: swimlane → list → cards, each
  card `{id, card_number, label_ids, slug, archived, sort, parent_id}`; `slug`
  extracted from the card's `customFields` entry for the board's `slug` field id
  (parse the combined `[<slug>](<link>)` value to the bracketed text; bare value
  passes through); PLUS the board's dependency lines and label-name/field-name
  maps. Titles/descriptions are NOT carried (owner said not needed). Archived
  cards are FLAGGED (`archived: true`), never silently dropped from the payload;
  pickup-relevant consumption filters them (C05). Linked cards are excluded by
  the exporter itself (S11) — document that.
- [ ] T3 `set_card_labels(card_ids, add_label_ids=None, remove_label_ids=None)`
  (AD-74): the upstream bulk route `POST /api/boards/:boardId/cards/labels`
  (`{cardIds, addLabelIds, removeLabelIds}`, ≤500 cards, write-access-gated,
  label ids validated against the board). `board_id` required per house style.
  Document the ≤500 cap + that absent lists are no-ops.
- [ ] T4 `_slim_card` passthrough: `card_dependencies` (the raw
  `[{cardId, type, color, icon}]`) and `parent_id` from the full single-card
  document — today silently dropped (RESEARCH 2.1). `list_cards_in_list` stays
  strip-accurate (by-list projection has neither).
- [ ] T5 `create_card` optional trailing `parent_id: Optional[str]`: two-step —
  create as today, then `PUT` the single-card route with body `parentId`
  (RESEARCH S9: `PUT /api/boards/:boardId/cards/:cardId` reads `req.body.parentId`;
  confirm the exact path against S9 at impl time — the single-card POST does NOT
  honor a body parentId). A PUT failure reports `parent_id_set: false` + reason
  in the response and NEVER rolls back the card (the default_checked posture).
  **OQ1 ruling (parentId only):** kind-1 follow-up lineage rides this parameter
  ALONE — NO Red Strings edge is drawn automatically for follow-ups; the tool
  never calls the dependency routes on a parent_id create.
- [ ] T6 Docs re-stamp same commit: `containers/wekan-mcp/README.md` (tool
  count 31→38, the new section), `skills/wekan-mcp/SKILL.md` (tier-table tool

  (8 new rows, evidence stamp `source-only 2026-11` until the C10 live probe
