## Ground truth to document (each claim stamped
## `verified 2026-10-26 · wekan-mcp 4.1.3 · dev boards endpoint (mcp.dev.scifi.farm/boards/mcp)`)

Headline rules (SKILL.md block, ≤8 lines):
- Every tool takes `board_id` except `list_boards` (no args); every card-scoped
  tool also takes `card_id`. Resolve ids top-down; never guess the shape.
- Argument discovery channel is pydantic validation errors: snake_case names,
  `Missing required argument: X` / `Unexpected keyword argument: Y` — the error
  text names the exact missing/unexpected parameter, so read it and retry.
- Checked-state naming split: `get_checklist` items report **`finished`**
  (never `checked`); `toggle_checklist_item` takes **`done`** (bool) and returns
  `{item_id, done}`. REST body under both is `isFinished`.
- Card number / custom fields / `label_ids` come ONLY from `get_card`;
  `list_cards_in_list`'s projection returns `card_number: null` and empty
  `custom_fields` — document this as the *why* behind the boards skill's
  "confirm cardNumber with `get_card`" rule.

Full table (wekan-mcp-ops.md, extend/reconcile the existing "Slim projections and
key names" section — no duplicated or contradictory rows):

| tool | required args | gotcha / cross-check anchor in server.py |
|---|---|---|
| get_card | board_id, card_id | only read carrying cardNumber, custom_fields (values may be **null**), label_ids |
| list_cards_in_list | board_id, list_id | projection strips card_number (null) + custom_fields (empty) — use get_card |
| list_checklists | board_id, card_id | returns `{id, title}` only (already documented — keep, don't restate twice) |
| get_checklist | board_id, card_id, checklist_id | item field is `finished` (`_slim` maps REST `isFinished`; `get_checklist` fn) |
| toggle_checklist_item | board_id, card_id, checklist_id, item_id, done | input+response field is `done`; NOT `checked` |
| move_card | board_id, card_id, from_list_id, to_list_id | REJECTS `swimlane_id`; optional `to_swimlane_id` is the cross-swimlane param (mark source-verified, not live-probed); lands at TOP of dest list — see existing "Move semantics" section, cross-reference don't duplicate |
| add_comment | board_id, card_id, comment | body arg is `comment`, NOT `text` |
| list_custom_fields | board_id | — |
| set_card_custom_field | board_id, card_id, custom_field_id, value | value arg is `value` (string verbatim); upsert semantics already documented — cross-reference |
| delete_checklist_item | board_id, card_id, checklist_id, item_id | destructive, scoped to one item |
