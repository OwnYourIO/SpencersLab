## Facts to resolve (consumer → fallback)

1. Tool registration: `ctx.tool.transform(editor => editor.add({...}))`
   synchronous; namespacing (`editor.namespace` / `options.namespace`) →
   effective visible name `pipeline_claim` exactly. Also whether executor
   `context` carries `sessionID`, `agent`, `messageID`, `id`, `signal`.
   → C03/C07. Fallback: flat tool names `pipeline_claim` registered without
   a namespace; C07 permission rows pin whatever the probe observed.
2. Tool hooks: `ctx.tool.hook("execute.before" | "execute.after", fn)` —
   event carries `{ tool, sessionID, agent, ... }` flat (question-notify
   verified this on 2.1.2 types; re-confirm on 2.1.4); throwing in
   execute.before blocks the tool. → C04. Fallback: none needed — precedent
   is live in this repo; the probe re-stamps it.
3. Events: `ctx.event.subscribe({ signal })` async iterable without the
   `types` filter (v2.1.4 < 2.2.0, DECISIONS); payload keys for
   `session.created` / `session.updated` — `data.parentID` vs
   `data.info.parentID` (dual-read covers both; log one raw event shape from
   the probe); `session.execution.{started,succeeded,failed,interrupted}`
   emission; `session.idle`/`session.status` truly never emitted. → C04.
   Fallback: dual-read + in-code filter already designed.
4. Commands: `ctx.command.transform(editor => editor.add({ name,
   description, execute }))` exists; executor receives `{ sessionID, prompt,
   delivery }`; `ctx.session.prompt({ ...prompt, sessionID, text })` callable
   from it; registered plugin command dispatches as a slash command. → C06.
   Fallback (live-deferred): loop-file plain-text body (C06 ships both).
5. `ctx.storage`: `get/set/remove/scan({prefix})` shapes, plugin-scoped by
   id, durable across restarts. → C03/C04. Fallback: an in-memory Map +
   disk-lock truth only (cross-restart resume degrades to re-claim).
6. `ctx.session.instructions.entry.put({ sessionID, key, value })` (+
   remove) exists and renders a context block. → C03/C04 pin/lock-lost.
   Fallback: drop the pin; lock state rides tool responses only (D16).
7. `ctx.location.project.canonical` — exists? string path? equals the main
   checkout root from a worktree-located session? → C03 D10 chain. Fallback:
   git-common-dir derivation (designed regardless — probe decides the order).
8. `node:fs`/`node:path`/`node:os`/`node:crypto` availability in the plugin
   runtime (board-context already imports node:fs live — re-stamp via probe).
9. `ctx.session.get({ sessionID })` — hang warning (#55318): confirm the
   "never await inline in the event loop" rule stays a grep-able AC in C04
   (no local repro needed; the design defers via setTimeout).
10. Multi-instance: does one server process load the same plugin once per
    location dir (log evidence says yes for question-notify)? → informs the
    cross-process safety margin in C03–C05 (already designed: O_EXCL +
    mkdir reaper lock). Evidence from opencode.log suffices.
11. Label projection shape (D17/D19 — the worker derives the pipeline set
    from labels): dev-boards `get_board` returns board labels with
    `{id, name}` entries, and `get_card` returns the card's `label_ids`
    (the by-list projection `list_cards_in_list` strips them — pickup facts
    always come from the single-card read). Verify against the wekan-mcp
    skill's call-shapes table (live-probed precedent) and ONE live read pair
    on the AI-Dev board (read-only). → C07's boards-skill text + the
    worker procedure. Fallback if shapes differ: the skill text pins
    whatever the live read shows; the plugin never parses board payloads
    itself (the worker passes the derived set to `pipeline_claim`).
