# C05: reaper + board move + HA alert + reap/status commands
size: L   wave: 4   depends_on: [C04]

## Goal

The deterministic half of the design (handoff B.7 + card note 3): a
cross-process-safe reaper that moves stale locks (> `staleMs`, **default 2 h
= 7200000 ms, D21**) to `.pipeline/locks/.reaped/`, moves their cards to the
board's **Timeout** list via the dev-boards MCP (with the `timeouts.jsonl`
degrade — the `create_list` tool that would let deterministic code own the
list is a coordinator-created FOLLOW-UP CARD, D22), posts the card comment
naming the full reaped pipeline set, and pushes the Home Assistant phone
alert (question-notify mechanics) — plus the `/pipeline-reap` and
`/pipeline-status` plugin commands.

## Tasks

- [ ] Reaper seam `reapStale(deps, { trigger })`: `mkdir`-based
      `.pipeline/reaper.lock` cross-process guard (EEXIST → if the guard dir
      is older than 5 min, remove + retry once; else `{skipped:true}`); scan
      `locks/*.json` (parse error → mtime as heartbeat, cardId unknown);
      stale iff `now - max(heartbeatAt, mtime) >= staleMs`; claim each stale
      file via `rename` into `.reaped/<name>.<ts>.json`; RE-read the reaped
      copy and restore it if a heartbeat raced in fresh; on confirmed reap:
      audit `reaped` (pipeline/setId/card/session/ageMin/trigger),
      cache/storage cleanup for sessions THIS instance owns, `meta/lastReap`.
      Guard removed in `finally`. Idempotent + safe under N plugin instances
      (log evidence: one process loads the plugin per location).
- [ ] Set-aware board leg (D18/D22): group the pass's confirmed reaps by
      `cardId`; per card make exactly ONE board move + ONE comment + ONE HA
      alert. The comment and alert name EVERY pipeline of the reaped claim:
      the union of the pass's reaped pipelineIds with the lock records'
      `pipelineSet[]` (so a partially-reaped set still reads complete).
      Comment text: "Timed out: no heartbeat for 2h (session <id>,
      pipelines: <a>, <b>)".
- [ ] Board client seam (board-context mechanics, duplicated locally with
      the precedent comment — no cross-plugin import): `resolveMcpUrl`
      (ctx.mcp.transform editor.get("dev-boards") → ctx.mcp.list() scan →
      project-config-text parse), streamable-HTTP JSON-RPC
      (initialize → notifications/initialized → tools/call; SSE-or-JSON
      parse), `unwrapToolResult`. Config-driven board constants (D8):
      boardTitle `AI-Dev`, swimlane `In Process`, timeoutListTitle `Timeout`.
- [ ] `moveCardToTimeout(board, { cardId, pipelines, sessionID })`:
      `get_card` (current list_id + label_ids echo for the comment) →
      `list_lists` → find **Timeout** in the swimlane →
      `move_card(from_list_id, to_list_id)` → `add_comment` (text above).
      ANY leg failing (incl. Timeout list ABSENT — the normal state until
      the D22 follow-up card lands) → append `{cardId, setId, pipelines,
      sessionID, at, reason}` to `.pipeline/timeouts.jsonl`, audit
      `board_move_err`, never throw into the reaper. Document in the module
      header: this degrade IS the interim contract of D22.
- [ ] HA alert seam `sendHaReapAlert(deps, {cardId, pipelines, ageMin,
      sessionID})`: question-notify mechanics — admin-global-homeassistant
      URL discovery (transform → list fallback; NO config-text leg here, the
      admin server lives in the machine-global config), `call_service`
      `notify.mobile_app_pixel_6`, title `OpenCode: pipeline lock reaped`,
      message `card=<c> pipelines=<a>,<b> age=<n>min session=<id>` truncated
      to the question-notify MAX_MESSAGE shape. Fire-and-forget; failures
      only stderr (never delays/breaks a reap; alert AFTER the file move, so
      a dead board still alerts).
- [ ] Commands (C01 fact 4 shapes): `/pipeline-reap` → `reapStale("command")`
      + synthetic message with the summary; `/pipeline-status` → the C03
      status view as a synthetic message (set-grouped locks with
      age/state/holder + meta/lastReap). If C01 could not confirm command
      registration, degrade per its fallback line and report under
      deviations.
- [ ] Wire the claim-time + setup-time + timer reaps (C03's stub, C04's
      timer) to the real `reapStale`.

## Acceptance criteria

1. `node --test tests/opencode/pipeline-locks-reap.test.ts` passes; all
   earlier plugin suites + the four pre-existing suites green.
2. Stale reap: hand-written locks with `heartbeatAt = now − 3h` (staleMs
   2h) → `reapStale` moves them to `.reaped/`, audits `reaped`, writes
   `meta/lastReap`; a 10-min-old lock in the same dir is untouched.
3. Set grouping: two stale locks of ONE claim (same cardId/setId, pipelines
   a+b) → exactly ONE move_card + ONE add_comment + ONE HA alert; the
   comment and the alert message both name `a` AND `b`.
4. Degrade legs: board seam rejecting at EACH leg → the card row lands in
   `timeouts.jsonl` with reason + full pipeline list, the reap itself still
   succeeds; Timeout-list-absent (list_lists returns no Timeout) → same
   degrade (this is the shipped interim until the D22 follow-up lands).
5. Heartbeat race: the re-read-after-rename leg restores a file whose
   reaped copy shows a fresh heartbeat (rename back, audit `reap_raced`,
   no board leg, no alert).
6. Reaper-lock guard: a second concurrent `reapStale` gets `{skipped:true}`;
   a stale guard dir (> 5 min) is recovered and the retry runs.
7. HA alert: fired exactly once per reaped CARD (not per file) with the
   title/message shape pinned; the alert seam rejecting changes NOTHING
   about the reap outcome (fake counts + assertions); no alert for
   skipped/raced/fresh locks.
8. No credential, host, or URL literal in the module (grep); the two server
   keys appear only as the named constants `dev-boards` /
   `admin-global-homeassistant`; the staleMs default constant is `7200000`
   (grep pin, D21).
9. Command registration present for reap + status (or the recorded C01
   fallback) and their executors route through `reapStale`/`lockStatus`
   (test drives the captured executors).
