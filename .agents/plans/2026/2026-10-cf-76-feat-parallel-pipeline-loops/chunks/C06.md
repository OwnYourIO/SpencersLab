## Live-smoke checklist (human/deferred — needs the real server)

1. Plugin loads at both locations (main checkout + a worktree) — opencode.log
   `loading plugin` lines for `.opencode/plugin/pipeline-locks`; no setup errors.
2. `pipeline_claim|release|heartbeat|status` visible in a session's tool list;
   the four tools callable from a board-coord session (permission rows land in C07).
3. Run-now the synced loop: `/pipeline-tick` dispatches (events.log `tick`);
   if it does NOT dispatch, swap to the fallback body and record the finding
   (handoff B.6 verdict).
4. First-event envelope keys logged by the engine match the dual-read shapes
   (one-shot stderr debug lines).
5. Overlapping ticks: Run-now twice during a live iteration — the second
   picks another pipeline or reports no eligible work; no double-claim.
6. Subagent heartbeat: a running chunk's subagent tool calls advance the
   parent's `heartbeatAt` (events.log `child_mapped` + beats).
7. Crash recovery: kill+restart the server mid-iteration — the lock
   persists, is not heartbeated, is reaped after staleMs → Timeout + HA push
   (test profile: set `staleMs` low in `.pipeline/config.json`, then restore).
8. Location isolation: unrelated sessions produce no mappings/beats.
9. Restore `staleMs` to 2 h (D21 default); enable the loop hourly; watch the
   first 3 ticks; user re-points/retires the old hourly task (Q5 transition).
