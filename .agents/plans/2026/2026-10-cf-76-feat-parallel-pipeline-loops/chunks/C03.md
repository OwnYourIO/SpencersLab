# C03: pipeline-locks plugin core — lock files + the four tools (all-or-nothing set claim)
size: L   wave: 2   depends_on: [C01]

## Goal

Ship `.opencode/plugin/pipeline-locks/index.ts` (id `local.pipeline-locks`):
the lease-lock store on disk under `.pipeline/locks/<pipelineKey>.json` and
the four agent tools — `pipeline_claim`, `pipeline_release`,
`pipeline_heartbeat`, `pipeline_status` — with the session→lock bookkeeping,
atomic creates/writes, the JSONL audit log, and the lock-root resolution
chain (D10). Pipeline identity is the LABEL-derived set of D17/D18: a claim
acquires its whole set all-or-nothing. Heartbeating beyond the claim itself
arrives in C04; this chunk wires registration + the store the engine drives.

## Acceptance criteria

1. `node --test tests/opencode/pipeline-locks-core.test.ts` passes (the four
   existing tests/opencode suites still pass too).
2. Concurrent overlapping-set race: `claimLockSet` for `{A,B}` and `{B,C}`
   (injected tmp dir, Promise.all, x20 repeats) → exactly one wins; the
   loser gets `reason:"locked"` naming the contended pipeline + the winner
   as holder, and leaves ZERO partial lock files (rollback audit line
   present).
3. Disjoint concurrent sets both win. Same-set concurrent claims → exactly
   one wins. A second claim from the SAME root session on a different set
   returns `reason:"already_held"` (one card per iteration).
4. `derivePipelineSet`: `["Pipeline: payments", "Pipeline:infra ",
   "Research"]` → `["infra","payments"]` (trimmed, sorted later at claim);
   `["Pipeline:"]` / `["Research"]` / `[]` → `["default"]`; prefix match is
   case-sensitive (`"pipeline: x"` ignored); duplicates dedupe.
5. Every lock file of one claim carries the same `sessionID` + `cardId` +
   `setId` and the full `pipelineSet[]`; `sanitizePipelineKey("../../x y/z")`
   matches `^[A-Za-z0-9._-]{1,100}$`.
6. `writeLockAtomic` leaves no `.tmp` behind on success and survives a
   mid-write failure (pre-existing content intact when the tmp write fails).
7. `releaseLockSet` with a mismatched owner on one file returns `not_owner`
   naming it and leaves ALL files in place; with the owner it deletes the
   whole set and writes the audit line.
8. `resolveLockRoot` picks the canonical leg when present, the git-common-dir
   leg from a worktree `.git` file, and the start dir otherwise (fake fs).
9. The default export is the plain-object shape (`id === "local.pipeline-locks"`,
   async `setup`, returns a cleanup fn) and `setup` with an empty fake ctx
   completes without throwing (degrade path).
10. `.gitignore` contains `.pipeline/`; grep pins: no `Plugin.define` import;
    tool visible-name constants + `LABEL_PREFIX` + `DEFAULT_PIPELINE` each
    defined once (single sources for C07 parity); no hardcoded MCP URLs/hosts.

## Notes for dev

- This module will grow in C04/C05 — keep the seam export surface additive;
  later chunks import what this one exports.
- The claim executor resolves the caller's ROOT session: in this chunk a
  minimal `resolveRoot` (storage/cache hit, else identity) is fine — C04
  grows the parent-walk. Keep the function name stable.
- Sorted-order acquisition is the deadlock argument — the sort key is the
  SANITIZED pipelineKey; keep acquisition and rollback in one seam so the
  ordering cannot drift between them.
