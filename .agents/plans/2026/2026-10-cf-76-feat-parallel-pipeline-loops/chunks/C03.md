# C03: pipeline-locks plugin core — lock files + the four tools (all-or-nothing set claim)
size: L   wave: 2   depends_on: [C01]

## Goal

Ship `.opencode/plugin/pipeline-locks/index.ts` (id `local.pipeline-locks`):
the lease-lock store on disk under `.pipeline/locks/<pipelineKey>.json` and
the four agent tools — `pipeline_claim`, `pipeline_release`,
`pipeline_heartbeat`, `pipeline_status` — with the session→lock bookkeeping,
atomic creates/writes, the JSONL audit log, and the lock-root resolution
chain (D10). Pipeline identity is the LABEL-derived set of D17/D18: a claim
acquires its whole set all-or-nothing. Heartbeating beyond the claim itself
arrives in C04; this chunk wires registration + the store the engine drives.

## Tasks

- [ ] Module skeleton following the two shipped plugins' conventions: plain
      `export default { id: "local.pipeline-locks", async setup(ctx) }`,
      header comment block (why/precedents/failure policy, comment-slop
      clean), seam exports for tests, `setup` returns a cleanup function.
- [ ] Pipeline-set seams (D17): `LABEL_PREFIX = "Pipeline:"` constant
      (exact, case-sensitive — the single source C07's parity test greps),
      `DEFAULT_PIPELINE = "default"` one-line constant, and
      `derivePipelineSet(labelNames: string[]) -> string[]`: keep names
      starting with the prefix, trim the remainder, drop empty remainders,
      dedupe, and return `[DEFAULT_PIPELINE]` when nothing survives. The
      worker passes the derived set; the plugin never reads the board.
- [ ] Lock-root resolution seam `resolveLockRoot(deps, startDir)` — D10
      chain: canonical (C01 verdict) → git-common-dir derivation (parse the
      worktree `.git` file's `gitdir:` → strip `.git/worktrees/<name>`) →
      startDir. Pure fs reads through an injected `readFile`; never throws —
      every miss falls through to the next leg.
- [ ] Lock-file primitives (all through injected fs so tests run offline):
      `sanitizePipelineKey`, `newLockRecord` (handoff B.1 shape, version 1,
      PLUS the shared claim identity of D18: `setId` (uuid per claim),
      `pipelineSet[]` (the full sorted set), same `sessionID`+`cardId`
      across every file of the claim), `writeLockAtomic` (tmp + rename +
      utimes), `readLock` (parse-error → null), `appendEvent`
      (`.pipeline/events.log` JSONL, fire-and-forget).
- [ ] Claim seam `claimLockSet(deps, { cardId, pipelines, cardTitle?,
      sessionID })`: normalize + sanitize the set (empty/missing →
      `[DEFAULT_PIPELINE]`), refuse-if-this-root-already-holds-another-claim,
      mint ONE `setId`, then ACQUIRE IN SORTED pipelineKey ORDER with
      `open(..., "wx")` O_EXCL per file (D18): on any EEXIST, read that
      holder, ROLL BACK every lock already taken (unlink + audit
      `claim_rollback`), return `{ok:false, reason:"locked", pipeline,
      holder}`. Full success → storage write (C01 verdict on ctx.storage;
      fallback: in-memory Map), instruction-pin (C01 verdict; fallback: skip
      per D16), audit `claim` with the whole set; return `{ok:true,
      setId, lockPaths}`. Reap-hook stub first (C05 replaces).
- [ ] Release seam `releaseLockSet`: resolve the caller's claim (storage/
      cache → its `pipelineSet`), owner-check EVERY file (`sessionID` ==
      caller's root), delete the whole set, storage/instruction cleanup,
      audit `release` with outcome `done|abandoned` + set; any file whose
      owner is not the caller → `{ok:false, reason:"not_owner", pipeline}`
      and the remaining files untouched.
- [ ] Status seam `lockStatus`: every lock file with age/state/holder,
      grouped by `setId`/card so a multi-pipeline claim reads as one unit,
      + this session's claim + lastReap (meta read; meta written by C05).
- [ ] Tool registration in `setup` via C01-confirmed shapes (namespace or
      flat names — whichever C01 proved; the VISIBLE names must be
      `pipeline_claim|release|heartbeat|status`), JSON-schema inputs:
      claim `{cardId, pipelines?: string[], cardTitle?}` (pipelines omitted
      or empty ⇒ default pipeline — the worker derives the set from labels
      per the boards skill, D17/D19), release `{outcome}`, heartbeat `{}`,
      status `{}`. Executor context → root-session resolution before store
      calls. `pipeline_heartbeat` always force-beats the caller's own set.
- [ ] `.gitignore`: add the `.pipeline/` entry (with the why-comment).
- [ ] Default export `setup` must degrade, never throw: every ctx surface it
      uses is optional-chained with a stderr line (board-context never-throw
      policy) — a plugin load failure would poison the server's plugin group.

## Acceptance criteria

1. `node --test tests/opencode/pipeline-locks-core.test.ts` passes (the four
   existing tests/opencode suites still pass too).
2. Concurrent overlapping-set race: `claimLockSet` for `{A,B}` and `{B,C}`
   (injected tmp dir, Promise.all, x20 repeats) → exactly one wins; the
   loser gets `reason:"locked"` naming the contended pipeline + the winner
   as holder, and leaves ZERO partial lock files (rollback audit line
   present).
3. Disjoint concurrent sets both win. Same-set concurrent claims → exactly
   one wins. A second claim from the SAME root session on a different set
   returns `reason:"already_held"` (one card per iteration).
4. `derivePipelineSet`: `["Pipeline: payments", "Pipeline:infra ",
   "Research"]` → `["infra","payments"]` (trimmed, sorted later at claim);
   `["Pipeline:"]` / `["Research"]` / `[]` → `["default"]`; prefix match is
   case-sensitive (`"pipeline: x"` ignored); duplicates dedupe.
5. Every lock file of one claim carries the same `sessionID` + `cardId` +
   `setId` and the full `pipelineSet[]`; `sanitizePipelineKey("../../x y/z")`
   matches `^[A-Za-z0-9._-]{1,100}$`.
6. `writeLockAtomic` leaves no `.tmp` behind on success and survives a
   mid-write failure (pre-existing content intact when the tmp write fails).
7. `releaseLockSet` with a mismatched owner on one file returns `not_owner`
   naming it and leaves ALL files in place; with the owner it deletes the
   whole set and writes the audit line.
8. `resolveLockRoot` picks the canonical leg when present, the git-common-dir
   leg from a worktree `.git` file, and the start dir otherwise (fake fs).
9. The default export is the plain-object shape (`id === "local.pipeline-locks"`,
   async `setup`, returns a cleanup fn) and `setup` with an empty fake ctx
   completes without throwing (degrade path).
10. `.gitignore` contains `.pipeline/`; grep pins: no `Plugin.define` import;
    tool visible-name constants + `LABEL_PREFIX` + `DEFAULT_PIPELINE` each
    defined once (single sources for C07 parity); no hardcoded MCP URLs/hosts.
