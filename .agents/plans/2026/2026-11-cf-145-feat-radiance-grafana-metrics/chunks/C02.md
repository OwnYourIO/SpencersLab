## Grounded mechanism facts (verified this round from the grafana 10.1.0 chart source + a live subtree render, RC=0)
- The lab ships providers EXPLICITLY in `grafana.dashboardProviders["dashboardproviders.yaml"].providers` — the chart renders that file verbatim into the provisioning CM; there is NO auto-provider magic.
- `download_dashboards.sh` (chart `_config.tpl`) resolves each url entry's write dir by matching the provider entry whose `name` EQUALS the `dashboards` map KEY, then curl → `<that provider's options.path>/<key>.json`; it also pre-`mkdir -p`s every provider path. So provider-name ↔ dashboards-key ↔ options.path must couple exactly (plan R8) or the JSON downloads nowhere.
- `folder:` is the display folder; the repo convention maps key → Title-case display (data→Data, kubernetes→Kubernetes; its-alive is the one human-name outlier).
- A string `datasource: Prometheus` makes the script sed every `"datasource":` field in the fetched JSON to `"Prometheus"` — the exact behavior the vllm url pair relies on (radiance.json has no `__inputs`, fact #24; the panel-side effect matches the precedent).
- Renders prove it live: current-tree render contains `dashboardproviders.yaml` + `download_dashboards.sh` with the vllm curls targeting the default path; adding a provider adds its mkdir + write path.
