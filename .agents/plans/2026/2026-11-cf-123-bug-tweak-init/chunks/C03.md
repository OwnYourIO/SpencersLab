# C03: First-prompt-only block + /reload-board-context (card ask D)
size: L   wave: 3   depends_on: [C01]

## Goal
Stop the board-context block re-injecting on within-session follow-up
prompts, and give the owner a manual refresh. Root cause (proven, EXPLORE
§D): the once-guard is an in-memory Map per plugin load, and two live
opencode servers (workspace :4096 + OpenChamber service :49374) load the
plugin independently — prompts of ONE session dispatched through different
processes see different maps (this run's own coord session re-injected at
02:55Z). Fix: a durable once-mark in `ctx.storage` — plugin-id+project-id
scoped, shared across processes, restarts and worktrees (the pipeline-locks
D26 precedent binds the same storage) — plus a `/reload-board-context`
plugin command that fetches a fresh block on demand.

## Design rulings (the plan carries these — dev implements, does not re-decide)
- **Durable mark**: storage key `once/<sessionID>`, value = epoch-ms stamp.
  Bind `ctx.storage` with the tolerant adapter shape pipeline-locks probes
  confirmed on v2.1.4: positional `set(key, value)`, `get(key)` →
  undefined-absent, `remove(key)`; adapter failure or absent storage
  degrades to the per-process in-memory Map (today's behavior) + one stderr
  line at setup, never a throw.
- **Semantics unchanged from today's S4/S6 shape, now durable** (owner
  ruling #5, 2026-11-07: KEEP consume-once-whether-successful): the first
  prompt attempt CONSUMES the mark whether the fetch succeeds or fails
  (re-firing a failed fetch would pay the 8 s admission budget on every
  later prompt of a degraded run; block absence is the designed-normal
  boards consumer rule). The canonical-header scan still marks without
  injecting (pasted blocks and the refresh command's own reply ride it).
  Non-coord sessions never consume. TTL stays 6 h: a stale mark is ignored
  and removed on encounter.
- **Scheduled ticks unchanged** (owner ruling #4, 2026-11-07): each tick is
  a FRESH session, so its first prompt keeps its block — the mark keys the
  sessionID, and the complaint is within-session follow-ups only; the once
  rule is session-scoped and durable across the two live opencode server
  processes.
- **Refresh command** `/reload-board-context`: no arguments; execute fetches
  a fresh block through the same resolve path (FETCH_TIMEOUT_MS budget) and
  answers via `ctx.session.prompt` on the invocation's envelope — the
  pipeline-locks `say` pattern. The reply text carries the block, so the
  hook's header scan marks the session and never double-injects. Fetch
  failure → one-line failure reply, mark untouched, never a throw. The
  command works in any session the human types it in (no agent gate — the
  human chose the target session). Human-typed surface only: slash dispatch
  from LOOP TEXT is unproven on the pinned builds (D30), so the loop body
  never names this command.

## Acceptance criteria
1. Cross-process seam: two handler instances sharing ONE fake storage — an
   injection through instance A prevents injection through instance B for
   the same sessionID; one board fetch total (S4 re-pin).
2. Storage absent/degraded → per-process in-memory fallback behaves exactly
   like today's guard (per-instance once semantics).
3. TTL: a mark older than 6 h does not block a fresh injection and is
   removed on encounter.
4. `/reload-board-context` registers through ctx.command.transform when the
   host provides it (and ONLY then — setup still returns normally and logs
   one degrade line without it); setup still registers exactly ONE prompt
   hook (S9 green).
5. Command executor: successful fetch → one `session.prompt` reply carrying
   the block (header scan marks; a following plain prompt does not
   re-inject); failed fetch → one-line failure reply, no mark mutation, no
   throw.
6. S5 (idempotence) and S6 (never-throw) green on their re-pins.
7. `npx aislop ci --changes` clean; header comment passes comment-slop
   (why-only: the two-server topology and the consume-once trade-off).
