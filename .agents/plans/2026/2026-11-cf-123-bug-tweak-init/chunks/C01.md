## The new fence (byte contract — five artifacts move together)
```text
Board context (collected <ISO-8601>, <server-id>)
board_id: <id>
swimlane_id: <id>
lists:
  - title: "<list title>"
    id: <id>
    cards:
      - card_number: "AD-<card_number>"
        card_id: <card id>
        labels: ["<label name>", ...]
custom_fields:
  "<field name>": <id>
labels:
  "<label name>": <id>
# Cards are a collection-time snapshot — the walk's get_card confirmation
# and claim-before-move absorb drift. Checklist ids are not included — they
# are live per-card data, resolved at use time. On any id-shaped call
# error, re-resolve this block against the live board before retrying.
```
Emitter rules (deterministic bytes, ruling #1 strict YAML):
- Header line UNCHANGED (`CANONICAL_HEADER` = "Board context (collected"
  stays byte-identical — the five-artifact idempotence anchor); everything
  under it parses as one strict YAML document.
- The footer prose becomes `#` comment lines (DECISIONS finalization:
  plain-prose footer would break parseability; a data-key footer would mix
  contract prose into the parsed document).
- Quoted via JSON.stringify: list `title`, custom-field/label mapping keys,
  every label name inside the flow list, AND `card_number` (always a quoted
  string — prefixed `"AD-123"` and degraded `"123"` must not flip YAML
  types across the degrade states). Bare scalars: `board_id`,
  `swimlane_id`, list/card `id`, `card_id`, custom-field/label mapping
  values.
- Empty list → `cards: []`; card with no labels → `labels: []`.
- Prefix DEGRADE (ruling #2): get_board answer carries a truthy `key` →
  `card_number: "<key>-<card_number>"`. Absent/falsy `key` (the deployed
  build pre-rollout) → bare `card_number: "<card_number>"` PLUS exactly one
  comment line, pinned bytes, as the FIRST trailing-comment line:
  `# card_number values are bare: the get_board projection carried no board key at collection time.`
  The schema section documents both shapes; the note is never silent, never
  stderr-only (scheduled-tick consumers read the block).

## Acceptance criteria
1. `formatBlock(FIELDS)` emits the fence above byte-for-byte (S1 parity
   green with the re-pinned EXPECTED_BLOCK); purity arm green; the body
   under the header line parses as strict YAML.
2. `resolveBoardContext` runs the six serial calls
   list_boards → get_board → list_swimlanes → list_lists → list_custom_fields
   → preload_board (preload called with `{board_id}` ONLY) and renders
   per-list cards: cards joined by list id from the preload's In-Process
   swimlane grouping (client-side scoping via the list_swimlanes/
   list_lists legs), `sort` ascending, archived cards skipped, label ids
   resolved through the preload's `label_names` with an UNKNOWN id emitted
   as the raw id.
3. Prefix derivation: a get_board answer with truthy `key` yields
   `card_number: "<key>-<n>"` (quoted); an answer WITHOUT `key` (the
   current deployed projection) yields the bare quoted number plus the
   pinned degrade note line — both arms deterministic and test-pinned.
   No `AD` literal anywhere in the emitter (derivation, never hardcode).
4. A list the preload grouping does not carry (live: Rework — empty lists
   drop out of the export, verified in the repo source under the NEW
   deployed shape too) renders `cards: []` from the plugin's own
   `list_lists` leg. A successful preload whose swimlane grouping is absent
   renders every list empty-cards + one stderr line, never a throw.
5. A FAILED preload_board leg (reject/timeout) rejects the whole resolve →
   the hook degrades per the S6 shape (prompt untouched, exactly one stderr
