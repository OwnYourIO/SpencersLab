# C02: Push engine — detect + push scripts, tfvars `namespace` supply, their suites
size: M   wave: 1   depends_on: []

## Goal
The two pure-shell scripts the workflow invokes: changed-template detection (the
`containers-build.yaml` house shape, adapted to `charts/coder/coder-templates/`) and
the per-template `coder templates push` driver with the env-only, warn-and-skip
posture — plus the OQ5-ruling repo-side value supply: `namespace = "default"` in both
templates' `terraform.tfvars`. Independent of C01 — the scripts run inside the image
at runtime; the test leg injects a fake `coder` binary, so no image is needed.

## OQ5 verification (done at plan time, 2026-11-25 — the settled decision this chunk lands)
Per the owner ruling, template input values come from the repo. Verified against the
actual files: the ONLY required variable without a repo-side value in either template
is `namespace` (required, no default — `kubernetes/main.tf:32-35`,
`kubernetes-hardened/main.tf:83-86`; absent from `kubernetes/terraform.tfvars`, and
`kubernetes-hardened/` has no tfvars at all). Every other variable has a `main.tf`
default (`use_kubeconfig` false, `shared_pvc_name` dev-shared, the three version pins
also in `kubernetes/terraform.tfvars`). `default` is valid for BOTH instances: both
coderd releases sit in `default` (`services/dev/prod/values.yaml:101`,
`services/gpu/prod/values.yaml:143`); the gpu `dev-shared` PVC manifest carries no
namespace key → `default` (`services/gpu/prod/templates/pvc-dev-seaweedfs.yaml`); the
dev git-auth secrets `github-pat`/`forgejo-token` are `default`
(`services/dev/prod/templates/secret-*.yaml:11`) — the hardened template's own header
requirement. No per-instance value differs, so NO Forgejo value var is needed (the
ruling's "minimal" is fully satisfiable from the repo). The single residual
mechanism, documented as a runbook answer (C03): if an instance's workspace namespace
ever diverges from coderd's, one `--var namespace=...` from one instance-side var is
the whole fix.

## Tasks
- [ ] Write `scripts/coder-template-detect.sh` — modeled on
  `scripts/forgejo-container-detect.sh` (same `die`/stderr-endpoints style, same
  first-push narrowing, same empty-set exemption arithmetic), adapted:
  - `detect` subcommand: stdout a sorted JSON array of template dir names under
    `charts/coder/coder-templates/`, gated on (a) DNS-safe name, (b) the dir carries a
    `main.tf`. Inputs are env: `EVENT_NAME` (`push`|`workflow_dispatch` — NO PR arm,
    the workflow has no PR trigger), `EVENT_BEFORE` + `SHA` (push range),
    `MANUAL_TEMPLATES` (dispatch list, comma/space separated).
  - Push arm: `EVENT_BEFORE` empty = fatal (no push payload sends one); all-zero
    before = first push, tip-only `HEAD^..HEAD` + the `::warning::` line; otherwise
    the whole `before..sha` range. No `|| true` on the git call (a red detection must
    fail the job, never report "nothing changed").
  - Dispatch arm: the named list, both gates still applied (a named dir without a
    `main.tf` is not a promise a pushable template exists).
  - Empty-set warning: a push whose before equals sha (no-op ref update) and an empty
    dispatch list (its own no-op intent) stay silent; any other empty set warns.
- [ ] Write `scripts/coder-template-push.sh` — `usage:
  scripts/coder-template-push.sh <template-name>`, run at the repo root:
  - Env contract (the OQ5-minimal vault): `CODER_URL`, `CODER_SESSION_TOKEN` — either
    absent/empty → `::warning::` naming the missing key + exit 0 (the designed
    warn-and-skip green, the `main-sync.yaml` unset-vault posture). NO value vars of
    any kind — the script passes no `--var`: template input values come from the
    auto-loaded `terraform.tfvars` + `main.tf` defaults (the repo, the ruling).
  - Unknown template name = fatal (a matrix cell could not have come from the detect
    gate — a bug, not an input).
  - Invocation, env-only (the token must never reach argv — the `argocd-fanout.py`
    doctrine):
    `coder templates push <name> --directory charts/coder/coder-templates/<name> -y
    --ignore-lockfile --name <short-sha> --message "forgejo <event> <sha>"` —
    `<short-sha>` from `git rev-parse --short HEAD`; event/sha from `EVENT_NAME` /
    `SHA` env (dispatch may carry no event ref — fall back to HEAD, the
    `main-sync.yaml` REF-chain shape).
  - Exit: 0 on success; the coder CLI's non-zero is propagated (the workflow's
    `fail-fast: false` matrix isolates the siblings).
- [ ] Supply `namespace` from the repo (the settled OQ5 decision, verified above):
  - `charts/coder/coder-templates/kubernetes/terraform.tfvars`: add
    `namespace = "default"` (a comment citing the verified grounds: coderd `default`
    on both clusters, the gpu `dev-shared` PVC `default`, the dev git-auth secrets
    `default`).
  - `charts/coder/coder-templates/kubernetes-hardened/terraform.tfvars`: CREATE with
    the same header style as the kubernetes one (the auto-load / resolved-values
    comment) + `namespace = "default"` (the hardened header's git-auth-secrets
    requirement — the `default` namespace on the dev cluster).
- [ ] Write `tests/coder/coder-template-detect.sh` — behavioral legs against a
  synthetic git tree (the cf-139 C07 "detect A/B on real history" shape).
- [ ] Write `tests/coder/coder-template-push-script.sh` — behavioral legs with a fake
  `coder` executable on `PATH` that records its argv (offline; no network, no live
  Coder), plus the tfvars content legs.

## Acceptance criteria
1. `bash -n` on both scripts.
2. Detect legs (synthetic tree): a push range touching `charts/coder/coder-templates/<x>/main.tf`
   names exactly `x` (plus any other changed gated dir); an unrelated path change names
   `[]`; first push (all-zero before) narrows tip-only with the warning line; an empty
   `EVENT_BEFORE` dies non-zero with the fatal message; a dispatch list names exactly
   the listed gated dirs; an ungated name (no `main.tf`) is excluded; the two exempt
   empties are silent, all others warn.
3. Push script legs (fake `coder` on PATH): (a) `CODER_SESSION_TOKEN` unset → exit 0 +
   a `::warning::` line naming it, no `coder` invocation recorded; (b) `CODER_URL`
   unset, token set → the same posture; (c) configured: the recorded argv is exactly
   the contract line (name positional, `--directory` path, `-y`, `--ignore-lockfile`,
   `--name <short-sha>`, `--message` shape, and NO `--var` of any kind — the ruling:
   values ride the auto-loaded tfvars), and the token value appears NOWHERE in the
   recorded argv (env-only doctrine); (d) an unknown template name exits non-zero;
   (e) the fake `coder` exiting non-zero → the script exits non-zero (propagation).
4. tfvars legs: `kubernetes/terraform.tfvars` carries exactly the three version pins
   (values unchanged — `2.0.22` / `2.1.0` / `7.7.7`) + `namespace = "default"`;
   `kubernetes-hardened/terraform.tfvars` exists and carries `namespace = "default"`;
   the chart packaging guard still counts `0` (tfvars stays out of the tgz); the
   terraform-validate smoke passes for both templates with the new tfvars content
   (scratch copy, the plan Commands shape).
5. Both suites green from the repo root (`bash tests/coder/<name>.sh`), offline, in
   the house ok/fail harness shape.

## Notes for dev
- Read `scripts/forgejo-container-detect.sh` first — reuse its `die`, `json_array`,
  first-push, and exemption logic verbatim where the semantics match; the only deltas
  are the path (`charts/coder/coder-templates/`), the gate (dir + `main.tf`), the env
  names, and the absence of the PR arm.
- The push script must not `set -e`-die on the warn-and-skip path: that exit 0 is a
  designed outcome, so the missing-key check happens BEFORE any `set -euo pipefail`
  would trap it (or use explicit checks, not `-e` reliance).
- `--ignore-lockfile` is pinned because NEITHER template dir ships a
  `.terraform.lock.hcl` (EXPLORE gotcha 4) — a lockfile appearing later changes
  nothing (the flag is a no-op then), but dropping it would re-noise the log.
- The tfvars edits change what a push RESOLVES: `namespace` becomes a persisted
  resolved value instead of a workspace-creation prompt (the Coder behavior the
  kubernetes tfvars header already documents for its values). That is the intended
  GitOS-ification — but keep the existing tfvars comment block intact and extend it
  rather than rewriting it.
