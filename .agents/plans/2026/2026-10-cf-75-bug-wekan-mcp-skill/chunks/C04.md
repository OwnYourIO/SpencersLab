# C04: board-context prefetch plugin
size: M   wave: 3   depends_on: [C03]

## Goal
Best-guess scope call (OQ5: include, last, degrade-safe): an OpenCode
server plugin that, ahead of the FIRST prompt of an agent-board-coord
session (the scheduled hourly case is the point), fetches the Board
context block itself and appends it to the prompt — so nobody has to
paste anything and the run still starts resolved even when the schedule
job text was never edited. Reuses C03's block schema and the C01 skill's
resolution sequence; nothing downstream changes because the consumer rule
already exists.

## Acceptance criteria
1. Plugin registers exactly one hook; agent filter is the three explicit
   board-coord ids (whole values, no prefixes); once-per-session guard.
2. Block text comes from a single formatter identical to the C01 schema
   (field set + order; `Board context (collected <ISO>, dev-boards)`
   header); a prompt already carrying that header is never double-injected.
3. Discovery never hardcodes the URL: ctx.mcp.list() first, jsonc parse
   fallback; no credentials anywhere.
4. Failure paths are silent-degrade: any throw → unmodified prompt +
   stderr; nothing in the hook can reject/delay admission indefinitely
   (bounded fetch timeout, e.g. AbortSignal.timeout ~8 s).
5. Seam test file passes `node --test tests/opencode/board-context.test.ts`
   AND `node --test tests/opencode/question-notify.test.ts` still passes
   (no plugin-dir collision).
6. Live-fire proof: the appended block is in the persisted first message
   of a real agent-board-coord session, OR — if the command/schedule
   admission path provably skips prompt hooks — RESULT records the
   evidence and the plugin ships with `enabled` flag default OFF + the
   collector path (C03) stands as the shipped feature; no half-broken
   hook stays on.
7. AGENTS.md plugin sentence updated; regen no-op + `--check`.

## Notes for dev
- Prompt-hook semantics (docs 2026-10-27): runs at admission once, after
  location plugins ready; command prompts submitted through
  session.prompt run it; synthetic/shell messages do NOT; edits become
  canonical persisted input; no exactly-once guarantee — hence the
  once-guard + header idempotence check.
- question-notify reads `event.agent` with a `ctx.session.get` fallback
  (installed CLI v2.0.32 predates checked types) — copy that tolerant
  shape.
- Do not make the plugin call dev-boards through the session's own tools
  — plugins live outside sessions (question-notify header comment).
- If V2 docs' `Plugin.define` shape differs from what the installed CLI
  expects (existing plugins are hand-written V2-style default-export
  functions), match the two shipped plugins' working export shape, not
  the docs example.
- Keep the scope honest (aislop): no narrating comments; the "why"
  comments are the failure-policy + discovery paragraphs.
